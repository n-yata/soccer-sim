# 要求内容

## 概要

試合画面（S-03）で手と運ぶ先（制限するエリア）を選んだとき、「決定」を押す前に、その手で**自分のコマがどう動くか**を作戦ボードに重ねて見せる。プレス・カバー・マークの付け直し・ドリブルなどで動く選手と、その移動先が、決定の前に読めるようにする。

## 背景

2026-10-22、シャビが PC で試合を遊んで、守備の「カバー」がわかりにくいと指摘した。具体的には次の3点。
- カバーとプレスの違いがわからない。
- カバーで選べないマスがあるのはなぜか。
- 「自分のコマを選んで動かす」操作の方が正しいのではないか。

話し合って、次のことを確かめた（モドリッチとシャビ）。
- **選ぶ対象**: 「相手が来ると読んだエリア」を選び、誰が動くかはルールが決める形のままにする。プレスとカバーの区別と、読み合いの軸（相手はどこへ来るか）を保つため。
- **本当の欠点**: 選んだときに、**自分の選手がどう動くのかが画面で見えない**こと。
  - 守備の手でも、いまの画面は「ボールから選んだエリアへの矢印」を出している。実際の動きと合っていない。
  - 実際の動きは、プレスなら隣の1人が選んだエリアへ、カバーなら1人が選んだエリアの背後へ、だ。
- **見せ方**: 決定の前に、すべての自分のコマの移動先が見えればわかりやすい（シャビ）。

前の作業（`.steering/20261022-match-clarity/`。盤面の情報を絞る、ボールのエリアに保持者を置く、CPU の方式の癖）が終わってから、この作業に入る。

## 実装対象の機能

### 1. 手を適用した後の自チームの配置を出す（ドメイン）

- 選んだ手（と運ぶ先・制限するエリア）を、相手が何もしないと仮定して適用する。その後の、**自チームの全選手の位置**と**動き**（移動元・移動先・理由）を返す関数を用意する。
- 計算は判定と同じ関数を使い、画面で別の計算をしない。表示した動きと、判定で実際に起きる動き（相手の手の影響を除く）が食い違わないようにする。手ごとの計算は次のとおり。

  | 手 | 自チームの動き | 使う計算（既存） |
  |---|---|---|
  | プレス・カバー | 寄せる・下がる1人。守備方式がマンツーマンなら、マークの付け直し | `DefenseMover`、`StyleLayoutCalculator.remark` |
  | ドリブル | 運ぶ選手（運ぶ先で固定） | `OpenPlayJudge.apply_attack` |
  | パス・ロングボール・サイドチェンジ・シュート | 選手は動かない（ボールだけ） | — |
  | カウンター（奪取側） | 方式による飛び出し（大外の前進） | `TransitionJudge.counter_layout` |
  | リトリート（喪失側） | 基本配置へ戻り、守備方式で動く | `StyleLayoutCalculator.retreat` |
  | 保持・即時奪回 | 選手は動かない | — |

- 結果はアプリケーション層で、利用者の視点に変換して画面へ渡す。既存の `ViewConverter` と同じ変換を使う。
- 次の点は設計で決める。
  - ヒント（`MoveHints`）と同じ場所に置くか。
  - 新しい値の型にするか。
  - リトリートの「ボール位置」の扱い。

### 2. 決定前のプレビューを盤面に重ねる（UI）

- **出すとき**
  - 運ぶ先を持つ手でエリアを選んだとき（`READY`）。
  - 運ぶ先を持たない手（リトリート・カウンターでない手など）を選んだとき。
- **出すもの**
  - 動く自分のコマの、移動先の位置（薄い ● など、いまの位置と区別できる形）。
  - 移動元から移動先への矢印。
  - 動かないコマは、いまの位置のまま。
- **相手のコマ**: 動かさない。同時手番なので、相手の手は決定まで見えない。
- **ボール**: 運ぶ手（パス・ドリブルなど）なら、いまの「ボールから運ぶ先への矢印」を残す。守備の手では、ボールからの矢印を出さず、プレビューの動きに置き換える。
- **消すとき**: 選び直したとき、決定したとき、次のターンが始まったとき。
- **見た目**: 前の作業で絞った盤面（シンプル案）を、ふたたび情報過多にしない。プレビューの色・線の太さは、開示後の動きの矢印と区別できるものにする。

### 3. 選べない理由（任意。設計で入れるか決める）

- カバーで選べないエリア（自陣の列・近くに味方がいないエリア）を押したときに、理由を一言出すか、選べる条件を操作の列に添える。
- シャビの「カバーで選べないマスがあるのはなぜ？」への対応。入れない場合は、理由を振り返りに残す。

## 受け入れ条件

### 手を適用した後の自チームの配置
- [ ] プレス・カバー・ドリブル・カウンター・リトリートのそれぞれで、返す動きが、判定で同じ手を適用したときの自チームの動きと一致する（相手が何もしない場合）。テストで固定する。
- [ ] マンツーマンの守備でプレス・カバーを選ぶと、マークの付け直しの動きも含まれる。
- [ ] パス・シュート・保持・即時奪回では、動きが0件。
- [ ] 入力の試合の状態を書き換えない。
- [ ] 利用者が守備のときも、利用者の視点（攻撃方向が右）に変換されて画面に届く。

### 決定前のプレビュー
- [ ] 手とエリアを選ぶと、盤面に、自分のコマの移動先と矢印が出る。数は、ドメインが返す動きの数と一致する。
- [ ] 相手のコマは動かない。
- [ ] 守備の手では、ボールから選んだエリアへの矢印を出さない。
- [ ] 選び直す・決定する・次のターンが始まると、プレビューが消える（前のターンのプレビューが残らない）。
- [ ] スクリーンショットで、プレス・カバー（ゾーンとマンツーマン）・ドリブル・リトリートの各場面を確かめる。駒・札・矢印が重なって読めなくならないこと。

### PC での確認
- [ ] シャビが PC で1試合を遊び、プレスとカバーの違いが、プレビューから読み取れる。

## 成功指標

- シャビが、プレスとカバーの違いを、説明なしでプレビューから読み取れる。
- 「選んだのに思っていた選手が動かなかった」という戸惑いが無くなる。

## スコープ外

以下はこのフェーズでは実装しません:

- 手の選び方の変更（「自分のコマを選んで動かす」操作）。読み合いの軸を保つため、選ぶのは「相手が来ると読んだエリア」のまま。
- 相手の動きの予測の表示（同時手番のため出さない）。
- 3D 演出、試合中のメニュー、保存、ヒントの ON/OFF。
- チュートリアル（FR-12）でのプレビューの説明。
