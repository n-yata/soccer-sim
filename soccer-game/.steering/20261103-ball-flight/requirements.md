# 要求内容

## 概要

開示の1拍目（プレー）で、ボールの動き方を**ボールを持つ側の手の種類**で変える。

| 手 | 軌道 | 見え方 |
|---|---|---|
| ショートパス・スルーパス・カウンター | グラウンダー | 地面を転がる。蹴り出しが速く、着くときに緩む |
| ロングボール（裏へ）・サイドチェンジ | 浮き球 | 弧を描いて浮く（影は地面に残る） |
| ドリブル | 運ぶ | 駒と同じ速さで進み、小さく弾む（タッチ） |
| シュート | 強いシュート | 低く速く、はじめに一気に進む |

ルールは変えない。見せ方だけの変更。

## 背景

2026-11-03、視覚的な動きの強化シリーズの2つ目（`.steering/20261103-two-beat-reveal/` の続き）。シャビの「進めて」による。
いまはどの手でも、ボールが同じ速さでまっすぐ動く。手の違いが見た目で分からない。

## 実装対象の機能

### 1. 1拍目のボールの軌道（UI）
- 1拍目のボールの道筋に、軌道の種類を持たせる。種類は、`RevealView` のボールを持つ側の手（攻撃の手、トランジションでは奪った側の手）から決める。ボールを持つ側の手が無い・運ぶ先の無い手（保持など）は、いまどおりまっすぐ等速。
- 2拍目のボールの動き（得点後のキックオフなどで置き直される）は、いまどおりまっすぐ等速。
- 浮き球と、ドリブルの弾みは、ボールの高さで表す。影は地面の位置に描く（いまの「少し浮かせて影を落とす」描き方の、浮かせる量を増やす）。
- 浮き球の高さ・ドリブルの弾みの高さと回数は、調整値として外に出す（設定ファイル）。

### 2. 作戦ボードの行数
- `tactics_board.gd`（551 行、目安 300 行）が、この作業でさらに増えないようにする。拍の道筋を組み立てる処理を `BoardShift` へ移す。

### 3. 変えないこと
- 得点のときの1拍目（ボールは動かない）。シュートが決まる見せ方は「結果の演出」の作業で扱う。
- 駒の動き方（等速）。質感は「動きの質感」の作業で扱う。
- 止める経路・動かさない場面。

## 受け入れ条件
- [ ] 手の種類ごとに軌道の種類が決まる（テストで固定。両チーム・攻守・トランジション）。
- [ ] 浮き球は途中で高さが最大になり、始めと終わりの高さは 0。グラウンダーとシュートは高さ 0。ドリブルは設定した回数だけ弾み、始めと終わりは 0。
- [ ] グラウンダーとシュートは、同じ時刻でまっすぐ等速より先へ進んでいる（蹴り出しが速い）。始めと終わりの位置は道筋の両端。
- [ ] 2拍目のボールは軌道の種類を持たない（まっすぐ等速、高さ 0）。
- [ ] 高さ・回数を設定ファイルで変えられ、範囲外ならデータ層が初期値に戻す。
- [ ] `tactics_board.gd` の行数が増えない。
- [ ] シャビが遊んで、軌道の見え方を判定する。

## スコープ外
- 結果の演出（ゴール・セーブ・インターセプト・オフサイド）。
- 駒の動きの質感（イージング・ずらし）。
- 振り返り（S-07）の盤面。
