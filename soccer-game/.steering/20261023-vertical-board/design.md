# 設計

## 座標の持ち方

作戦ボードの位置は、**平面図**（縦向きのピッチを真上から見た図。上が敵陣）の座標で持つ。画面に描くとき・押した点を読むときに、遠近の写し方を通す。

| 座標 | 中身 | 使う所 |
|---|---|---|
| 平面図 | ボードの大きさの矩形に、縦向きのピッチを置いた座標。エリア = 列（レーン、左が L2）× 行（ゾーン、上が A） | `area_rect`・駒の位置（`piece_center`）・ボールの位置・開示の道筋・プレビュー・テスト |
| 画面 | 遠近を付けた後の座標（奥＝上を狭く・縦を詰める） | 描画・押す操作（`area_at`）・押せる範囲のテスト |

- 写し方は `BoardProjection`（新規、`ui/board2d/board_projection.gd`。RefCounted の静的関数）に置く。
  - 平面図 → 画面: `to_screen(plan, size)`。
  - 画面 → 平面図: `to_plan(screen, size)`。逆の写し方で、往復で一致する。
  - 奥行きによる縮み: `scale_at(screen_y, size)`。
- 写し方の式
  - `t = 平面図の y / 高さ`。
  - 画面の y: `上の余白 + (高さ − 上の余白) × (0.6t + 0.4t²)`（奥ほど縦を詰める）。
  - 画面の x: `中央 + (平面図の x − 中央) × 縮み`。縮みは、画面の y に比例して奥 0.72・手前 1.0。
  - 平面図の縦・横の線は直線のまま写る（斜めの線は曲がるので、点ごとに写す）。
- 遠近の強さ（上の余白の割合・奥の縮み・縦の詰め方）は、見た目の定数として `BoardProjection` に持つ。
  - 判定やバランスに関わらないので、設定ファイルには出さない。

### 押す操作
- `area_at(screen_point)` は、`to_plan` で平面図へ戻してからエリアを引く。ピッチの外なら空文字。
- `plan_area_at(plan_point)` を足す。平面図の点のエリアで、テストと道筋の確かめに使う。
- `screen_center(key)` を足す。エリアの中央の画面の点で、テストで押す位置に使う。

### 押せる範囲（NFR-19。48dp = 96px）
- いちばん奥の行（A）のエリアの、画面での幅（上端）と高さが 96px 以上になるよう、最小の大きさを決める。
  - `MIN_CELL` は、平面図での1エリアの最小。幅 136px（奥で 0.72 倍 → 98px）、高さ 140px（奥の行は縦が約 0.73 倍 → 約 98px）。
  - ボードの最小の大きさは `MIN_CELL × (5 列, 3 行)`。
- テスト: 基準の大きさと最小の大きさの両方で、奥の行の画面上の幅と高さが 96px 以上。

## 駒の並べ方（平面図）
- 1チームは、エリアの自分の側（自分は左半分・相手は右半分）に 2列×2段。
  - 添字 0・1 が奥の段、2・3 が手前の段。
  - 段の位置は、エリアの高さの 50% と 72%（上側はボール、下端はヒントの札）。
- 横の間隔は `(セルの幅 / 2 − 余白) / 列の数 2` で、上限を付ける。駒の半径は `min(直径の半分, 間隔の半分 − 1)`（同じ段の隣の駒と重ならない）。列の数（`PIECE_COLUMNS`）と段の数は別に持つ。
- 5人以上は、駒3つと「+N」の札（添字 3 の位置）。いまと同じ決まり。
- ボールは、エリアの上側の中央（高さの 26%）。

## 描画（`BoardPainter`）
- 順番
  1. 地面（ピッチ・芝目・ハーフスペースの帯）。
  2. 塗り（ボールのエリア・選んだエリア）と、選べるエリアの点線の枠。
  3. 白線。
  4. エリアの点線。
  5. レーン名。
  6. 動きの矢印・意図の矢印。
  7. プレビューの点線。
  8. **立っているもの**（駒・プレビューの半透明の駒・ボール・「+N」）を奥から手前の順に。
  9. ヒントの札・比較の札。
- エリアは、平面図の矩形の四隅を写した四角形で描く。矢印は、エリアの中央を写した点で描く。
- 駒は、モックと同じチェスの形にする。
  - 部品は、影・台座・胴・首の輪・頭。
  - 自分は丸い頭、相手はとがった頭。
  - 大きさは `scale_at` に比例する。
- 立っているものの並びは `standing_order()`（ボードの問い合わせ）で決める。描画とテストで共有する。
  - 中身は {"kind", "plan": Vector2, ...} で、画面の y の小さい順（奥から）。

## 画面の配分
- 盤面と操作の列の幅（`SIDE_WIDTH` 480）は変えない。
  - 基準の 1280×720 で、ボードは約 728×576。縦向きのピッチでも、押せる範囲・駒の大きさは足りる（テストで確かめる）。
  - 操作の列の文字の折り返しも、いまと変わらない。
- スクリーンショットで確かめ、問題があれば見直す。

## ミニピッチ（`MiniPitch`）
- 向きは、列 = レーン（左が L2）、行 = ゾーン（上が A）。`cell_rect(area, cell_size)` を変える。
- 1マスは、横 44px・縦 60px（全体 220×180。いまの 216×180 とほぼ同じ大きさ）。人数の数字（24px）が入る。
