## 学んだこと

**技術的な学び**
- **見た目の座標と論理の座標を分けた**
  - 位置を平面図で持ち、描くときと押した点を読むときだけ写すようにした。
  - そのため、開示の動き・プレビュー・駒の位置の計算は、そのまま使えた。
  - テストも平面図で値を確かめられ、写し方の正しさは往復のテストで別に固定できた。
- **逆の写し方には、範囲外の分岐がある**
  - 押した後に盤面の外で離すと、その点も届く。ずっと外の点（判別式が負）まで、空に倒れることをテストで固定した。
- **立体の駒は、エリアの上へはみ出して見える**
  - 押せる範囲はエリアのままなので、駒の頭を押すと奥のエリアになる。仕様どおりだが、遊んで気になるかは要確認。

**プロセス上の改善点**
- **良かった点**
  - モック（横向き → 縦向き）を2回見せてから、要求書にまとめた。作ってから向きを変えるより、ずっと安く済んだ。
  - 書き換えのスクリプトを、すべて Write ツールで書いた。バックスラッシュの化けは起きなかった。
  - 変異の確認は、9個を19秒、追加の2個を5秒（3分以内）。
- **悪かった点**
  - 仕様書の取り残しを探すとき、*.md だけを検索して、.drawio の中の文を見落とした（実装レビューで発見）。
  - 一度、Bash に Python の1行スクリプトを直接渡した（バックスラッシュを含む）。化けは無かったが、メモリの規則に反した。以降は Write ツールに戻した。
