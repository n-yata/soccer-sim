# 要求内容

## 概要

試合画面の作戦ボードを、**縦向き・斜めから見た遠近付きのピッチ**と、**チェスのような立体の駒**にする。

- 自チームは上へ攻め、相手チームは下へ攻める。ペナルティエリアとゴールは上下に来る。
- あわせて、**3D 演出（FR-24）をやめる**。ターンの結果は、盤面の上で駒とボールが動くこと（前の3つの作業で作った動き）で見せる。

## 背景

2026-10-23、シャビと次のことを話した。
- 3D 演出は、落としてもよいと考えていた（シャビ）。開示で駒とボールが動くようになったので、盤面を半3Dにして動きを見せるだけで、ゲームとして十分に面白い。
- 半3Dの見せ方として、案 A（ピッチを斜めから見る）のモックを見た（モドリッチ）。
  - 駒は、チェスのように立体的にする。
  - そのうえで、縦横を入れ替える。「上下にペナルティエリアがきて、自チームは上に向かって攻め、相手チームは下に向かって攻めがいい」（シャビ）。
- 縦向きのモックを見て、この方向で進めることにした（シャビ）。
  - モックでは、1チームの駒をエリアの中で 2列×2段 に並べた。横1列だと、縦が余って駒が小さくなったため。
- 縦にすると「前に進む」と「上へ動く」が一致し、開示の動きが読みやすい。
- 3D 演出を作る量（3D の舞台・カメラ・演出の状態・性能の要件）を、読み合いの面白さに直接効く盤面に回せる。

## 実装対象の機能

### 1. 縦向き・遠近付きの作戦ボード
- **向き**
  - 上が敵陣（A）で相手のゴール、下が自陣（D）で自分のゴール。
  - 列は左から左大外（L2）・左HS（L1）・中央（C）・右HS（R1）・右大外（R2）。利用者の攻撃方向から見た左右と一致する。
  - 利用者が守備のときも、この向きは変えない（いまの「利用者の攻撃方向が常に右」を「常に上」に置き換える）。
- **遠近**
  - 奥（上）を狭く・縦を詰め、手前（下）を広く描く台形の見え方にする。
  - 直線（エリアの境界・白線）は直線のまま写す。
- **白線**: 外枠・ハーフウェイライン・センターサークル・ペナルティエリア（上下）・ゴール（上下）。
- **レーン名**: 自陣（手前の行）の各エリアに出す。
- **画面の向き**: 横向きのまま（NFR-25 は変えない）。ピッチだけを縦に置く。

### 2. チェスのような立体の駒
- 駒は、影・台座・胴・頭で立てて描く。
  - 自分はポーンのような丸い頭。
  - 相手はビショップのようなとがった頭。
  - 色だけでなく形で区別する（NFR-20 のグレースケールでも判別できる）。
- 奥の駒ほど小さく描く。手前の駒が奥の駒に重なるよう、奥から順に描く。
- **1エリアの並べ方**
  - 自分を左、相手を右に置き、それぞれ 2列×2段 で並べる。
  - 1チーム5人以上は、駒を3つと「+N」の札にする（いまと同じ決まり）。
- **ボール**: 少し浮かせて、地面に影を落とす。
- **プレビュー**: 移動先に半透明の駒を立て、地面に沿った点線の矢印を引く。
- **開示**: 駒とボールが、判定前の位置から次のターン開始時の位置へ動く（いまの動きのまま）。

### 3. 押す操作
- エリアを押して選ぶ操作は、遠近付きの見た目のエリア（台形）で判定する。押した点は、見た目のエリアに入る。
- 押せる範囲は 48dp 以上（NFR-19）。いちばん奥の行でも満たす。

### 4. 画面の配分
- 縦のピッチに合わせて、盤面と操作の列の幅の配分を見直す。
- 手のボタン・判定理由・決定ボタンが読めて押せること。基準の 16:9 と、最小の大きさの両方で確かめる。

### 5. ミニピッチの向きを揃える（2026-10-23 にシャビの指示でスコープに追加）
- 陣形カードなどのミニピッチ（`MiniPitch`）も、作戦ボードと同じ向きにする。
  - 上が敵陣、下が自陣。
  - 列は左から L2〜R2。
- 小さい表示なので、遠近と立体の駒は付けない（真上から見た平面のまま）。

### 6. 3D 演出（FR-24）をやめる
- 要件定義書の FR-24 を、「ターン結果は作戦ボードの上の動きで見せる」に置き換える。廃止の理由と、置き換えた内容を残す。
- 3D 演出だけに関わる記述を、外すか置き換える。
  - NFR-02（3D 演出の滑らかさ）。
  - S-03 の状態 `REPLAYING`・「スキップ」・`ReplayLayer`。
  - `ReplayStage`・`replay_max_sec`。
  - 3D 演出の上限（設定値の表）。
  - 用語集・アーキテクチャ・ユースケース・データ定義の該当箇所。
- 開示の動きは、いまの2D の動き（`start_shift`）をそのまま使う。

## 受け入れ条件

### 盤面
- [ ] 上が敵陣、下が自陣、左から L2〜R2 で描かれる。利用者が守備のときも同じ向き（テストで固定する。視点の変換が UI に漏れていない）。
- [ ] 各エリアの駒の数が `BoardSnapshot` の人数と一致する（FR-16）。
- [ ] 押した点のエリアが、見た目のエリアと一致する。遠近の写し方とその逆の写し方が往復で一致することと、各エリアの中央を押すとそのエリアが選ばれることを、テストで固定する。
- [ ] いちばん奥の行でも、押せる範囲が 48dp 以上（NFR-19）。基準の大きさと最小の大きさの両方で、テストで固定する。
- [ ] 駒は奥から手前の順に描かれる（描く順をテストで固定する）。
- [ ] プレビュー・開示の動き（駒とボール）・ヒントの札・比較の札が、縦向きでもいまと同じ値で出る（既存のテストの意味を保って書き直す）。

### 見た目
- [ ] スクリーンショットで、次の各場面を確かめる。
  - ターンの始め。
  - 攻撃の手を選んだとき。
  - 守備のプレビュー。
  - 開示の途中と終わり。
  - 5人以上のエリア。
  - 最小の大きさ。
- [ ] 駒・札・矢印・レーン名が重なって読めなくならないこと。
- [ ] グレースケールで、自分と相手の駒を形で区別できる（NFR-20）。

### 3D 演出をやめる
- [ ] 仕様書から、3D 演出を前提にした記述が無くなる。FR-24 は廃止の理由とともに置き換える。
- [ ] 試合画面の状態の表と状態遷移図が、いまの実装（`REPLAYING` が無い）と一致する。

### ミニピッチ
- [ ] ミニピッチが、作戦ボードと同じ向き（上が敵陣、左が L2）で描かれる（テストで固定する）。

### PC での確認
- [ ] シャビが PC で1試合を遊び、縦向きの盤面で、読み合いと開示の動きが読み取れる。

## 成功指標

- シャビが、3D 演出が無くても、盤面の動きだけで試合を楽しめると感じる。
- 「前に進む」が「上へ動く」として、説明なしで読める。

## スコープ外

以下はこのフェーズでは実装しません:

- 3D の舞台（Node3D・カメラ・3D モデル）。
- 駒の背番号・選手ごとの見た目の違い。
- ドメイン・判定のルールの変更。
- アニメーションの演出の追加（ボールの弧など）。
- 画面の向き（横向き）の変更。

## 未決事項

- **座標の持ち方**: 縦向きの平面の座標を正にするか、いまの論理座標（横向き）を残して描くときに回すか。押す操作・テスト・描画で同じ写し方を使うことが条件。
- **遠近の強さ**: 奥の縮め方（モックは奥で 0.72 倍）と縦の詰め方を、設定値にするか定数にするか。
- **画面の配分**: 盤面と操作の列の幅（モックは今の配分のまま）。
- **駒の大きさ**: 2列×2段のときの大きさと、最小の大きさでの収まり。
- **FR-24 の扱い**: 廃止にして新しい FR を立てるか、FR-24 の中身を置き換えるか。
