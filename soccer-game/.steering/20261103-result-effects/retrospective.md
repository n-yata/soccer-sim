## 計画と実績の差分

**計画と異なった点**:
- **テロップを待つ印**: 設計では `_telop_pending` を持つ形だった。変異で確かめたところ、`start_turn` が後でテロップを隠すため印は効いておらず、「開示中（`_reveal` がある）なら出す」に簡単にした。
- **演出の時間の初期値**: ボードの初期値を設定と同じ 0.8 にしていたので、bind で値を入れ忘れても気づけなかった（変異で残った）。ボードの初期値を 0（演出なし）にし、パネルのテストで「bind の後は演出が出る」を確かめた。
- **パネルのテスト**: 実装を先に書いてしまった。Red の確認は変異で代えた。
- **オフサイドの旗**: 最初は小さすぎてボールと駒に紛れた。スクリーンショットで気づき、エリアに合わせた大きさにして下寄りに立てた。
- **全体テスト**: 180 秒で打ち切り（3分を超えて失敗扱い）。並行セッションのバランス計測の除外が入った後でも収まっていない。

## 学んだこと

**技術的な学び**
- **「1拍目の終わり」を知らせるには、拍に元の keyframe の番号を持たせる**: 動きの無い拍を取り除くと、並びの先頭が1拍目とは限らない。
- **知らせは必ず1回**: 通常の着地・1拍目が無いとき・途中で止めたとき、の3つの経路で1回だけ出す。止めたときは演出を出さず知らせだけを出す（テロップの出し忘れを防ぐ）。
- **画面の部品の初期値を設定と同じ値にしない**: 値を入れ忘れても同じ見た目になり、テストで捕まらない。「入れなければ何も出さない」値にしておく。
- **GDScript の三項演算子と `as`**: `a if x as bool else b` は構文エラーになる。`(x as bool)` と括弧で囲む。

**プロセス上の改善点**
- 変異で残ったものを見ると、「効いていない守りのコード」が見つかる。消して簡単にするか、効くことをテストで確かめる。
