# 要求: テストを「単体は局所に細かく・結合は最低限のシナリオ」に組み直す

## 概要
全体テスト（`tools/run-tests.sh`）が3分の上限に近い（約166秒）。原因は、局所の性質を確かめるテストが、狙った段階（得点後・ハーフタイム・試合終了など）まで試合を毎回1回回していること。テストの仕方を見直し、単体テストは状態を直接用意して局所を細かく確かめ、試合を通す結合テストは最低限のシナリオに絞る（シャビの指示。2026-11-05）。

## 実装対象
- テスト用の補助に、段階ごとの試合の状態を1回だけ作って使い回す仕組みを置く。状態の写しを一時ディレクトリの中断データに保存し、本番と同じ再開の経路（`inspect_suspended`・`resume`）で `MatchController` を作る（本番のコードにテスト専用の窓口を足さない）
- 試合を段階まで回していた単体テスト（確定・中断・メニュー・振り返り・S-03〜S-06 の画面）を、その仕組みから始める形に移す。確かめる中身は変えない（再開の経路で成り立たない前提は、テストごとに書き直す）
- 結合テストを次の最低限に絞る: CPU と最後まで戦う1試合（得点・方式の選び直し・ハーフタイム・結果を通る）、画面を通して1試合（`match_flow_test`）、中断→再開→最後まで→戦績に記録、1ターン1マスの不変条件

## 受け入れ条件
- `tools/run-tests.sh` が成功し、所要時間が約166秒から明らかに縮む（目安 120 秒以下）
- 移したテストが、移す前と同じ性質を確かめている（件数が減る場合は統合の理由を記録する）
- 本番のコードに、テストのためだけの関数・分岐を足していない

## スコープ外
- 本番のコードの高速化（CPU の手の選択・判定の計算）
- `board2d/` のテスト（別セッションが分割中）
