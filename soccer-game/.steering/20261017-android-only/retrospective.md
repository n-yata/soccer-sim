# 振り返り: MVP の配布先を Android に絞る

## 何をしたか
- 要件定義書・非機能要件・アーキテクチャ概要・リポジトリ構造・用語集・機能概要から、Windows（Steam）の要件を外し、後続マイルストーン（要件定義書 §6.2）へ移した
- 戻すときに要る要件の一覧を §6.2 の下に残した
- 画面設計とワイヤーフレームから、横長の画面の配置を外した

## コミット前レビュー（review-pre-commit）の結果
- 第1回: Critical 0 / High 0 / Medium 1 / Low 5 / 改善提案 1。すべて対応した（再レビューなし）
- 全文: [review-report.md](./review-report.md)

## 学び
- 配布先を減らす変更は、要件を「消す」だけだと、戻すときに安全策（外部通信なしの検査・認証情報の管理）が抜け落ちる。外したものの一覧を正本に残しておく
- デザイン案を先に見せたことで、「PC だと違和感が出る」という判断が早い段階で出た。縦長のピッチを主役にする方針と、対象の端末を一緒に決められた
