# 要求内容

## 概要

スマホの縦画面でも遊べるようにする（3回に分ける作業の1回目）。今回は、縦・横の切り替えの土台と、試合をするのに要る3画面
（S-01 タイトル・S-02 試合準備・S-03 試合）の縦の配置を作る。

## 背景

シャビの要望「スマホの縦画面に対応して」（2026-11-27）。いまは横向きだけで設計していて（NFR-25「縦向きには回転しない」。
2026-10-18 決定）、縦で開くと横長の画面がそのまま縮み、上下が大きく空いて文字も小さい。

シャビの決定（2026-11-27）:
- 縦用のレイアウトを作る（横長の配置を縮めるのではなく、縦では上下に積む配置にする）
- ブラウザ版とアプリ版（Android）の両方で、端末の向きに合わせて縦・横を切り替える
- 3回の PR に分ける: ① 土台＋タイトル・試合準備・試合 → ② 方式の選び直し・ハーフタイム・結果・振り返り →
  ③ チュートリアル・理解度チェック・表現範囲・戦績・設定
- 試合画面は「盤面が上、操作が下」。ほかの画面も「横で左右に分けていたものを上下に積む」を基本にする

## 実装対象

### 1. 縦・横の切り替えの土台
- ウィンドウが縦長（高さ ＞ 幅）なら縦。基準の解像度を 720×1280（幅に合わせて拡大縮小。余った高さは画面に渡す）、
  横なら今までどおり 1280×720（高さに合わせる）
- 向きが変わったら、表示中の画面と、その後に開く画面へ伝える（各画面が配置を組み替える）
- 切り欠き（セーフエリア）の余白は、縦では上下、横では左右に当てる
- アプリ版の向きの固定（横・センサー）を外し、ブラウザ版（PWA）の manifest の横固定も外す

### 2. 縦の配置（今回の3画面）
- S-01 タイトル: プロダクト名の区画を上、カードを下
- S-02 試合準備: 陣形のカードを上、守備・攻撃方式と「この布陣で試合開始」を下
- S-03 試合: 上部バーを2段（1段目: メニュー・スコア、2段目: 保持・局面のタグ／両者の選択の帯）、作戦ボードを横幅いっぱいに、
  その下に陣形・方式、手のボタン・判定のテロップ、いちばん下に「詳細」と「LOCK IN／NEXT」

## 受け入れ条件

- [ ] 縦（720×1280）で、3画面のどの要素も画面からはみ出さず、横に並べていたものが上下に並ぶ
- [ ] 横（1280×720）の配置は今までと変わらない（既存のテストが通る）
- [ ] 試合中に向きを変えても、試合の状態（選んだ手・開示中の盤面）を失わずに配置だけが組み替わる
- [ ] ブラウザ版を縦の大きさで開き、タイトル → 試合準備 → 試合を数ターン進められる
- [ ] 要件（NFR-25・要件定義書の対象プラットフォーム）と画面設計・ワイヤーフレーム（3画面の縦）を更新する

## スコープ外（2回目・3回目の PR）

- S-04〜S-12 の縦の配置（今回は横の配置のまま縦の画面に表示される）
