## 計画と実績の差分

**計画と異なった点**:
- 画面を描いたら、攻撃の手が6つになって運ぶ先の説明が手のボタンの下にはみ出し、隠れていた。説明が見える所までスクロールするようにした。遅らせて呼ぶ（`call_deferred`）だけでは試合画面の入れ子の並べ直しより先に走ってスクロールせず、2フレーム待つ形にした。
- シュートを絞ったので、得点の場面を使う既存のテスト（match_rules・cpu_planner・move_hints・画面のテスト）の場面をペナルティエリアへ移した。画面のテストは得点までのターン数が延び、上限をシードを探す側と同じにした。

**新たに必要になったタスク**:
- スルーパスの札を控えめな色にしない（実装レビューで発見）。
- 試合進行（`resolve_turn`）と決定前のプレビューを通したスルーパスのテスト（実装レビューで指摘）。
- 測定用の補助（`match_balance_probe`）にスルーパスの割合とロスト率を足した。

**積み残し**:
- 判定の内訳（`JudgeReasonFormatter.detail`）は、スルーパスでもカバーの有無を出す。結果には効かない表示（シャビが遊んで気になれば直す）。
- ワイヤーフレーム（.drawio）の手のボタンの図は5つのまま。
- `match_board_panel.gd`（422行）・`tactics_board.gd`（465行）が目安の300行を超えている（前から）。`board_painter.gd` もちょうど300行。

## 学んだこと

**技術的な学び**
- **パネル単体のテストでは、画面の入れ子での並べ直しの順を再現できない。** `call_deferred` のスクロールはパネルのテストでは通り、実際の画面では効かなかった。画面の見た目に関わるものは、画面の実寸のテスト（match_screens_test）で確かめ、変異で「古い実装なら落ちる」ことを確かめた。
- **「人数を比べない手」を増やすと、人数差を前提にした見た目の分岐（±0 の札の色）から、隠れた値が漏れる。** 比べるかどうか（`is_compared`）で分岐を揃える。
- **手の enum の途中に値を足すと、番号に依存するテスト（エラー文の action 番号・手の数）がずれる。** 保存は enum の名前で持つので本番には影響しないが、テストの期待値は直す。

**プロセス上の改善点**
- 作業の切り替わりの直後に、Bash 経由の Python と sed の置き換え文字列にバックスラッシュを書いてしまった（12・13回目）。sed の置き換えでテストの期待値の `\n` が本物の改行になった。メモを更新した。期待値に `\n` を含む行は Edit ツールで足す。
- 画面を描いて確かめたことで、テストでは見つからない「説明が隠れる」問題を見つけられた。
