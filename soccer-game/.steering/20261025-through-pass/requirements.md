# 要求内容

## 概要

シュートを打てるエリアをペナルティエリアの3マスに絞り、攻撃の手に「スルーパス」を足す。

## 背景

- 6列の盤面（2026-10-25）では、シュートが5・6列目の中央・ハーフスペース（6マス）から打てた。シャビの判断で、ペナルティエリアの3マスに限る。
- 攻撃の手は、味方のいるエリアへのパス・ドリブル・ロングボール・サイドチェンジだけで、空いたスペースへ味方を走り込ませる手が無かった。読み合いの選択肢として、ハイリスク・ハイリターンの手を足す。
- 決めたこと（2026-10-25。シャビの回答）:
  - ペナルティエリアは6列目（`A2`）の `L1`・`C`・`R1` の3マス。盤面の白線もこの3マスに合わせて描き直す。
  - スルーパスは「前の空いたエリア」へも出せる手。
  - 判定は「読まれたら必ず奪われる」（人数に関係なく、ぴったり読まれたらロスト、読まれなければ前進）。

## 実装対象の機能

### 1. シュートをペナルティエリアに限る
- ボールが `A2-L1`・`A2-C`・`A2-R1` にあるときだけシュートを選べる（5列目と、6列目の大外からは打てない）。
- 作戦ボードのペナルティエリアの白線を、この3マス（幅は L1〜R1、奥行きは6列目の1列分）に合わせて描く。

### 2. スルーパス（`THROUGH_PASS`。攻撃の手の6つ目）
- 運ぶ先: ボールより1〜2列前で、レーン差1以内のエリア。味方がいなくてもよい。
- 受け手（走り込む選手）: 運ぶ先から1マス以内（運ぶ先そのものを含む）にいる、ボールのエリア以外の味方のうち、いちばん近い選手（同じ近さなら配置の選手の順）。受け手がいなければ、そのエリアは選べない。
- 受け手は運ぶ先へ動いて固定される（ドリブルで運ぶ選手と同じ扱い。1ターン1マスの範囲）。守備がマンツーマンなら、マークを付け直す。
- 判定:
  - 守備の手がそのエリアをぴったり読んでいたら（制限するエリア = 運ぶ先）、人数に関係なく `LOSS`。守備側が運ぶ先でボールを奪う。
  - それ以外（隣の読み・外れ）は、人数に関係なく `ADVANCE`。ボールは運ぶ先へ進む。
  - カバー判定はしない。

### 3. 画面・文言
- 手のボタンに「スルーパス」を足す（攻撃の手は6つ。ボタンは2列×3段）。
- 運ぶ先の補足文: 「スルーパス: 1〜2列前の、味方が走り込めるエリアへ出す。読まれていれば人数に関係なく奪われる」の趣旨。
- 判定理由: 「読まれてロスト」「読まれず前進」の形（人数の句を原因にしない）。
- ヒント（FR-19）: スルーパスの札は人数差ではなく、読まれなければ通ることを示す（見せ方は設計で決める）。

### 4. CPU
- スルーパスは評価値（人数差）を持たない手として扱う（保持・リトリートと同じ 0）。前へ運ぶ加点は他の手と同じく付ける。
- カウンター型の方式の癖の加点の対象にする（直線的に背後を狙う手のため）。

### 5. 仕様書
- `functional-overview.md`（アルゴリズム3・5・8、判定例に JE-09 として1つ追加、表示仕様）、`glossary.md`、`requirements-definition.md`、`component-design.md`、`screen-design.md`・`screen-03-match.md` を更新する。

## 受け入れ条件

### シュート
- [ ] テストを先に書き、落ちることを確かめてから実装する
- [ ] `A2-L1`・`A2-C`・`A2-R1` で選べ、`A2-L2`・`A2-R2`・`A1-C` などでは選べない（境界のテスト）
- [ ] 盤面のペナルティエリアの白線が3マスに一致する（画面を描いて確かめる）

### スルーパス
- [ ] 運ぶ先: 1列前・2列前で選べ、3列前・同じ列・後ろ・レーン差2では選べない
- [ ] 受け手がいない（1マス以内に味方がいない、またはボールのエリアにしかいない）エリアは選べない
- [ ] 判定: ぴったり読まれたら、攻撃側が多くても `LOSS`。隣の読み・外れなら、守備側が多くても `ADVANCE`
- [ ] 受け手が運ぶ先に動いて固定される。いちばん近い選手（同じなら配置の順）が選ばれる
- [ ] 1ターン1マスの性質のテスト・対称性・通しの試合が通る

### 画面・全体
- [ ] 攻撃の手のボタンが6つ並び、1280×720 で操作の列に収まる（画面を描いて確かめる）
- [ ] `tools/run-tests.sh` で失敗0・終了コード0
- [ ] 点数などの数字は、壊れていないかの目安だけ確かめる（調整はしない。スルーパスの選択率も報告する）

## 成功指標

- シャビが遊んで、スルーパスが「読まれるか」の駆け引きとして機能していると感じられる。
