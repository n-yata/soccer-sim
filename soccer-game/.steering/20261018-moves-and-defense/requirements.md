# 要求内容

## 概要

ドメイン層に、次の2つを作る（`functional-overview.md`・`component-design.md` §2.2〜2.4）。
- **アルゴリズム3「選択可能な手」**: 局面とボール位置・現在配置から、選べる手と運ぶ先を決める。
- **アルゴリズム4「守備の手による移動」**: プレス・カバーで動く選手を一意に決め、固定する。

あわせて、次の値オブジェクトを作る。
- `TurnChoice`: 手の選択
- `MoveOptions`: 選べる手と運ぶ先の一覧

## 背景

- アルゴリズム2（`../20261018-style-layout/`）で、ターン開始時の配置が出せるようになった。
- 攻守ターンの判定（アルゴリズム5）は、この配置に守備の手（アルゴリズム4）を適用してから人数を比べる。試合画面の手のボタン（`ChoicePanel`）と運ぶ先の枠は、アルゴリズム3で決まる。
- シャビの指示（2026-10-18「アルゴリズム3と4に進んで」）。

## 実装対象の機能

### 1. 値オブジェクト（`game/domain/`）
- `TurnChoice`（`turn_choice.gd`）: `family: ChoiceFamily`・`action: int`・`target: PitchArea`。運ぶ先を持たない手（シュート・即時奪回・リトリート・保持）では `null`。
- `MoveOptions`（`move_options.gd`）: 手（`family` と `action`）ごとの、選べる運ぶ先の一覧。
  - 運ぶ先を持たない手は、選べるかどうかだけを持つ。
  - 一覧が空の手は選択不可。
  - 静的関数 `needs_target(family, action)` で、運ぶ先を伴う手かどうかを返す。

### 2. `MoveRules`（`game/domain/judge/move_rules.gd`。アルゴリズム3）
- `attack_options(pair, ball)`: 攻撃の手。`ball` と運ぶ先は攻撃側から見た座標。味方の人数は、攻撃側の現在配置で数える。
- `defense_options(pair)`: 守備の手。運ぶ先（制限するエリア `T_d`）は攻撃側から見た座標で返す（`DefenseMover.apply` の `target` と同じ）。
- `neg_transition_options()`: 失った側は `COUNTER_PRESS`／`RETREAT` を常に選べる。
- `pos_transition_options(winner, ball)`: 奪った側は `SECURE` を常に選べる。
  - `COUNTER` の運ぶ先は、ボール位置から奪った側の攻撃方向へ1〜2ゾーン前のエリア（レーン不問）で、`winner` の配置に味方が1人以上いるところ。
  - `winner` には、アルゴリズム6のカウンターの配置を呼び出し側が渡す。
- `is_allowed(options, choice)`: 選択不可の手・選べない運ぶ先・運ぶ先の要否の食い違いを拒否する。
- `MatchState` から呼ぶ入口 `options_for(state, side, catalog)` は、`MatchState` を作る作業（試合進行）で足す。

### 3. `DefenseMover`（`game/domain/layout/defense_mover.gd`。アルゴリズム4）
- `apply(pair, action, target)`: 守備の手を適用し、動いた選手を固定した `LayoutStep` を返す。`target` は攻撃側から見た座標。
  - `PRESS`: 仕様どおり。`T_d` の上下左右の隣接エリアのうち、守備側が1人以上いて余り（守備側人数 − 攻撃側人数）が最大のエリアから1人を `T_d` へ動かす。同じ余りなら、守備側から見て前方 → 横（中央寄りのレーンが先。同じなら左） → 背後の順。
  - `COVER`: `T_d` に守備側がいればその1人を、いなければ `PRESS` と同じ規則で選んだ隣接エリアの1人を、`T_d` の背後へ動かす。
  - 固定されていない選手を優先する。同じエリアに複数いれば、配置の選手の順で先の選手。固定された選手しかいなければ、その選手を動かす（固定先を更新）。
  - 選べない手（動かせる選手がいない、`COVER` の背後が無い）なら `null` を返す。
  - マンツーマンのマークの付け直しは、呼び出し側（アルゴリズム5）が `StyleLayoutCalculator.remark` で行う。

## 受け入れ条件

- テストは先に失敗する状態から書く（Red→Green）。`bash tools/run-tests.sh` が成功する（件数が増え、失敗0）。
- アルゴリズム3
  - `SHORT_PASS`: 斜めを含む隣接8エリアで味方がいるところだけ。盤の端・角でも盤外を含めない。
  - `DRIBBLE`: 前・左・右だけ（後ろ・斜めは含めない）。味方の有無は問わない。
  - `LONG_BEHIND`: ボールが `D` のときだけ。`A` で同じか隣のレーン、味方がいるところ。
  - `SWITCH`: 同じゾーンで、レーンが3つ以上離れ、味方がいるところ。
  - `SHOT`: ボールが `A` の `C`・`L1`・`R1` のときだけ選べる。大外・`M`・`D` では選べない。
  - `PRESS`・`COVER`: 条件どおり（`COVER` は守備側の `D` ゾーンを除く）。
  - トランジション: 失った側の2つは常に選べる。`COUNTER` は1〜2ゾーン前（盤外を含めない）で、味方がいるところ。
  - `is_allowed`: 正しい選択は通し、選択不可の手・一覧に無い運ぶ先・運ぶ先の要否の食い違いは拒否する。
- アルゴリズム4（仕様のエッジケースすべて）
  - 余りが負のエリアしかなくても、守備側の選手がいれば動かす。
  - 同率の優先順（前方 → 横 → 背後、左右同率は守備側の左）。
  - マンツーマンでプレスに出たマーカーは固定され、`remark` で残りのマーカーがマークを付け直す。
  - 固定されていない選手を優先し、固定された選手しかいなければその選手の固定先を更新する。
  - `COVER` は `T_d` の背後へ動かす。`T_d` に守備側がいなければ、隣接エリアから選ぶ。
  - 動きは理由（`PRESS`・`COVER`）・守備側のチーム・移動元・移動先つきで返し、入力を書き換えない。
  - 選べない手では `null` を返す。
- 禁止依存の検査で 0 件、型の警告 0 件。

## 未決事項（設計で既定を決めた）

- `COVER` の「隣接エリア」は、`PRESS` と同じ上下左右とする（アルゴリズム4の `COVER` が「`PRESS` と同じ規則で選んだ隣接エリア」と書いているため）。
- 守備の手の `T_d` は、ボールの位置によらず15エリアのすべてが候補（仕様は条件だけを決めている）。
- 同じエリアに動かせる選手が複数いるときは、配置の選手の順で先の選手を動かす。
