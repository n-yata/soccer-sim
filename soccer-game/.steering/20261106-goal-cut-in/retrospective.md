# 振り返り（20261106-goal-cut-in）

## やったこと
- 得点のシュートが着地したら、盤面の上に3Dのカットインを重ねる。夜のスタジアムで選手が助走してゴールを決め、得点された側の
  キーパーが跳ぶが届かず、ネットが揺れ、「GOAL!」・「得点／失点」・スコアを出し、選手が喜ぶ。押すと飛ばせる。
  終わるまでキックオフへの組み直し（2拍目）を待たせる。時間は設定値（既定 3.6 秒、0 なら出さない）。
- 選手は Quaternius の CC0 の体にユニフォームをシェーダーで着せ、蹴る動きは CMU のモーションキャプチャ（本物の人の蹴り）を
  骨の向きで移した。

## うまくいかなかったこと（作り直しが多かった）
- 見た目を4回作り直した: 2D の絵 → 手作りの3D（のっぺりしたマネキン）→ 顔・髪を足した手作りの3D → 外部の素材。
  シャビの言葉は「2Dすぎて全然よくない」「のっぺりしたマネキン」「ゼロから作ってるせいか、全然よくない」。
  人の体と動きを手で作るのは、手を入れても素材の質に届かなかった。**人や動物の3Dは、最初から外部の素材（CC0 など）を探す**。
  駒の作り直しの学び（`visual-direction-confirm-first`）と同じく、方向（2D か本当の3Dか、手作りか素材か）を最初に確かめるべきだった。
- 手で作った蹴る姿勢は、直しても「硬い」が残った。要所の姿勢を正しくしても、間の動き（加速・体重の移り・腕の釣り合い）が
  不自然になる。本物の動きの記録を骨の向きで移したら、一度で自然になった。
- シャツの襟が首の付け根より下で切れていて、肩が出て見えた（シャビ「セクシーになってる」）。塗り分けを高さの数字だけで
  決めて、肩の上を寄りの画で確かめていなかった。服を着せたら、首元・肩・背中を寄りで撮って確かめる。

## うまくいったこと
- カットインの時刻 p だけで舞台・選手・カメラが決まる純粋な関数（`GoalCutInArt`）にしたので、テストでもスクリーンショットでも
  任意の瞬間を止めて確かめられた（インパクトの瞬間に足の甲がボールの後ろに来ることを、数字で合わせられた）。
- 動きの記録を「体の空間の手足の向き」で持ち、骨を向ける形にしたので、記録の人と素材の体の寸法の違いを気にせずに移せた。
- 書き出しで実際に APK を作って中身を見たことで、`kick_motion.json` が書き出しに含まれない（JSON はリソースではない扱い）ことを
  見つけ、`include_filter` に足した。端末で蹴る動きが読めずに落ちるところだった。

## 次に気をつけること
- Bash 経由の Python の置き換え文字列に `\` を書かない（テストの行継続を含む置き換えで、またアサーションが外れた。Edit で直した）。
- 素材を足したら、書き出しの `include_filter` に入るか（リソースとして取り込まれる形式か）を確かめる。
- 使わなくなった値（テーマの `skin`・`mouth`）は、仕様書に書く前に使われているかを確かめて消す。

## コミット前レビュー（review-pre-commit）の結果
- 第1回で収束。Critical / High なし、Medium 4件・Low 6件。Medium は4件とも対応した（キーパーのテストを描く体の骨で測る形にした・CMU の利用条件を本家で確かめて記録した・体の形のキャッシュ・出していない間のビューポートを最小に）。詳細は [review-report.md](review-report.md)。
- キーパーのテストを実物で測る形にしたら、着地で手が芝に 11.5 cm 沈む・構えでつま先立ち、の2つが見つかった。**描くものと別の骨組みを検証するテストは、緑でも何も守っていない**。
