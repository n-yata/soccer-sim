# 要求内容

## 概要
シャビのテストプレイの指摘3件を直す。
1. ドリブル・ショートパスは斜めにもできるべき。
2. 空きマスがあるのだから、試合開始時の配置で同じマスに選手が固まらないようにする。
3. いまどちらがボールを持っているかを、常に表示する。

## 確かめたこと・決めたこと
- ショートパスは、もともと周り8エリア（斜めを含む）へ出せた（味方がいるエリアだけ）。斜めに出せなかったのは、選手が中央に固まって斜めのエリアに味方がいなかったため。2 で解消する。
- ドリブルは前・左・右だけだった。**周り8エリアすべて**（斜め・後ろも）にする（シャビの選択）。
- 固まりは、陣形の座標から決める**基本配置そのものを散らす**（シャビの選択）。キックオフの瞬間だけ散らすと、方式の動きで基本エリアへ戻ってまた固まるため。

## 実装対象
1. **基本配置の散らし**（アルゴリズム1）
   - 座標のエリアで同じエリアに2人以上いるゾーンだけ、そのゾーンの選手を1マス1人に置き直す。
   - 左右の並び順（x。同じ x は陣形データの順）を保つ。レーンの中心（10・30・50・70・90）と x の差の合計が最小の置き方。同じなら左右の釣り合いが取れた置き方、それも同じなら左を先に詰めた置き方。
   - ゾーンの人数が5人を超えれば置き直さない。
2. **ドリブル**: 周り8エリア（アルゴリズム3）。
3. **保持の表示**: S-03 の上部バーに「● 自分のボール」／「◆ CPU のボール」を、保持側のチームの色で常に出す。開示中も隠さず、判定後の保持に替える。

## 受け入れ条件
- テストを先に書き、落ちることを確かめてから実装する。
- 4陣形の基本配置が、手で計算した表と一致する（どのエリアも1人以下）。散らしの規則（対称・並び順・同じ x・重なりの無いゾーン・6人以上）を確かめる。
- 判定例 JE-01〜08 の結果は変えない（判定の規則は変えていないので、場面は座標のエリアのまま配置で示す）。
- ドリブルの運ぶ先が周り8エリア（盤面の中だけ）。
- 保持の表示が、ターン開始と開示の両方で、盤面の保持と一致する。
- 点数は壊れていないかの目安として、CPU 同士 3〜5.5点・利用者役 1〜3.5点に広げる（シャビの選択。多すぎるかは遊んで決める）。
- `tools/run-tests.sh` で失敗0・終了コード0。

## スコープ外
- 点数の調整。
- 陣形の噛み合わせの解説の見直し（まだ作っていない）。
