# 設計

## 用語

- **S**: ターン開始時の位置（そのターンの手を選ぶ盤面の位置）。
- **J**: 判定時の位置（両者の手を適用した後）。
- **S'**: 次のターン開始時の位置。
- 1マス = ゾーン差・レーン差がどちらも1以内（チェビシェフ距離 1。斜めを含む）。
- 規則: キックオフを除き、**S から J、S から S' がどちらも1マス以内**。

## 未決事項の決定

### 固定の扱い（今の意味を保つ）
- プレス・カバー・ドリブルで動いた選手は、今と同じく固定される。固定は、トランジションが終わって攻守ターンが始まるとき、リトリートを選んだ喪失側、キックオフで解く。
- 変わるのは、解いたときに基本エリアへ一気に戻らないこと。その後は、方式の目標へ1マスずつ近づく。
- 理由: 攻守ターンが続く間の配置（寄せた選手が残る・運んだ選手がボールと一緒にいる）は今と同じになり、判定の人数とバランスへの影響が小さい。「次のターンまで」にすると、ドリブルした選手がボールから離れていく。

### 目標へ近づく1マス
- ゾーン差・レーン差をそれぞれ1ずつ詰める（斜めを優先）。`PitchArea.step_toward(target)`。
- 決定的で、チーム自身の視点で計算するので対称性を保つ。

### マンツーマンの割り当て
- 対象の優先順（守備側ゴールに近い相手から）は今と同じ。
- 誰をつけるかの「近さ」を、基本エリアではなく、マーカーの今の位置で測る（今は起点＝基本エリアか固定先）。対象と同じエリアにすでにいるマーカーを先に残す、も今と同じ。
- マーカーの目標は対象のエリアで、1マスずつ近づく。

### ボールの保持者
- 次のターン開始時に、ボールのエリアに保持側の選手がいなければ、**S と J のどちらからもボールのエリアが1マス以内**の保持側の選手を置く（いちばん近い選手。距離は J から。同じなら配置の順）。
- 候補がいなければ、誰も置かない（ボールのエリアに保持側がいないまま進む）。頻度を計測で確かめ、振り返りに残す。
  - 計測（CPU 同士 50試合・1200ターン）: 空になったターンは0回。既存の不変条件のテスト（ball_holder_invariant_test）はそのまま通るので残し、説明を「実測の性質」に直した。
- キックオフ（試合開始・得点の後・後半の開始）の保持者は、今と同じく最寄りの選手を距離を問わず置く（実装中に決めた。キックオフは仕切り直しで、全員が基本エリアに戻る例外の一部）。

### 付け直し（実装中に追加）
- 1ターンの中で付け直しが2回（プレスの後とドリブルの後）あると、マーカーが2マス動いていた（性質のテストで発見）。
- `remark` に、ターン開始の配置を渡す。マーカーはターン開始の位置から対象へ1マス近づいた位置に置く（何回付け直しても1マス以内）。

### 判定例（実装中に確認）
- 判定例の配置は「方式の動きが落ち着いた後」とする。テスト（open_play_judge_test の `_scene`）は、誰も動かなくなるまでターン開始を繰り返す。
- これで JE-01〜08 の結果は変わらなかった。

## 計測の結果（2026-10-24。CPU 同士・3シード × 50試合。加点は変えていない）

| | 前の作業の後 | この作業の後 | 目標 |
|---|---|---|---|
| 1試合の点数 | 2.41 | 2.65 | 2〜3 |
| プレー中の入れ替わり | 7.0 | 6.5 | 6〜10 |
| 保持の平均 | 2.4 | 2.5 | 2〜4 |
| 利用者を模した手の得点 | 1.65 | 1.60 | 1.0〜2.5 |

- 目標の範囲に入っているので、加点は調整しない。入れ替わりの下限までの余裕は 0.5回。
- 判定は今もこの状態を扱える（ドリブルは「ボールだけが進む」。パスは運ぶ先の味方の人数で判定する）。

### キックオフ
- 試合開始・得点の後・後半の開始では、全員を基本エリアに置き、固定を解く（今と同じ）。

## データ

- `PlayerState`:
  - `current_area: PitchArea` を足す（チーム自身の視点）。コンストラクタで省略したら基本エリア。
  - `moved_in_turn: bool` を足す。前のターンの手・トランジションの動き・保持者を置く動きで、S から動いた選手。次のターン開始の方式の動きでは動かない（S から S' を1マス以内に保つため）。
- `TeamLayout.from_players(players)`: 各選手の `current_area` を現在エリアにした配置。
- `MatchRules._store_players`: 判定時の配置（J）の現在エリアを `current_area` に写す。
- `MovementReason.RETURN` を足す（方式の動きの理由が無いまま、目標＝基本エリアへ戻る動き）。

## アルゴリズム2（StyleLayoutCalculator）

- `turn_start`（攻守ターン）:
  1. 両チームの今の位置（`current_area`）を起点にする。
  2. 方式の目標を今と同じ規則で出す（基本エリアを起点に、保持型の前進・スライド。マンツーマンは、今の位置で近いマーカーを対象へ。固定された選手は固定先）。
  3. 固定されていない選手を、目標へ1マス近づける。`moved_in_turn` の選手は動かさない。
  4. 動きの理由は、目標を決めた方式の動き（SLIDE・MARK・POSSESSION_ADVANCE）。方式の動きが無く基本エリアへ戻るときは RETURN。
- 攻撃側の目標を先に出し、マンツーマンの対象は攻撃側が1マス動いた後の位置にする（今と同じ順）。
- `remark`（ドリブル・プレス・カバーの後）: マーカーは対象へ1マス近づく（今は同じエリアへ置く）。
- `retreat`: 喪失側の固定を解き、方式の目標（基本エリア＋守備方式）へ1マス近づく（今は基本配置へ一気に戻る）。理由は RETREAT_RESET のまま。
- `reset_segment` は使わなくなるので消す（キックオフは MatchRules で基本エリアに置く）。

## アルゴリズム4（カバー）

- カバーで背後へ下がる選手の候補から、制限するエリアの前方（守備側から見て1ゾーン前）を外す。前方からだと2ゾーン下がることになるため。
  - 候補: 制限するエリア自身 → 横（中央寄り、同じなら左）→ 背後。余りの最大で選ぶ規則は今と同じ。
- `MoveRules.defense_options` の COVER の条件も合わせる（制限するエリア・横・背後のどこかに守備側がいる）。`MatchTexts.target_rule` の文言も直す。

## アルゴリズム7（試合進行）

- キックオフ: 全員の `current_area` を基本エリアに、固定と `moved_in_turn` を解く。
- `resolve_turn` の最後に、各選手の `moved_in_turn` を「次の状態の位置 ≠ S」で付け直す。
- トランジションの後に攻守ターンが始まるとき: 固定を解くだけで、位置は戻さない。
- `_place_holder(next, start)`: 上の「ボールの保持者」の規則。置いた選手は `current_area`・固定先をボールのエリアにし、`moved_in_turn` を立てる。
- 膠着したドリブル: 運んだ選手の `current_area` を B（S と同じ）へ戻す（今は固定だけ戻す）。

## ヒント・プレビュー・表示

- いずれも `turn_start` を使っているので、計算はそのまま一致する。
- 盤面: RETURN は方式の動きと同じ扱い（矢印は描かない。駒の動きで見せる）。

## テスト

- `PitchArea.step_toward` の単体テスト（縦・横・斜め・同じエリア）。
- StyleLayoutCalculator: スライドの反転が2ターンかかる、固定を解いた選手が1マスずつ戻る、マーカーが1マスずつ近づく、`moved_in_turn` の選手は動かない、目標にいれば動かない。
- DefenseMover・MoveRules: カバーの前方からの選手を使わない、条件の一致。
- MatchRules: キックオフで全員が基本エリア、トランジション後に戻らない、保持者の規則（候補あり・なし）、膠着したドリブルの位置。
- **性質のテスト**（新規 `tests/domain/match/one_step_movement_test.gd`）: CPU 同士の試合（固定シード・複数）のすべてのターンで、キックオフを除き S→J、S→S' が1マス以内。
- 既存のテストのうち、リセット（基本エリアへ一気に戻る）を前提にした期待値は、新しい規則に合わせて直す。判定例 JE-01〜08 は、1ターン目（全員が基本エリア＋方式の動き）なら結果は変わらない見込み。
- 計測のテスト（match_balance_test）で測り直し、必要なら CPU の加点を調整する。
