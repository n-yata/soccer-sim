# 要求内容

## 概要

選手が1ターンに動けるのを、隣のエリア（斜めを含む周り8エリア）までにする。
選手の位置をターンをまたいで持ち越し、方式の動き（スライド・マーク・保持型の前進・リトリートなど）は「目指す位置へ1マスずつ近づく」形にする。

## 背景

- 開示の動きで、相手のコマが2マス以上一気に飛んでくることがある（シャビの指摘。2026-10-24）。
- 計測（CPU 同士 30試合）では、ターンの始まりの配置どうしを比べると、2マス以上動く選手が1ターンに約0.7人いた。原因は3つ。いずれも今の規則（アルゴリズム2）どおりの動き。
  1. ゾーン守備のスライドが、ボールの左右で反転する（全員が2レーン横へ）。約0.31人／ターン。
  2. トランジションの後の配置区間のリセットで、全員が基本エリアへ戻る。約0.24人／ターン。
  3. マンツーマンの付け直しで、遠くの相手へマークが移る。約0.12人／ターン。
- 位置を毎ターン基本エリアから計算し直しているため、選手が「ワープ」して見える。サッカーとしても、守備が戻りきれない・スライドが追いつかない、といった読み合いの材料が盤面に現れない。
- シャビと相談し（2026-10-24）、「1ターンに動けるのは1マスまで（斜めも1マス）」を規則にする。

## 実装対象の機能

### 1. 1ターン1マスの規則
- どの選手も、1ターンの間に、ターン開始時のエリアから隣のエリア（ゾーン差・レーン差がどちらも1以内。斜めを含む8エリア）までしか動かない。
- 対象は、方式の動き・守備の手（プレス・カバー）・攻撃の手（ドリブル）・トランジションの動き（リトリート・カウンターの飛び出し）・ボールの保持者を置く動きのすべて。
- 例外: キックオフ（試合開始・得点の後・後半の開始）では、全員が基本エリアに戻る（試合の仕切り直しのため）。

### 2. 位置の持ち越し（アルゴリズム2）
- 選手の現在エリアを試合の状態に持たせ、ターンをまたいで持ち越す。
- 方式の動きは、方式が目指す位置（今の規則で出す位置。基本エリア＋スライド・マーク・保持型の前進）を「目標」として、現在エリアから目標へ1マス近づく形にする。
- 配置区間のリセット（トランジションの後に全員を基本エリアへ戻す）をやめる。戻る動きも1マスずつになる。
- 固定（プレス・カバー・ドリブルで動いた選手）の扱いを、持ち越しに合わせて決め直す（未決事項）。

### 3. マンツーマン
- マーカーは、マークする相手のエリアへ1マスずつ近づく。
- 誰が誰をマークするかは、届く（近い）マーカーを優先する形にする。遠くの相手を追い続けて、マークが永久に追いつかないことを避ける。

### 4. 守備の手・トランジション
- プレス: 今と同じく隣（上下左右）から1人が寄せる（1マス以内なので変えない）。
- カバー: 制限するエリアの背後へ下がる選手が、1マス以内で届く選手に限る（今は、隣のエリアから背後へ下がると2マス動くことがある）。
- リトリート: 基本配置へ一気に戻らず、目標へ1マス近づく。
- カウンターの飛び出し: 今と同じ（1ゾーン前。1マス以内）。

### 5. ボールの保持者
- ターンの開始時にボールのエリアに保持側の選手がいなければ、1マス以内にいる保持側の選手を1人、ボールのエリアに置く。
- 1マス以内に誰もいないときの扱いを決める（未決事項）。

### 6. ヒント・決定前のプレビュー・開示
- ヒント・決定前のプレビュー・判定は、同じ位置の計算を使う（ヒントの人数が判定と一致する。FR-16・FR-19）。
- 開示の駒の動きは、今と同じく判定前の位置から次のターンの位置へ動かす。1マスずつになるので、ワープに見える動きが無くなる。

### 7. バランスの測り直し
- エリアの人数の出方が変わるため、計測のテスト（match_balance_test）で点数・プレー中の入れ替わり・保持の長さを測り直す。
- 目標から外れたら、CPU の加点（forward_bonus・shot_bonus・anticipation_bonus など）を調整する。規則の調整が要る場合は、シャビに相談する。

## 受け入れ条件

### 1ターン1マス
- [ ] CPU 同士の試合（複数シード）のすべてのターンで、キックオフを除き、どの選手もターン開始のエリアから次のターン開始のエリアまで、ゾーン差・レーン差がどちらも1以内（テストで確かめる）。
- [ ] 判定時の配置（両者の手を適用した後）も、ターン開始のエリアから1マス以内。
- [ ] キックオフでは、全員が基本エリアにいる。

### 位置の持ち越しと方式の動き
- [ ] ゾーンのスライド: ボールが左寄りから右寄りへ移っても、選手は1ターンに1レーンずつしか動かず、2ターン目に目標へ届く。
- [ ] トランジションの後、選手は基本エリアへ一気に戻らず、1マスずつ目標へ近づく。
- [ ] マンツーマン: マーカーは相手へ1マスずつ近づき、届く範囲のマーカーが優先して割り当たる。
- [ ] 選手がすでに目標にいれば動かない。

### 守備の手・保持者
- [ ] カバーで下がる選手は1マス以内。届く選手がいないカバーは選べない（選べる手の条件を合わせる）。
- [ ] ボールの保持者を置く動きも1マス以内。

### ヒント・判定の一致
- [ ] ヒントの人数と、相手が何もしないときの判定の人数が一致する（今のテストの観点を保つ）。
- [ ] 決定前のプレビューの動きも1マス以内。

### バランス
- [ ] 計測のテストで、CPU 同士: 1試合 2〜3点、プレー中の入れ替わり 6〜10回、保持の平均 2〜4ターン。利用者を模した手の得点 1.0〜2.5点。読んだときに奪う割合が外したときより高い。

### 共通
- [ ] テストは先に失敗する状態から書く（Red→Green）。`tools/run-tests.sh` が成功する（実行件数・失敗0・終了コード0）。型の警告（エラー扱い）0件。
- [ ] 判定は対称性を保つ（利用者と CPU を入れ替えると結果が鏡写しになる。FR-05）。
- [ ] 判定に乱数を使わない（FR-05）。
- [ ] 仕様書（要件定義書 FR-05・FR-10 周辺、機能概要のアルゴリズム2〜7・判定例・エッジケース、用語集の「配置区間」「固定」、component-design・data-definition の MatchState / PlayerState）を、.drawio を含めて新しい規則に合わせる。
- [ ] 判定例（JE-01〜08）の結果が変わる場合は、変わった理由を判定例に残す。

## 成功指標

- 開示の動きで、コマが2マス以上一気に飛ぶことが無くなる（キックオフを除く）。
- ボールを失った直後に守備が戻りきれない、サイドチェンジでスライドが追いつかない、といった状況が盤面に現れ、読み合いの材料になる。
- バランスの目標（2〜3点・入れ替わり 6〜10回）を保つ。

## スコープ外

以下はこのフェーズでは実装しません:

- 選手ごとの速さ（能力値）。全員が1ターン1マス（SIM-03 の単純化を保つ）。
- 中断データの保存形式の実装（data-definition.md の更新だけ行う。保存・読み込みは保存の作業で作る）。
- 3D 演出。
- ヒントの表示の見た目の変更。

## 未決事項

設計フェーズで決める（決めた内容は design.md と振り返りに残す）。

- **固定の扱い**: 配置区間が無くなるので、プレス・カバー・ドリブルで動いた選手の固定をいつ解くか。
  - 案: 固定は次のターンの開始までとし、その後は方式の目標へ1マスずつ戻る。
  - 別案: 今のように、トランジションをまたぐまで固定を保つ。
- **保持者が1マス以内にいないとき**: ボールのエリアに保持側が誰もいないまま進めるか、ボールの位置を最寄りの味方のエリアへ寄せるか。計測で頻度を見て決める。
- **マークの割り当て方**: 「ゴールに近い相手から順」と「届くマーカーを優先」をどう組み合わせるか（例: 届く範囲で割り当て、届かない相手には最も近いマーカーが1マス近づく）。
- **目標へ近づく1マスの選び方**: 斜めと縦横のどちらを優先するか（例: ゾーン差・レーン差の両方を1ずつ詰める＝斜めを優先）。同じ距離のときの順。
