# 要求内容

## 概要

アルゴリズム6「トランジションターンの判定」をドメイン層に作る（`functional-overview.md`・`component-design.md` §2.3・§2.4）。
ボール保持が入れ替わった直後に、両チームの手を組み合わせて結果を決める。
- 失った側（喪失側）の手: 即時奪回・リトリート
- 奪った側（奪取側）の手: カウンター・保持

これで、攻守ターン（アルゴリズム5）とあわせて、すべての判定がそろう。

## 背景

- アルゴリズム5（`../20261018-open-play-judge/`）で、攻守ターンの判定ができた。`LOSS` と `SAVE` の後は、トランジションターンになる。
- 判定例 JE-07（保持型の背後をカウンターで突く）が、受け入れ基準になる。
- シャビの指示（2026-10-18「続けて」。アルゴリズム6へ進む提案への返事）。

## 実装対象の機能

### 1. `TransitionJudge`（`game/domain/judge/transition_judge.gd`）
- 呼び出し: `judge(origin, winner_styles, loser_styles, ball, winner_choice, loser_choice) -> JudgeOutput`。
  - `origin`: 直前のターン終了時点の配置。奪取側を `attacker` として持つ。
  - `ball`: 奪ったエリア `X`。奪取側の視点。
- 喪失側の配置
  - `COUNTER_PRESS`: 直前の配置のまま。
  - `RETREAT`: 基本配置に戻し（固定も解除する）、守備方式で動く（アルゴリズム2。ボール位置は `X`）。
- 奪取側の配置
  - `COUNTER`: カウンター型なら、直前の配置から大外の選手が1ゾーン前へ出る。保持型は直前の配置のまま。
  - `SECURE`: 直前の配置のまま。
- 組み合わせごとの判定

  | 喪失側 \ 奪取側 | `SECURE` | `COUNTER`（運ぶ先 `T`） |
  |---|---|---|
  | `COUNTER_PRESS` | `X` と上下左右の隣接エリアの人数合計を比べる。喪失側が上回れば `REGAIN`、同数以下は `REGAIN_FAILED` | 比較エリア `T` で、アルゴリズム5の手順5〜6を適用する |
  | `RETREAT` | `NO_CONTEST`（内訳は `null`） | 比較エリア `T` で、アルゴリズム5の手順5〜6を適用する |

- 内訳（`JudgeDetail`）の攻撃側は、奪取側。即時奪回×保持では、比較エリアに `X`、人数に周辺の合計を入れる。
- 結果の反映（保持・ボールの位置・次のターン種別・配置区間のリセット）は、試合進行（アルゴリズム7）の作業で作る。

### 2. `StyleLayoutCalculator.retreat(pair, defender_styles, ball) -> LayoutStep`
- 守備側（喪失側）を基本配置に戻して固定を解除し、守備方式の動き（ゾーンのスライド、マンツーマンのマーク）を適用する。マンツーマンのマークの対象は、`pair.attacker` の現在の配置。
- 動きは、直前の配置から位置が変わった選手だけ。理由は `RETREAT_RESET`。

### 3. `OpenPlayJudge` の比較の公開
- アルゴリズム5の手順5〜6（人数差とカバー判定）を、`TransitionJudge` と共有できるように公開する。

## 受け入れ条件

- テストは先に失敗する状態から書く（Red→Green）。`bash tools/run-tests.sh` が成功する（件数が増え、失敗0）。
- 判定例 JE-07 の両方（カウンター → `ADVANCE`、保持 → `REGAIN_FAILED`）を、実際の陣形データから再現する。途中の配置（カウンター型の飛び出し後の奪取側の配置）も確かめる。
- エッジケース
  - 即時奪回の同数は `REGAIN_FAILED`。喪失側が上回れば `REGAIN`。
  - カウンターの同数はカバー判定（敵陣の大外は `ADVANCE`、中央・ハーフスペースは GK のカバーで `STALL`）。
  - リトリート×保持は `NO_CONTEST`（内訳 `null`）。
- 配置
  - リトリートで、喪失側の固定が解除され、基本配置から守備方式で動く（ゾーンのスライドの向き、マンツーマンのマーク）。
  - 保持型の奪取側は飛び出さない。固定された奪取側の選手は飛び出さない。
- 選べない手（手の種類の取り違え、カウンターの運ぶ先の欠け、ボール位置の欠け）では `null` を返す。入力を書き換えない。
- 対称性: 奪取側のチームを入れ替えても、結果・内訳・配置が同じで、動きのチームだけが入れ替わる。
- 禁止依存の検査で 0 件、型の警告 0 件。

## 未決事項（設計で既定を決めた）

- **カウンター型の飛び出しの対象**: 固定されていない選手だけとする。方式の動きなので、アルゴリズム2の手順2（固定された選手は方式の動きの対象外）に揃える。大外かどうかは、直前の配置のレーンで見る。
- **リトリートの動き**: 1人につき1本にまとめる（直前の位置 → 最終の位置、理由 `RETREAT_RESET`）。基本エリアへ戻る動きと方式の動きを分けない。
- **カウンターの選べる運ぶ先**: `MoveRules.pos_transition_options` に渡す配置は、カウンター型の飛び出しの後の配置。これを作る関数（`TransitionJudge.counter_layout`）を公開する。
