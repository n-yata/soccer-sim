# 振り返り: 全体テストを3分以内に収める（2026-11-03）

## やったこと
- `tools/run-tests.sh` の手順3を変えた
  - gdUnit4 のコンソール出力を捨て、`results.xml` から件数と失敗を読む
  - `tests/` 直下のディレクトリごとに Godot を起動し直して順に流す
  - `APPDATA` で `user://` を分ける
  - 180秒で止めて失敗にする
  - `--with-balance` でバランスの計測を含める
- 重いテストの回数を絞った（1ターン1マス 20→4試合、CPU と最後まで戦う試合 20→4、中断データの往復 3→1）。finalize の同じ準備を使う2件を1件目へ統合した。ball_holder_invariant_test を `tests/balance/` へ移した。盤面のテストのシード探索を既知のシードから始めるようにした
- 結果: 約10分 → 160秒（78スイート・1092件・失敗0）

## わかったこと（計測）
- 遅さの大半は Windows で Godot の標準出力へ書くことだった（1回あたり数ms〜十数ms。gdUnit4 はテスト1件ごとに数回書く）。空のテスト50件で、出力を受け取ると13.0秒、捨てると2.6秒
- フレームの速さ・orphan の検出・プロジェクト設定の保存は、ほとんど効いていなかった
- 1本の Godot で全部を流すと後になるほど遅くなる（ディレクトリごとの合計より1分以上長い）
- 以前、テストを重ねて流すと無関係なテストが落ちたのは、gdUnit4 がスイートを終えるたびに `user://tmp` を消していたため。`APPDATA` を分ければ干渉しない

## 反省
- 3分以内の基準を以前にも言われていたのに、変異の確認の話としてしか覚えていなかった。メモリに直した
- 計測の実行に3分の制限を付けずに流し、シャビに止めるよう言われた
- 最初に Godot を4本並行で立てて縮めた（133秒）が、メモリに負荷をかける対応はやめるよう言われ、1本ずつ順に流す形へ戻した
