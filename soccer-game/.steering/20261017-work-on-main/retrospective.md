# 振り返り: worktree をやめて main で作業する運用への切り替え

## 何をしたか
- `AGENTS.md` の「必ず守ること」2. ブランチ運用と「実装前の確認」0. を、`main` の作業ツリーで編集・コミットする手順に書き換えた
- `AGENTS.md`「プロジェクト固有の設定」に、優先順位・同時に作業するセッションは1つに限ること・`/kit-sync` 後の確認手順を書いた
- `repository-structure.md`「汎用規約からの差分」に、外れる汎用規約（`git-workflow.md`「基本フロー」）と理由を記録した

## コミット前レビュー（review-pre-commit）の結果
- 第1回: Critical 0 / High 0 / Medium 4 / Low 3。すべて対応した（記述のみの変更のため再レビューなし）
- 全文: [review-report.md](./review-report.md)

## 学び
- 最初は `AGENTS.md` の末尾に「worktree の規則は適用しない」という上書きの節を足しただけで、kit が生成した本文の「worktree を作る」はそのまま残していた。シャビに「矛盾ないよね？」と指摘されて気づいた。規則を変えるときは、上書きを追記するのではなく、元の指示そのものを書き換える
- 規則の上書きは、優先順位と、上書きが消えたときに気づく手段（`git diff` での確認）までを書いて初めて機能する

## 改善提案（kit への提案）
- kit の `AGENTS.md` テンプレートと `git-workflow.md` に、「worktree を使わず `main`（または単一の作業ツリー）で作業する」選択肢を、プロジェクトの設定として持てるようにしてほしい。今は、選ぶとマーカー区間を手で書き換えるしかなく、`/kit-sync` のたびに警告なしで元に戻る
- 少なくとも `/kit-sync` が、マーカー区間がテンプレートと異なる場合に差分を示して確認を求めるようにしてほしい（スタブ・hooks と同じ扱い）
