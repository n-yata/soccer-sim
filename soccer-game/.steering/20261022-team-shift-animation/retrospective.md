## 計画と実績の差分

**計画と異なった点**:
- **設定を読む時期**: コントローラーは、作るときではなく使うときに読むようにした。試合を進めるだけのテストに、表示の設定ファイルを求めないため。
- **`finish_shift()`**: 作らなかった。止める経路は、次の盤面と重ね表示の消去の2つで足りるため。
- **動く選手の決め方**: 設計ではエリアで比べていた。実装レビューを受けて、駒の位置で比べる形に変えた。
  - エリアで比べると、ほかの選手の出入りで列が詰まった駒が、補間されずに飛ぶ。
- **「添字 → 駒の中心」の計算**: 4か所に重複していたので、`slot_center` に1つにまとめた。
- **道筋の計算**: `BoardShift` に分けた。
  - 前の作業のレビューで、tactics_board.gd が目安の 300 行を超えていると指摘されたため。
  - 増えた行の大半はボード側の配線（Tween・状態・描画）で、ファイルは約 590 行になった。

**新たに必要になったタスク**:
- `PresentationConfig` を作った（設計書にあるが、まだ無かった）。
  - いまは駒を動かす時間だけを持つ。
  - 3D 演出の上限と、振り返りで遡るターン数は、それぞれの作業で足す。

## 学んだこと

**技術的な学び**
- **「ルールでは起きているのに、見えていない」問題**: ルールを変えずに、見せ方だけで直せることがある。
  - 前の作業で矢印を外して盤面を絞った結果、方式の動きが見えなくなっていた。
  - 矢印を戻す代わりに駒を動かすことで、情報を増やさずに見せられた。
- **Tween の完了のように時間で起きることにも、テストが要る**
  - 強制的に止める経路だけをテストしていた。そのため、「完了で止まる」接続が外れても、全テストが緑のままだった（レビューが指摘し、変異で確かめた）。
  - ツリーに載ったノードなら、短い時間で実際に待つテストが書ける。
- **補間の対象**: 「エリアが変わった選手」ではなく「描く位置が変わった選手」にする。列の詰まりのような二次的な位置の変化も、補間しないと飛んで見える。

**プロセス上の改善点**
- **良かった点**
  - 変異の確認は、狙ったスイートだけで計24秒だった（3分以内）。
  - 実装レビューに規約をほぼ全文で渡した（前回の申し送りを反映）。
- **悪かった点**
  - **変異スクリプトを、ヒアドキュメントの Python で作り、タブが化けた（7回目）**。
    - メモリに「ヒアドキュメントで .py を書くのも不可」と書いてあったのに、「既存のスクリプトをコピーして一部を差し替える」形なら大丈夫だと思い込んだ。
    - 対象のソースは無傷。Write ツールで書き直し、メモリに追記した。
