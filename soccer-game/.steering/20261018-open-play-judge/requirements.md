# 要求内容

## 概要

アルゴリズム5「攻守ターンの判定」の手順2〜6をドメイン層に作る（`functional-overview.md`・`component-design.md` §2.2・§2.4）。
アルゴリズム2を適用した配置に、両者の手を適用し、動いた後の人数差とカバーの有無で、攻守ターンの結果を決める。

あわせて、判定の結果を返す値オブジェクトを作る。
- `JudgeDetail`: 比較エリア・人数・カバー
- `JudgeOutput`: 結果・内訳・判定時の配置・動き

## 背景

- アルゴリズム2〜4（`../20261018-style-layout/`・`../20261018-moves-and-defense/`）で、配置・選べる手・プレスとカバーができた。
- 判定は FR-05 の中核で、仕様の判定例 JE-01〜06 が受け入れ基準（NFR-14）になっている。
- シャビの指示（2026-10-18「続けて」。アルゴリズム5へ進む提案への返事）。

## 実装対象の機能

### 1. 値オブジェクト（`game/domain/`）
- `JudgeDetail`（`judge_detail.gd`）: `compare_area`（攻撃側の視点）・`attacker_count`・`defender_count`・`cover: CoverKind`。
- `JudgeOutput`（`judge_output.gd`）: `outcome: TurnOutcome`・`detail: JudgeDetail`・`pair: LayoutPair`（両者の手を適用した後の配置）・`movements: Array[Movement]`。

### 2. `OpenPlayJudge`（`game/domain/judge/open_play_judge.gd`）
- `judge(pair, attacker_styles, defender_styles, ball, attack, defense) -> JudgeOutput`。`pair` はアルゴリズム2を適用済みの配置、`ball` と運ぶ先は攻撃側の視点。
- 手順2: 守備の手を `DefenseMover.apply` で適用する。守備側がマンツーマンなら `StyleLayoutCalculator.remark` でマークを付け直す（JE-02・JE-03）。
- 手順3: 攻撃の手が `DRIBBLE` なら、ボールを持つ選手を運ぶ先へ動かして固定する。守備側がマンツーマンなら、マークを付け直す。
- 手順4〜6: 比較エリア（`SHOT` は `ball`、それ以外は運ぶ先）で人数差を出し、結果とカバーの内訳を決める。
  - `SHOT`: `diff > 0` → `GOAL`、それ以外 → `SAVE`（カバーは `NONE`）。
  - それ以外: `diff > 0` → `ADVANCE`、`diff < 0` → `LOSS`（カバーは `NONE`）、`diff = 0` → カバー判定。
  - カバー判定: 比較エリアが攻撃側の `A` なら、`C`・`L1`・`R1` は `STALL`（`GOALKEEPER`）、`L2`・`R2` は `ADVANCE`（`OUT_OF_GK_REACH`）。それ以外は、背後（攻撃側から見て1ゾーン前）で守備側人数 > 攻撃側人数なら `STALL`（`DEFENDER`）、そうでなければ `ADVANCE`（`NONE`）。
- 動きは、守備の手 → 付け直し → ドリブル → 付け直し の順に並べる。
- 手順7（結果の反映。ボールの移動・保持の入れ替え・得点）は、試合進行（アルゴリズム7）の作業で作る。

## 受け入れ条件

- テストは先に失敗する状態から書く（Red→Green）。`bash tools/run-tests.sh` が成功する（件数が増え、失敗0）。
- 判定例 JE-01〜JE-06 のすべて（JE-02 の `LOSS` の変形を含む）を、実際の陣形データ（`formations.json`）から、アルゴリズム2 → アルゴリズム5 の順に通して再現する。途中の配置（仕様に書かれた守備側の配置・寄せる選手のエリア）も確かめる。
- エッジケース
  - 敵陣ゾーンの大外で同数 → `ADVANCE`（`OUT_OF_GK_REACH`）。
  - 敵陣ゾーンの中央・ハーフスペースで同数 → `STALL`（`GOALKEEPER`）。
  - シュートは同数で `SAVE`。`diff > 0` のみ `GOAL`。
  - 背後の人数が同数ならカバーなし（`ADVANCE`）。
- `DRIBBLE`: ボールを持つ選手が運ぶ先へ動いて固定される。守備側がマンツーマンなら、マーカーがついていく。
- 対称性（FR-05）: 攻撃側のチーム（`HOME`／`AWAY`）を入れ替えても、結果・内訳・配置が同じで、動きのチームだけが入れ替わる。
- 選べない手（守備の手を適用できない、手の種類の取り違え）では `null` を返す。入力を書き換えない。
- 禁止依存の検査で 0 件、型の警告 0 件。

## 未決事項（設計で既定を決めた）

- **ドリブルする選手**: ボールのあるエリアにいる攻撃側の選手のうち、固定された選手（= 直前にボールを運んできた選手）を優先し、配置の順で先の選手。（変更前は「固定されていない選手を優先」だった。実装レビューの指摘で変えた）誰もいなければ、誰も動かさない（ボールだけが運ぶ先へ進み、人数で判定する）。
- **選べない手が渡されたとき**: `null` を返す（呼び出し側は `MoveRules.is_allowed` で先に拒否している前提）。
- **マンツーマンの付け直し**: 守備の手の後にも行う。アルゴリズム5の手順3はドリブルの後だけを書いているが、JE-02・JE-03 とアルゴリズム4のエッジケース（「プレスに出たマーカーは固定され、マークは残りのマーカーで付け直す」）が守備の手の後の付け直しを前提にしているため。
