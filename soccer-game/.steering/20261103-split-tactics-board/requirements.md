# 要求内容

## 概要

作戦ボード `tactics_board.gd`（624 行。目安 300 行）を、責務ごとにファイルを分ける。描画の `board_painter.gd`（394 行）のうち、開示の結果の演出の描画も別のファイルへ分ける。

**動作は変えない**。外から見た形（`TacticsBoard` の公開の関数・シグナル）も変えない。

## 背景

2026-11-03、シャビから「tactics_board.gd（624 行）の分割」の依頼があった。
- 視覚的な動きの強化（2拍の開示・ボールの軌道・結果の演出）で、`tactics_board.gd` は 551 → 624 行に増えた。結果の演出の作業の実装レビューで、責務が6つ（入力・盤面の状態・位置の計算・開示の動き・結果の演出・問い合わせ）混ざっていると指摘された。
- シリーズの4つ目「動きの質感」の前に分けておくと、質感の変更でボードが太らずに済む。

## 実装対象

1. **位置の計算**を、盤面の大きさだけから決まる計算のクラスへ移す（エリア・写し方・駒の列の位置・ボールの位置・ゴール）。
2. **開示の動きと結果の演出**（拍の Tween・着地・演出の状態と Tween）を、ボードの子ノードへ移す。
3. **結果の演出の描画**（輪・旗・ゴールの光）を、描画の別のクラスへ移す。
