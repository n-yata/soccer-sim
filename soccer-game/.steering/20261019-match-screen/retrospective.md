## 計画と実績の差分
- **部品と画面の子のノードを、`.tscn` ではなくコードで組んだ**。部品の差し替えとテストでの参照を優先したため。ノード名は詳細設計に合わせた。3D 演出を足すときに `.tscn` へ移すかを見直す（design.md と component-design.md に記録）。
- **詳細設計の `AreaCell`・`MoveArrowLayer` を `TacticsBoard` にまとめた**。エリアの位置の計算を、描画・入力・テストで共有するため。
- **判定理由の主語を「こちら／相手」にした**。即時奪回のように、比べるのが攻撃側でない場面で、主語が無いとどちらの優位か読めないため。
- **手のボタンの「選択不可」を次の行に出し、シュートのボタンは列の幅いっぱいにしなかった**。2列の幅に入らないため。
- **スクリーンショットで見た目の崩れを4つ見つけた**。テストは全部通っていた。
  - タグが1文字ずつ縦に並ぶ。
  - S-05 の後半開始が画面の外にはみ出す。
  - ボタンの文字が切れる。
  - 上部バーが伸びる。

## 学び
- **UI はテストが通っても見た目で壊れる**。折り返しの設定と、縮める指定（`SIZE_SHRINK_BEGIN`）の組み合わせで、ラベルの幅が0になり、文字が縦に並んだ。どのテストにも引っかからなかった。画面を作ったら、一時的なシーンで実際に描画し、スクリーンショットで確かめる工程を入れる（今回は実装の後に入れて4件見つかった）。
- **寸法のテストは、本番の配置の実寸で測る**。部品のテストで大きさをテスト自身が決めると、恒真になる。上部バーと本体の間の余白で盤面がはみ出していることを見逃した。
- **自動で進めるテストの「選び方」が、確かめたい経路を通るかを先に確かめる**。運ぶ先の一覧の先頭（いちばん後ろ）を選ぶ補助では、ボールが進まず得点が一度も起きなかった。シードの探索が「該当なし」になったときは、まず補助の選び方を疑う。
- **原因を確かめる前に直したものを、原因と書かない**。Callable を enum に替えたことを原因のように記録しかけた。実際の原因は選び方だった。
- **バックスラッシュの事故が5回目**。複数行の置き換えを Bash 経由の Python でまとめて書いた。メモリに「書き換えるたびに行の途中のタブや NUL を grep する」「行継続は使わない形で書く」を足した。
