# 要求内容

## 概要

試合画面 S-03 を作り、PC で CPU と1試合を最後まで遊べるようにする。手を選び、開示と判定理由を見て次のターンへ進む。
S-04（方式の選び直し）・S-05（ハーフタイム）・S-06（試合結果）は、試合を進めるのに要る項目だけの最小限の形で作り、
S-02 の「この布陣で試合開始」を `MatchController.start_match` につなぐ。

## 背景

- ドメイン（アルゴリズム1〜8）とアプリケーション層（`MatchController`・`CpuOpponent`・`ConfigRepository`）はそろったが、
  画面から試合を始められない。
- 得点・前半終了・後半終了で S-04・S-05・S-06 へ移るため、S-03 だけでは1試合を終えられない。
- 読み合いと数的優位の理解という試合の面白さを、実際に遊んで確かめられる段階にする。FR-02 の自己対戦の検証にも、
  遊べる画面が要る。
- 2026-10-19 にシャビと決めた範囲:
  - S-04〜S-06 は最小限にする。
  - 3D 演出と試合中のメニューは今回作らない。
  - ヒントは、設定（`UserDataService`）がまだ無いため、初期値（ON。`data-definition.md` の `show_hints`）で常に出す。

## 実装対象の機能

### 1. S-03 試合（`MatchScreen`・`MatchBoardPanel`）
正本は `screen-03-match.md`。

- **上部バー**
  - スコア表示（`ScoreBug`。「前半 5／12」の形のハーフと残りターンを含む）。
  - 局面のタグ（`ATTACK 攻撃` など）。
  - 開示中は局面のタグに替えて、両者の選択の帯（「あなた: …／CPU: …」）。
- **作戦ボード（`TacticsBoard`）**
  - ピッチを横に置き、利用者の攻撃方向を右にする。15エリアの点線とレーン名を描く。
  - 背番号つきの駒（自分 ●・相手 ◆）と、全エリアの角の優劣記号（▲・＝・▼）。
  - 選べるエリアの枠、選んだエリアの塗り、ヒントの札、ボールから運ぶ先への矢印。
  - 開示後は、動きの矢印（理由ごとに線種を分け、凡例を付ける）と、比較エリアの人数の札。
- **操作の列**
  - 両チームの陣形・方式（常に表示。FR-16・21）。
  - 手のボタン（`ChoicePanel`。選べない手は「選択不可」）。
  - 運ぶ先の説明（ヒントの札の文）。
  - 「決定」（ボタンの中に、選んだ手と運ぶ先の要約を書く）。
- **判定理由のテロップ**
  - 結果のラベル（`ADVANCE 前進` など）と判定理由の文。
  - 判定の内訳（比較エリア・両者の人数・カバー）。`NO_CONTEST` では隠す。
  - 「次へ」。
- **画面の状態**: `screen-03-match.md` の7つから `REPLAYING` を除いた6つ
  （`SELECT_ACTION`・`SELECT_TARGET`・`READY`・`SUBMITTING`・`SHOW_RESULT`・`LEAVING`）。「決定」→ `turn_resolved` の後、
  3D 演出を挟まずにすぐ `SHOW_RESULT` へ進む。
- **戻る操作**（PC の Esc・Android の戻る操作）は何もせず `true` を返す（試合画面からアプリを閉じない）。

### 2. 判定理由の文（`JudgeReasonFormatter`）とエリア名の表記
- `RevealView` から、`functional-overview.md`「表示仕様」の形式（例:「中盤・中央で 1対0。数的優位で前進」）の文を作る。
- 比較エリア・人数・カバーの有無を必ず含める。原因の句は、人数の大小とカバーの有無から作る
  （数的優位／同数／数的不利／背後にカバー）。
- `NO_CONTEST` は利用者の役割で文を変える（奪取側:「判定なし（相手は撤退、こちらは保持）」、
  喪失側:「判定なし（こちらは撤退、相手は保持）」）。
- エリア名（「中盤・中央」「中盤・左HS」など）の表記を1か所で決め、決定ボタンの要約・選択の帯・テロップで共通に使う。

### 3. S-04 方式の選び直し（最小限）
- 得点の知らせとスコア（`BoardSnapshot.last_goal_by`）。
- 相手の陣形・方式（`opponent_setup()`）。
- 守備方式・攻撃方式の2択（初期値は現在の方式）。
- 「キックオフ」→ `submit_style_change`。

### 4. S-05 ハーフタイム（最小限）
- 前半のスコア。
- 相手の前半の陣形・方式。
- 陣形の4カード（既存の `FormationCard` を使う）。
- 守備方式・攻撃方式の2択（初期値は前半の陣形・方式）。
- 「後半開始」→ `submit_halftime`。

### 5. S-06 試合結果（最小限）
- 勝敗（勝ち／引き分け／負け。色だけでなく文字で示す）。
- 最終スコア。
- 「タイトルへ」→ `leave_result()`。

### 6. `MatchController` の追加
画面の切り替えはコントローラーが要求する（`screen-02`〜`screen-06` の詳細設計のとおり）。

- `start_match`・`submit_style_change`・`submit_halftime` が成功したら、S-03 を要求する。
- `leave_result()` を足す。今は S-01 を要求するだけ。終了処理と中断データの削除は、保存・戦績の作業で足す。

### 7. S-02 の試合開始と画面の登録
- S-02 の「この布陣で試合開始」を `start_match` につなぐ。
- S-02 に状態 `STARTING` を足し、二重に試合を作らないようにする。
- `MainShell.SCREEN_SCENES` に S-03〜S-06 を足す。

## 受け入れ条件

### 共通
- [ ] テストは、すべて先に失敗する状態から書く（Red→Green）。`bash tools/run-tests.sh` で、実行件数が0件でないこと、
      失敗0・終了コード0を確かめる。型の警告（エラー扱い）も0件。
- [ ] **通しの試合**: `MainShell` から S-01 → S-02 → S-03 と進み、得点時の S-04 と S-05 を経て S-06 → S-01 まで、
      画面の操作（ボタンの押下・エリアの押下）だけで進めるテストがある。乱数は固定シードにする。

### S-03 試合
- [ ] `SELECT_ACTION` では「決定」を押せない。運ぶ先を持つ手を選ぶと `SELECT_TARGET`、選べるエリアを押すと `READY`
      になる。運ぶ先を持たない手（シュートなど）は、選んだ時点で `READY` になる。
- [ ] 選べないエリアを押しても反応しない。
- [ ] `SUBMITTING`・`LEAVING` では何も押せない（「決定」「次へ」の二度押しで2回送らない）。
- [ ] ターンが始まるたびに、前のターンの選択・ヒント・矢印が残らない。
- [ ] 駒の数と位置、優劣記号は、`BoardSnapshot` の人数と一致する（FR-16）。
- [ ] 利用者が守備のときも、利用者の攻撃方向が右で描かれる（UI でエリアを変換しない）。
- [ ] 開示で、帯に両者の手が出る（FR-09）。スコアは開示の後に更新される。比較エリアの人数の札は `RevealView` の値と一致する。
- [ ] 手を選ぶと、選べる各エリアにヒントの札（`+1`・`±0 GK外` の形）が出る。最善手の印は付けない（FR-19）。
- [ ] 戻る操作は何もせず `true` を返す。

### 判定理由の文
- [ ] 結果ごと（`ADVANCE`・`STALL`・`LOSS`・`GOAL`・`SAVE`・`REGAIN`・`REGAIN_FAILED`、`NO_CONTEST` の奪取側と喪失側）の文を
      テストで固定する。`NO_CONTEST` 以外の文には、比較エリア・人数・カバーの有無が入る。
- [ ] エリア名の表記は15エリアすべてで一意で、全画面で同じ表記を使う。

### S-04・S-05
- [ ] 初期値は現在の方式（S-05 は陣形も）。変えずに進められる。
- [ ] 確定すると、CPU の選び直しが反映された S-03 に戻る（相手の陣形・方式の表示が変わる）。
- [ ] 確定の二度押しで2回送らない。

### S-06
- [ ] 勝敗と最終スコアが `snapshot()` と一致する（勝ち・引き分け・負けのそれぞれ）。
- [ ] 「タイトルへ」で S-01 に戻り、そのあと新しい試合を始められる。

### PC での確認
- [ ] Godot エディタで実行し、マウスで1試合を最後まで遊べる（シャビが目視で確かめる）。
- [ ] 作戦ボードのエリア・ボタンの押せる範囲は 48dp 以上（NFR-19）。

## 成功指標

- シャビが PC で CPU と1試合を最後まで遊び、「どのエリアで何人対何人だったから、結果がこうなった」を画面から読み取れる。
- 1試合（24ターン）を、操作に迷わずに最後まで進められる。

## スコープ外

以下はこのフェーズでは実装しません:

- 3D 演出（`ReplayStage`・`ReplayLayer`・「スキップ」）。
- 試合中のメニュー（設定・中断してタイトルへ）と確認ダイアログ。
- 中断データの保存と再開。
- 戦績と終了処理（`final_record`）。
- 振り返り（S-07）と、S-06 の陣形・方式の推移。
- 設定画面とヒントの ON/OFF（今は常に ON）。
- 噛み合わせ・陣形・方式の解説（`style_notes` など）と「実戦では」（単純化 ID）。
- アルゴリズム9の解説文（判定理由は、人数とカバーから作る基本の文だけにする）。
- Android 実機での確認（受け入れ条件は PC での確認だけ）。
