# 要求内容

## 概要

チュートリアル（FR-12）を作る。ピッチ構造・噛み合わせ・4局面・同時手番・方式による動き方・ターン判定（人数差とカバー）・
シュートを、少なくとも1回ずつ操作して体験でき、最後にゲームが表現していないこと（FR-23 の単純化カタログ）を示す。

## 背景

タイトルのチュートリアルは「準備中」のまま。初めての人は、読み合いの仕組みを知らないまま CPU 対戦に入るしかない。
設定の作業で完了フラグ（`tutorial_completed`）の保存はできている。

## 実装対象の機能

### 1. 静的データ
- `tutorial.json`（data-definition.md §3.6）: 段階の並び。種類 `EXPLAIN`・`OPERATE`・`SCOPE`、説明文、盤面の初期状態、選べる手、相手の手、体験する要素
- `simplifications.json`（§3.4）: 単純化カタログ（functional-overview.md「単純化カタログ」と ID・件数が一致）
- 読み込み時に形・範囲を確かめる（誤りは開発時の誤り。カタログを空にする）。ルールの上で成り立つか（選べる手・相手の手が試合の規則で選べるか、7要素を網羅するか）はテストで確かめる

### 2. チュートリアル用の試合
- `App.new_tutorial_controller()`: 保存しない・画面遷移を要求しない・相手は `ScriptedOpponent`
- `MatchController.start_tutorial_step(step)`: 段階の盤面で試合の状態を作り直し、相手の台本をその段階の手に差し替える
- 盤面は、両チームが基本配置に立ち、ボールを持つ側の最寄りの選手がボールの位置に立つ（トランジションは、その配置を起点にする）

### 3. 画面
- S-08 チュートリアル（screen-08-tutorial.md）: 見出し「チュートリアル N／M」と進み具合、説明文の吹き出し、試合と同じ盤面と手の選択、「次へ」。
  `EXPLAIN` は操作できない盤面、`OPERATE` は選べる手を絞った盤面（決定して判定理由が出たら「次へ」）、最後の `SCOPE` は単純化の一覧と「完了」
- 「完了」で `mark_tutorial_completed()` を呼んでタイトルへ。「やめる」・戻る操作は確認してからタイトルへ（完了にしない）
- `SimplificationList`（S-10 と共用の単純化のカード。2列）
- タイトル: チュートリアルのカードを押せるようにする。完了後は小さなカードの最後へ移し（5列）、「はじめての方へ」を隠す

### 4. 単純化カタログの見直し
- 2026-10-25 以降に足したルール（オフサイド・スルーパスの走り込み・守備の手によるラインの上下）で古くなった行（SIM-01・SIM-04・SIM-09）を、今のルールに合わせて書き直す（案。シャビの確認を受ける）

## 受け入れ条件

- [ ] 段階をすべて進めると、7要素（PITCH・MATCHUP・PHASES・SIMULTANEOUS・STYLES・JUDGEMENT・SHOT）すべてを通り、最後に単純化の一覧が出る
- [ ] `OPERATE` の段階では、絞った手だけが選べ、決定すると相手の台本の手で判定され、判定理由が出てから「次へ」が出る
- [ ] チュートリアルでは中断データ・戦績を保存しない（本番の試合の状態にも触れない）
- [ ] 「完了」で完了フラグが保存され、タイトルのチュートリアルのカードが小さなカードの最後へ移る
- [ ] 「やめる」は確認を経てタイトルへ。完了フラグは変わらない
- [ ] 段階の定義の誤り（存在しない手・選べない相手の手・7要素の不足）をテストが見つける
- [ ] 全テストが通る

## スコープ外

- S-10 ゲームの表現範囲の画面（`SimplificationList` は作るが、画面はその作業で）
- 初回起動時の導線（タイトルの「はじめての方へ」の表示で示す。専用の案内は作らない）
- 「実戦では」の吹き出し（解説・振り返り・ヒントで単純化に関わる場面で添えるもの。単純化の作業で）
- 方式の解説（FR-17）
