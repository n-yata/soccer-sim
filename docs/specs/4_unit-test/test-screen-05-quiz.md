# 画面: クイズ画面 単体テスト仕様書

> 対象画面の詳細設計は
> [`screen-05-quiz.md`](../3_detail-design/screen/screen-05-quiz.md)。
> テスト方針全体は `<kit>/reference/rules/testing.md`「テストの種類と目安比率」を正本とする。
> 本書はコンポーネント単位のユニットテスト、および設問生成（`data/quiz.ts`）のテストケースを
> 列挙する。

## テスト対象

| コンポーネント / 関数 | テスト種別 |
|---|---|
| `buildQuiz`/`defaultShuffle`（`data/quiz.ts`） | ユニットテスト（Vitest）。外部依存なしの純粋関数（`shuffle`は決定的な関数を注入） |
| `QuizQuestionCard` | ユニットテスト（Vitest + Testing Library） |
| `QuizPage` | ユニットテスト（Vitest + Testing Library。`vue-router`はモック化） |

## 備考

- テストケース3（`buildQuiz`の正解一意性）は、クイズとして成立するための最も基本的な
  不変条件であり必須とする。
- テストケース20（参照先が存在しないマッチアップの除外）は、`formations`/`matchups`の
  データ追加・削除の運用でも壊れた設問が生成されないことの担保である。
- テストケース32（ミニピッチ図の読み上げ対応）は、`FormationMiniPitch`の`label` props
  （`component-design.md`参照）が正しく使われていることの担保であり、装飾用途（一覧カード）
  との実装差分を検知する必須ケースとする。
- テストケース46（再挑戦時の完全リセット）は、状態の一部だけをクリアする実装に戻すと
  正答数が静かに誤った値になるため、回帰防止として必須とする。
- テストケース51（出題できない場合のフォールバック）は、`data/quiz.ts`が返しうる空配列を
  画面側が正しく扱えることの担保であり、クラッシュを防ぐ必須ケースとする。
