# 画面: 陣形学習画面 単体テスト仕様書

> 対象画面の詳細設計は
> [`screen-07-formation-learning.md`](../3_detail-design/screen/screen-07-formation-learning.md)。
> テスト方針全体は `<kit>/reference/rules/testing.md`「テストの種類と目安比率」を正本とする。
> 本書はコンポーネント単位のユニットテスト（本画面はAPIを持たない）と、教材データの一貫性・
> 補間関数のテストケースを列挙する。教材の検索関数（`getFormationLesson` の過不足・不明ID）は
> [`test-screen-06-learning-list.md`](./test-screen-06-learning-list.md) を参照。

## テスト対象

| コンポーネント / 関数 | テスト種別 |
|---|---|
| `formationLessons`（`data/formationLessons.ts` と `data/lessons/`）の教材内容 | ユニットテスト（Vitest）。静的データの不変条件を全陣形について走査 |
| `interpolateFrame`（`components/tacticalReplayFrame.ts`） | ユニットテスト（Vitest）。外部依存なしの純粋関数 |
| `FormationLearningPage` | ユニットテスト（Vitest + Vue Test Utils。`createMemoryHistory` の実ルーター） |
| `TacticalReplay` / `TacticalReplayPlayer` / `TacticalReplayPitch` | ユニットテスト（Vitest + Vue Test Utils。フェイクタイマー、`matchMedia` はスタブ、教材は `wideOverloadScene`） |

## 前提データ（全テストケース共通）

`data/formations.ts`（8陣形）・`data/formationLessons.ts`（8教材）・`data/soccerTerms.ts` の実データを使う。
`TacticalReplay` 系のケースは `data/tacticalScenes.ts` の `wideOverloadScene`（5解説、`durationMs` 2800）を使う。

    再生し、タイマーが1件開始することを確かめている（jsdom の仕様に依存するため、明示的に `matchMedia` を外すテストを
    追加すると依存が無くなる）

  走査する不変条件として書いている（testing 規約「不変条件のテストは、対象データを全走査する」）。
