# 学習目標と戦術原則（壁打ちメモ）

壁打ち開始: 2026-10-17

## なぜこの壁打ちをしているか

要件定義書（承認済み）を受けて機能概要（ゲームデザイン）を詰め始めたところで、
シャビから「この選択で本当に戦術が学べるのか不安。実際の選手に遊んで戦術理解してもらいたい」
という懸念が出た。

ゲームとしては面白くても、**間違った戦術を覚えさせるリスク**がある。特に以下の3点。

1. 種別相性（パス/ドリブル/ロングボール × プレス/マーク/カバー）が根拠のないじゃんけんになりやすい
2. エリアの人数だけでは表現できない要素（ライン間の距離・最終ラインの高さ・体の向き・オフサイド・
   プレスのスイッチ等）が多く、単純化を明示しないと実戦とのズレに選手が気づく
3. ルールの戦術的妥当性を検証できる人がいない

そこで、機能概要に入る前に「何を学ばせるか」「どの戦術原則をルールにするか」を固める。

## ターゲット（この壁打ちで更新）

- **育成年代（中学・高校）**: 部活・クラブで戦術を学び始める層
- **大学・社会人・アマチュア**: 競技経験はあるが、戦術を体系的に学んだことが少ない層

要件定義書のペルソナ（戦術好きの観戦ファン／ライト層）からの変更になる。
→ 要件定義書 §2.1 の改訂が必要。

## 妥当性の根拠

- 現時点で、ルールの戦術的妥当性をレビューできる指導者・専門家はいない
- **公開された戦術理論（書籍・解説）を根拠にする**。各ルールに根拠となる原則を紐づける

## 学習目標（決定）

遊び終えた選手が、次の4つをできるようになっていること。

| ID | 学習目標 | 中身 |
|---|---|---|
| LG-1 | 位置的・数的優位を見つける | どのエリア（特にハーフスペース・ライン間）で数的優位があるかを見つけ、そこへボールを運べる |
| LG-2 | チャレンジ＆カバーとスライド | 寄せたら背後や逆サイドが空くことを理解し、どこで寄せ、どこを捨てるかを判断できる |
| LG-3 | トランジションの判断 | 奪われた瞬間に即時奪回か撤退か、奪った瞬間にカウンターか保持かを、人数と位置から判断できる |
| LG-4 | 陣形の噛み合わせ | 自分と相手の陣形から、試合前に「どこが空き、どこが薄いか」を予測できる。ハーフタイムに修正策を立てられる |

扱わないもの: **質的優位**（個の能力で上回る）。能力値を持たない設計のため、表現できない。

## 前提（これまでに決まっていること）

- ピッチ 5レーン×3ゾーン（15エリア。2026-10-25 に5レーン×6列（30エリア）へ変更）、局面は攻撃・ネガトラ・守備・ポジトラの4つ
- 同時手番。判定に乱数なし（CPU の手選びのみ乱数可）。能力値なし
- 陣形4種（4-4-2 / 4-3-3 / 4-2-3-1 / 3-5-2）。soccer-sim の座標から15エリアの人数を導出
  - レーン: 中央 d≤15、ハーフスペース 15<d<30、大外 d≥30（d=|x−50|）
  - ゾーン: y<33.3 自陣、<66.7 中盤、それ以上 敵陣。GK は数えない
- ~~判定値 = 人数差 + 種別相性(±1) − 読み当て(2)~~ → 下記「種別の意味（決定）」で改訂
- 選手位置: ボール位置で全体がスライドし、寄せ（プレス等）で動いた選手は局面が変わるまで戻らない

## 種別の意味（決定）

**種別相性（±1）は廃止。** 「プレスにはロングボールが勝つ」のような相性は、相手最終ラインの高さや
背後のスペース次第で成り立たず、戦術原則から導けない。選手が覚えると誤った一般化になる。

代わりに、種別は「**誰が動き、どのエリアで人数を比べるか**」を変えるものとする。

```
判定値 = 両者が動いた後の、比較エリアでの人数差（攻撃側 − 守備側）
  正 → 攻撃成功（ボールが比較エリアへ）
  0  → カバーの有無で決まる（下記）
  負 → ボールロスト（トランジションへ）
```

**同数のときはチャレンジ＆カバー原則で決める（決定。当初の「同数＝膠着」を改訂）**:

- 同数で、守備側の背後（比較エリアから守備側ゴール方向へ1マス）に**余っている守備者**
  （そのエリアの守備側人数 > 攻撃側人数）がいる → 膠着（ボールは動かず攻撃側が保持）
- 同数で、背後にカバーがいない → 攻撃成功（1対1で前進を許す）

改訂の理由: マンツーマンは相手と同じ人数をつけるため、同数＝膠着だとほぼ全エリアで膠着し試合が
進まないうえ「マンツーマン最強」という誤学習になる。実戦で同数局面を分けるのはカバーの有無である。
この原則により、ゾーン（コンパクトでカバーが残りやすい、ただし逆サイドは手薄）と
マンツーマン（全員が相手につきカバーが残りにくい＝ハイリスク・ハイリターン）の性格が人数から
自然に出る。LG-2 の学びそのものでもある。

**読み当てボーナス（−2）も廃止（決定）。** 守備側の「読み」は、正しいエリアへ人を動かしたか
として人数に現れる。別途ボーナスを足すと同じ読みを二重評価し、「なぜ奪われたか」を人数で
説明できなくなる。~~同数＝膠着は「同数ではボールは失わないが前進もできない」という実戦感覚に合わせた。~~
→ 改訂: 同数はカバーの有無で決める（上記「同数のときはチャレンジ＆カバー原則で決める」）。
攻守バランスは模擬プレイで確認する。

叩き台（中身は次以降の論点で詰めた。確定した内容は `functional-overview.md`「アルゴリズム設計」が正本。守備の「スライド」は守備方式に吸収して廃止）:

| 側 | 種別 | 動き・比較エリア |
|---|---|---|
| 攻撃 | ショートパス | 受け手のいる隣接エリアで比べる |
| 攻撃 | ドリブル | 運んだ先で比べる。成功すると相手を1人引きつける（その相手の元のエリアが空く） |
| 攻撃 | 背後へのロングボール | 2マス先、相手最終ラインの背後エリアで比べる |
| 守備 | プレス（チャレンジ） | 隣接エリアから1人寄せる。寄せた元は −1 のまま局面内持続 |
| 守備 | カバー | 背後エリアに1人残して守る |
| 守備 | スライド | ボールサイドへ全体を1レーンずらす。逆サイドが薄くなる |

狙い: 結果がすべて「動いた後の人数差（読みは人を動かしたエリアの人数として現れる）」で説明でき、LG-1（数的優位）と LG-2（寄せた背後が空く）に直結する。

## 守備方式・攻撃方式（決定: 導入する）

シャビの発案。試合前に選ぶのを陣形だけにせず、**守備方式（マンツーマン／ゾーン）**と
**攻撃方式（保持型／カウンター型）**も選ぶ。**方式によって選手の動き方（スライド位置）が決まる。**

- 「同じ陣形でも、守り方・攻め方の考え方でどこが空くかが変わる」という実戦の理解に直結する
- 先に検討していた「守備側だけ自動スライド」案は、実はゾーンディフェンスの動き方の決め打ちだった。方式の一つとして相対化される
- LG-4（噛み合わせ）が「陣形×陣形」から「陣形・方式×陣形・方式」へ広がる

**選択タイミング（決定）**: 試合開始時に選ぶ。**方式は試合中も変更できる**（陣形はハーフタイムのみ）。
- **変更タイミング（決定）**: ボールが止まったとき＝得失点後のキックオフ前・ハーフタイム。
  毎ターン変えられると方式が「その場の手」と区別できなくなり、操作量も増えるため
- **開示（決定）**: 変更は両者が同時・秘匿で選び、再開時に開示。試合中は相手の現在の方式を常に表示する
  （相手の戦い方は実際のピッチでも見て分かる。見えないと LG-4「相手を見て修正」が成り立たない）

方式ごとの動き方の叩き台（公開された戦術理論に基づく。詳細は未決）:

| 方式 | 動き方 | 強み | 弱み |
|---|---|---|---|
| ゾーン | ボールサイドへ1レーンずつスライドし、ボール周辺を圧縮 | ボールサイドで数的優位 | サイドチェンジで逆サイドが空く |
| マンツーマン | 担当の相手についていく（相手の動きに合わせて人数が移る） | 陣形ミスマッチの数的不利を消せる | 相手が動くと背後が空き、カバーがいない |
| 保持型 | 幅と高さを取り5レーンに配置。失った瞬間に近くに人が多い | 敵陣の数的優位・即時奪回 | 自陣が薄くカウンターに弱い |
| カウンター型 | 自陣寄りにコンパクト。奪った瞬間に前へ出る | ポジトラで前進しやすい・背後が堅い | 敵陣に人が少なく崩しが難しい |

### ゾーンディフェンスの動き方（決定）

- ボールが左右どちらかのハーフスペース／大外にあるとき、守備側フィールド選手全員が**1レーンボールサイドへ**ずれる
- ボールサイドの大外にいる選手はその場に留まる（それ以上外へ出られない）
- ボールが中央レーンなら、ずれない
- 縦方向（ラインの上げ下げ）は MVP では扱わない。**単純化として明示する**

検証例（自分 4-3-3 がボール保持側で基本配置のまま、相手 4-4-2 ゾーン、ボールは中盤の左HS）:

| 中盤 | 左大外 | 左HS | 中央 | 右HS | 右大外 |
|---|---|---|---|---|---|
| 相手（スライド前） | 1 | 0 | 2 | 0 | 1 |
| 相手（スライド後） | 1 | 2 | 0 | 1 | 0 |
| 自分 4-3-3 | 0 | 1 | 1 | 1 | 0 |

ボールのある左HSは 1対2 に圧縮され、中央は 1対0 になる。「ボールサイドで詰まったら中央・逆サイドへ
逃がす」判断が人数の変化として見える。

### マンツーマンの動き方（決定）

- 守備側は、自陣・中盤にいる相手選手（相手から見て敵陣・中盤の選手）に、**同じエリアでマーク**をつける
- 守備側の前線（敵陣ゾーンの選手）はマークに参加せず、基本位置に残る
- マーカーが余ったら、**自陣中央に残ってカバー役（リベロ）**になる
- マーカーが足りなければ、**ゴールに近い相手から優先**してマークし、外側の中盤の選手から順にフリーにする
- 相手が動いたら（ドリブル等）マーカーもついていく

全員マークだと完全な鏡写しになり守備側の陣形が意味を失う。実際のマンツーマンも相手最後尾まではつかず、
余りを最終ラインのカバーに回すことが多い。これにより「マーク対象より自陣＋中盤の人数が多い陣形ほど
カバー役を残せる」という陣形の意味が残る。

検証例（自分 4-3-3、相手 4-4-2 マンツーマン）: 4-3-3 の敵陣3＋中盤3＝6人に対し、4-4-2 の
自陣＋中盤は8人。2人余りが自陣中央のカバー役。中盤はすべて1対1。中盤中央へのパスは背後にカバー役が
いて膠着、カバーのいない大外ウイングへ届けば1対1で前進。「マンツーマン相手にはカバーの届かない外の
1対1を作る」という定石が出る。

### 方式の役割分担（決定）

- **守備方式**: ボールを持っていないときの動き方を決める
- **攻撃方式**: ボールを持っているときの配置と、トランジションでの振る舞いを決める

### 保持型・カウンター型の保持中の配置（決定）

- **保持型**: 大外レーンの選手が1ゾーン前へ出る（幅と高さ）。SB→中盤、SH/WB→敵陣。
  敵陣に人数をかけられるが、自陣はCBだけになり失ったときに薄い
- **カウンター型**: 基本配置のまま。崩しの人数は少ないが背後が堅い
- 保持型の肝であるハーフスペース占有は表現しない。**単純化として明示する**

保持型の配置（列: 左大外 / 左HS / 中央 / 右HS / 右大外）:

| 陣形 | 敵陣 | 中盤 | 自陣 | 実戦での呼び名 |
|---|---|---|---|---|
| 4-3-3 | 1 0 1 0 1 | 1 1 1 1 1 | 0 0 2 0 0 | 2-5-3 |
| 4-4-2 | 1 0 2 0 1 | 1 0 2 0 1 | 0 0 2 0 0 | 2-4-4 |
| 4-2-3-1 | 1 0 1 0 1 | 1 0 3 0 1 | 0 0 2 0 0 | 2-5-3 |
| 3-5-2 | 1 0 2 0 1 | 0 0 3 0 0 | 0 1 1 1 0 | 3-3-4 |

### トランジション（決定）

叩き台の抽象的な2×2表は廃止し、トランジションもすべて人数で判定する。

- **ネガトラ（失った側）の選択**
  - 即時奪回: ボールのあったエリア＋上下左右の隣接エリアの人数で相手と比べ、上回れば奪い返す
  - リトリート: 基本配置に戻り、守備方式の動き方で構える
- **ポジトラ（奪った側）の選択**
  - カウンター: 1〜2ゾーン前のエリアへ一気に運び、そこでの人数を比べる
  - 保持: 基本配置に戻り、通常の攻撃から始める
- **攻撃方式の違い**
  - 保持型: もともと前に人をかけているので、失った瞬間にボール周辺の人数が多く即時奪回に強い。自陣が薄くカウンターを受けやすい
  - カウンター型: カウンターを選んだ瞬間だけ、大外の選手が1ゾーン前へ飛び出す（奪った瞬間に前へ出る）
- **同時選択の扱い**
  - 相手がリトリート → カウンターは基本配置に戻った守備と比べるため止まりやすい
  - 相手が即時奪回 → 奪回に出た選手はボール周辺に集まっており、前方のエリアが空く

検証例（自分 4-3-3 保持型、相手 4-4-2 カウンター型、自分が敵陣中央でロスト）:
自分の即時奪回はボール周辺 2対4 で失敗（PA付近で CB2枚に囲まれた状態）。相手のカウンターは
SH が飛び出し自陣大外へ、こちらの SB は上がったままなので 1対0 で通る。
「保持型の背後をカウンターで突く」が人数から出る。

### ターンごとの手（決定）

方式（ゾーン／マンツーマン）は全体の動き方の規則、毎ターンの手はその上に乗る個別の判断。

- **守備の手（両方式共通）**: 制限するエリア ＋ 次のどちらか
  - プレス（チャレンジ）: 選んだエリアへ隣接エリアから1人寄せる。寄せた元は −1 のまま局面内持続。
    マンツーマンでプレスに出ると、マークしていた相手がフリーになる
  - カバー: 選んだエリアの背後へ1人下げ、カバーを厚くする
  - 誰が動くか: 余っている人数が多い隣接エリアを優先する決定的な規則（細部は機能概要で詰める）
- **攻撃の手**: 運ぶ先のエリア ＋ ショートパス／ドリブル／ロングボール（背後への1本 or サイドチェンジ）

先の叩き台の守備「スライド」は方式（ゾーン）に吸収されたため廃止。
「どこで寄せ、どこを捨てるか」は両方式で同じ判断。寄せた後に何が空くかが方式で変わる（LG-2）。

### シュートと GK（決定）

- **GK は最後のカバー**: 敵陣ゾーンの中央・HS で同数のときは、背後に GK がいるとみなし膠着。
  大外はゴールから遠く GK のカバーが届かないため、同数なら攻撃成功（サイドで1対1を抜いた）
- **シュート**: ボールが敵陣ゾーンの中央・HS にあるときだけ選べる（大外からは直接打てず、中へ運ぶ必要がある）
  - そのエリアで攻撃側が**上回っていればゴール**
  - 同数以下なら GK・守備に止められ、相手ボールで相手のポジトラから再開
- 狙い: 「ゴール前で数的優位を作れたら決まる」を得点条件にする。CB をプレス・マークで引き出して
  ゴール前の人数を逆転させる崩しの考え方が身につく
- 得点頻度は模擬プレイで確認して調整する

## 単純化の明示（決定）

実際の選手はズレに気づく。黙っていると「現実と違う」と信頼を失うか、「現実もこうだ」と誤学習する。
単純化は隠さず、**「ゲームでの表現」と「実戦ではこう」をセットで示す**。

- 単純化した項目を、根拠の戦術原則とあわせて**単純化カタログ**として持つ（正本は機能概要）
- 解説・振り返りで単純化に関わる場面が出たら「実戦では〇〇も効いてくる」と一言添える
  - 例: ゾーンのスライドで逆サイドが空いた場面 →「実戦では逆SBが絞って中央を埋めることも多い。それでも大外は空く」
- チュートリアルの最後に「このゲームが表現していること／していないこと」を1画面で示す

ここまでで出た単純化（カタログの初期項目）:

| 単純化 | ゲームでの扱い |
|---|---|
| 縦方向のライン調整（ラインの上げ下げ・ライン間の距離） | 扱わない |
| ハーフスペースの占有（保持型の内側への移動） | 扱わない（保持型は大外の前進のみ） |
| 個の能力（質的優位） | 扱わない（能力値なし） |
| オフサイド | 扱わない |
| 体の向き・タイミング・パスの質 | 扱わない |
| 人の配置 | エリア単位の人数で表す（エリア内の位置関係は扱わない） |

## 学習効果の測り方（決定）

MVP はサーバーなし・外部通信なしのため、アプリから学習データは集めない。**プレイテストで測る。**

- LG-1〜4 に対応した**場面問題**を各2問・計8問用意する
  （例:「この配置で相手のゾーンがスライドした。どこへ運ぶ？」）
- 公開前のプレイテストで、育成年代・アマチュアの選手にプレイ前とプレイ後（例: 3試合後）に解いてもらう
- **正答数の伸びを KPI** にする（例: 平均 +2問以上。目標値は要件定義書改訂時に確定）
- 同じ場面問題をアプリ内の「理解度チェック」として提供し、選手自身が確かめられるようにする。
  結果は端末内で完結し外部送信しない
- 帰結: プレイテストに協力してくれる選手を集める必要がある

## 妥当性の担保（決定）

専門家不在の間は3段構えにする。

1. **戦術原則カタログ**: すべてのルール（スライド・マーク・カバー原則・トランジション・シュート）に、
   根拠となる原則名と出典（公開された書籍・解説）を紐づける。根拠を示せないルールは入れないか、
   単純化カタログに載せる
2. **セルフレビュー用チェックリスト**: soccer-sim の `content-review-checklist.md` と同じ考え方。
