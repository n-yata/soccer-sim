# 戦術解説コンテンツ セルフレビューチェックリスト

## このドキュメントの役割

`src/data/matchups.ts` の戦術解説文（`advantagesForA` / `advantagesForB` /
`overallReason`）を、サッカー戦術の専門家でなくてもセルフレビューできるように
した観点集。

`docs/specs/1_requirements/requirements-definition.md` §7.1
「戦術解説コンテンツの正確性レビュー体制」に対応するもので、レビュー体制は
以下の通り: **開発者（Claude）が一般的な戦術理論に基づき文言を作成し、
本チェックリストに沿って開発者本人がセルフレビューする**。

`matchups.ts` に新しい組み合わせを追加・変更するたびに、このチェックリストを
上から順に確認すること。

## チェック項目

### 1. 人数表現の検算

- [ ] 「数的優位」「数的同数」「数的不利」と書いた箇所は、実際にその
      フォーメーションの該当ポジションの人数を数えて検算したか
      （例: 「守備的MF2枚 vs FW2枚」は2対2の**同数**であり「数的優位」ではない）
- [ ] ウイングバック・サイドMFなど「実質的に中盤に含めてよい」ポジションを
      加算する場合、その加算根拠（攻撃時/守備時どちらの局面の話か）を
      文中または自分の中で明確にできるか

### 2. A/B間の主張の整合性

- [ ] `advantagesForA` と `advantagesForB` が、同じ人数関係について矛盾した
      主張をしていないか（例: B側が「中盤で数的優位を握れる」と言っているのに、
      A側で同じ中盤対決を「機動力で上回る」と数的不利を認めない書き方に
      なっている、など）
- [ ] `overallReason` が `advantagesForA`/`advantagesForB` のどちらの主張を
      根拠に優劣を判定したか、読み返して説明できるか

### 3. `overallEdge` との整合性

- [ ] `overallEdge`（"A"/"B"/"even"）と `overallReason` の内容が一致しているか
      （evenなのに一方だけが有利に読める理由が書かれていないか、など）
- [ ] 全組み合わせを通して見たときに、特定のフォーメーションが常に劣位/優位に
      固定されていないか。固定されている場合、それが偶然ではなく戦術理論上
      妥当と自分の言葉で説明できるか（説明できない偏りは要見直し）

### 4. 表現の一貫性

- [ ] 同じ戦術的事象（例: サイドの1対1、中盤の枚数差）を指す語彙が組み合わせ間で
      揺れていないか
- [ ] 「〜しやすい」「〜を作れる」など断定を避けた表現で統一されているか
      （個人開発の学習用コンテンツであり、断定的な戦術評論を避ける方針）

### 5. 変更時の再チェック

- [ ] `formations.ts` のポジション定義（人数・配置）を変更した場合、その
      フォーメーションが関わる全 `matchups.ts` レコードの人数表現（1.）を
      再検算したか
- [ ] レビューで文言を修正した場合、対応する `ComparisonPage.test.ts` の
      文言アサーション（`toContain` で戦術解説文の一部を検証している箇所）も
      追随して更新したか
