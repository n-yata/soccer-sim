# 要求内容

## 概要

8種類のフォーメーション全組み合わせ（総当たり1回戦・28試合）を既存の試合シミュレーションロジックで実行し、勝ち点表として一覧できる「リーグ戦シミュレーション」画面を新設する。

## 背景

既存の試合シミュレーション（FR-14）と相性マトリクス（FR-07）は、いずれも「2フォーメーション間の1対1の関係」を扱う機能である。プロダクトビジョン（KPI: MVPで提供する8種類のフォーメーションそれぞれの強み・弱みを自分の言葉で説明できる状態になること）に対し、個々の組み合わせだけでなく「全体を通してどのフォーメーションが総合的に強い傾向にあるか」を俯瞰できると、学習効果がさらに高まる。

`simulateMatch`（`src/composables/matchSimulation.ts`）による1試合のシミュレーションは既に決定的に実装済みであり、`matchups.ts` には28組み合わせ全ての `Matchup` データが揃っている。これらをそのまま流用して総当たり戦を組めるため、実装コストの割に得られる学習効果・満足度が高いと判断した。

## 実装対象の機能

### 1. リーグ戦の実行・勝ち点表の算出

- 8フォーメーションの総当たり1回戦（全28試合、`n(n-1)/2`）を、既存の `getMatchup` と `simulateMatch` を使って決定的に実行する。
- 各フォーメーションについて、試合数・勝数・分数・敗数・得点・失点・得失点差・勝ち点（勝ち3 / 分け1 / 負け0）を集計する。
- 順位は 勝ち点 → 得失点差 → 総得点 の順で決定する。すべて同値の場合は同順位として扱う（`formations` 配列の元の並び順で安定ソートする）。
- 同じシミュレーション基盤を使うため、リーグ戦全体も再訪・再実行のたびに常に同じ結果になる（決定性）。

### 2. リーグ戦画面（新規）

- 新規ルート（例 `/league`）・新規ページコンポーネント（例 `LeaguePage.vue`）として提供する。
- 勝ち点表を、順位・フォーメーション名・試合数・勝/分/敗・得点/失点/得失点差・勝ち点の列を持つ表として表示する。
- 表の行（または専用の導線）から、該当するフォーメーションが関わる比較画面（`/compare/:formationAId/:formationBId`）へ遷移できるようにする（どの組み合わせに飛ぶかはUXとして自然な形を設計フェーズで決めてよい）。

### 3. ナビゲーション導線の追加

- `FormationListPage.vue` の既存導線群（「相性表を見る」「理解度チェック」「用語集」）に並べて、リーグ戦画面への導線を追加する。
- 一覧画面からリーグ戦画面まで、NFR-01（3クリック以内）を満たす到達性にする。

## 受け入れ条件

### リーグ戦の実行・勝ち点表の算出

- [ ] 8フォーメーション全てが勝ち点表の行として表示され、各行の試合数が7であること
- [ ] 同一フォーメーション同士の対戦が結果に含まれないこと（対戦組み合わせは28通りちょうど）
- [ ] 各フォーメーションの勝+分+敗の合計が試合数（7）と一致すること
- [ ] 得失点差 = 得点 − 失点 が表示値と一致すること
- [ ] 勝ち点 = 勝数×3 + 分数×1 と一致すること
- [ ] 順位が 勝ち点 → 得失点差 → 総得点 の順で正しくソートされていること
- [ ] 全項目が同値のフォーメーションが複数ある場合、それらが同順位で表示されること
- [ ] 画面を再訪問・リロードしても、勝ち点表の内容（各行の数値・順位）が変わらないこと（決定性）

### リーグ戦画面

- [ ] `/league` にアクセスすると勝ち点表が表示されること
- [ ] 表の行（または導線）から比較画面（`/compare/:formationAId/:formationBId`）へ遷移できること
- [ ] 一覧画面からの遷移導線が存在し、3クリック以内でリーグ戦画面に到達できること

## 成功指標

- 定量: 上記受け入れ条件（決定性・集計整合性）を自動テストで検証できる状態にする。
- 定性: 開発者本人（シャビ）が勝ち点表を見て「どのフォーメーションが総合的に強い傾向にあるか」を把握できること（要件定義書 KPI との整合）。

## スコープ外

以下はこのフェーズでは実装しません:

- ホーム&アウェイ方式（2回戦制）でのリーグ戦
- 一発勝負のトーナメント（ノックアウト方式）
- リーグ戦結果のシェア・エクスポート機能（画像化・SNS共有等）
- 勝ち点表の並び替え・フィルタ等のインタラクティブな表操作
- シミュレーション結果の手動再実行（既存ロジックが完全に決定的なため、再実行しても結果は変わらない）

## 未決事項

- 表の行から比較画面へ遷移させる際、どの操作（行クリック、チーム名クリック、専用ボタン等）にするかは設計フェーズ（design.md）で決定する。
- 勝ち点表の集計ロジックの配置場所（`composables/` か `data/` か）は、`composables/` が `data/` に依存しない既存方針との整合を見て設計フェーズで決定する。
