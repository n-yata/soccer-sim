# 要求内容

## 概要

アプリ全体に**グローバル基盤CSS（リセット＋フォント指定）が存在しない**問題を解消し、
タイポグラフィ（サイズ・ウェイト・行間）の体系を確立する。UI/UXモダナイゼーション全3フェーズの
第1弾で、**配色・装飾には一切手を付けない**（Phase 2 の担当）。

## 背景

「全体的に古く見える」という指摘を受けて現状を機械的に棚卸しした結果（2026-09-29 実施）、
装飾センス以前に**土台が2つ欠落している**ことが判明した。

### 1. グローバルCSSが存在しない（最大の原因）

- `src/styles/tokens.css` はカスタムプロパティの宣言のみで、`body` セレクタも `*` セレクタも持たない。
- **`font-family` の指定がリポジトリ全体で 0 件**（`grep -rn "font-family" src/` の結果）。
- `main.ts` が読み込むCSSは `tokens.css` のみで、リセットCSSも存在しない。

結果として、実行時は以下のブラウザ既定値がそのまま適用されている。

| 項目 | 現在の実効値 | 影響 |
|---|---|---|
| 本文フォント | ブラウザ既定のセリフ体（Windows/Chrome では Times New Roman） | 「ひと昔前のサイト」に見える最大の要因 |
| `body` のマージン | 8px（既定値） | 画面端に意図しない余白が残る |
| `box-sizing` | `content-box` | 各コンポーネントが個別に `border-box` を再指定して回避している |
| フォーム要素のフォント | ブラウザ既定（`font: inherit` 未指定） | `<button>` だけ別フォントで描画される |

### 2. ウェイト階層が崩壊している

`font-weight` の実測分布（`src/**/*.vue`）:

| 値 | 件数 |
|---|---|
| `700` | 44 |
| `400` | 4 |
| `bold` | 3 |
| `600` / `800` / `normal` | 各1 |

全54件中47件（87%）が太字。ナビ・バッジ・ラベル・本文が同じウェイトで描画され、
**情報の階層が視覚的に表現されていない**。これが「のっぺり詰まって見える」直接原因である。

### 3. タイポグラフィスケールが二重管理・不均一

- `font-size: 13px` の直書きが13件ある一方、同じ値を指す `var(--font-sm)` が14件。**同一値が二重管理**。
- トークン外の値（`11px` 4件・`7px` 1件・`14px` 4件・`16px` 5件）が混在。
- `line-height` はトークンに存在せず、`1` / `1.5` / `1.6` / `1.7` / `1.8` が場当たりに散在。

### 4. 過去3回のUI作業が土台に触れていない

| ステアリング | 実施内容 | 基盤CSSへの言及 |
|---|---|---|
| `20260911-ui-redesign-sporty` | 「スポーティ&エネルギッシュ」路線の装飾実装 | なし |
| `20260926-ui-ux-upgrade` | トークン整理・共通ヘッダー抽出・レスポンシブ | なし |
| `20260926-ui-ux-upgrade-v2` | 375/768px対応・アニメーション・a11y | なし |

3回とも**コンポーネント単位の装飾**に閉じており、リセットCSSとフォント指定という
アプリ全体の土台には一度も触れていない。ここを直さない限り、配色をどう変えてもモダンにはならない。

## 実装対象の機能

### 1. グローバル基盤CSS（`src/styles/base.css`）の新設

- ボックスモデル・マージンのリセット、日本語対応のシステムフォントスタック指定、
  既定の行間・文字色・背景色、フォーム要素への `font: inherit`、
  `color-scheme` 宣言、`:focus-visible` の共通フォーカスリングを定義する。
- `src/main.ts` から `tokens.css` の**後に**読み込む（トークンを参照するため）。

### 2. タイポグラフィトークンの再定義（`src/styles/tokens.css`）

- `--font-*` を不均一な px 値から `rem` ベースの均等なスケールへ再定義する。
- ウェイトトークン（`--weight-*`）と行間トークン（`--leading-*`）を新規追加する。

### 3. 全コンポーネントのタイポグラフィをトークンへ統一

- `font-size` / `font-weight` / `line-height` の直書きを、すべてトークン参照へ置き換える。
- ウェイトを**3段階の階層**へ再配分し、「全部太字」状態を解消する。

## 受け入れ条件

### 1. グローバル基盤CSS

- [ ] `src/styles/base.css` が存在し、`src/main.ts` が `tokens.css` の後に import している
- [ ] ブラウザの開発者ツールで `<body>` の算出 `font-family` がサンセリフ体（システムフォント）になっている
- [ ] `<body>` の算出 `margin` が `0` になっている
- [ ] 任意の `<button>` 要素の算出 `font-family` が `<body>` と一致している
- [ ] キーボードの Tab 操作で、すべての操作可能要素に視認できるフォーカスリングが出る
- [ ] 外部Webフォント（Google Fonts 等）を**一切読み込んでいない**（制約の項を参照）

### 2. タイポグラフィトークン

- [ ] `--font-xs` 〜 `--font-2xl` が `rem` 単位で定義されている
- [ ] `--weight-normal` / `--weight-medium` / `--weight-semibold` / `--weight-bold` が定義されている
- [ ] `--leading-tight` / `--leading-normal` / `--leading-relaxed` が定義されている

### 3. トークンへの統一

- [ ] `grep -rn "font-size: *[0-9]" src/ --include=*.vue` の結果が 0 件（SVG属性の `font-size` は除く）
- [ ] `grep -rn "font-weight: *\(bold\|normal\|[0-9]\)" src/ --include=*.vue` の結果が 0 件
- [ ] `grep -rn "line-height: *[0-9]" src/ --include=*.vue` の結果が 0 件
- [ ] `--weight-bold`（700）の使用箇所が **5 件以下**である
- [ ] 一覧・比較・相性表・用語集・クイズの全5画面で、見出し／ラベル／本文のウェイト差が目視で判別できる

### 4. 回帰がないこと

- [ ] `npm test` が **34ファイル / 535テスト 全passing**（2026-09-29 時点の基準値）を維持している
- [ ] `npm run lint` / `npm run typecheck` / `npm run build` がすべて成功する
- [ ] 全5画面を 375px / 768px / デスクトップ幅で目視し、横スクロールの発生・要素の重なりがない

## 成功指標

- **定量**: `font-weight: 700` 相当の使用箇所を 47 件から 5 件以下へ削減する。
  タイポグラフィ関連の直書きを 0 件にする。
- **定性**: シャビが本フェーズ完了時点の画面を見て、「フォントが原因の古さ」が解消されたと判断できること。
  Phase 2（配色・装飾の刷新）の方針判断は、この状態を見てから行う。

## スコープ外

以下はこのフェーズでは実装しない。

- **配色の変更全般**（`--color-*` の値は1つも変えない） → Phase 2
- **グラデーションページヘッダーの廃止・装飾の刷新**（枠線幅・影・角丸） → Phase 2
- **ハードコードされたカラーコード86箇所のトークン化** → Phase 3
- **ダークモード対応** → Phase 3
- 機能・ロジック・データの変更（本フェーズは表示のみを対象とする）
- 新規画面・新規コンポーネントの追加

## 制約

### 外部Webフォントの使用禁止

`docs/specs/1_requirements/architecture-overview.md`「技術的制約 > 環境要件」に
**「必要な外部依存: 無し（オフラインでも動作する静的サイト）」**と明記されている。
Google Fonts 等からWebフォントを読み込むとこの制約に違反するため、
**OS標準フォントのみで構成したフォントスタック**を用いる。

日本語グリフを持たない `system-ui`（Windows では Segoe UI）だけでは日本語が既定フォントへ
フォールバックしてしまうため、**日本語フォントを明示的にスタックへ含める**こと。

### アクセシビリティ

`.steering/20260926-a11y-audit/` および `20260926-ui-ux-upgrade-v2` でタップ領域44px・
コントラスト比 WCAG AA・`prefers-reduced-motion` 対応を作り込んである。
**フォントサイズの変更でこれらを退行させないこと**。とくに:

- 縮小方向のサイズ変更は、最小タップ領域 44px を割らないか確認する。
- `PageHeader.vue` のコメントにある通り、白文字とヘッダー背景のコントラストは
  `--color-primary` 側の暗さで AA を満たしている。**本フェーズでは色を変えないため影響しないが、
  文字サイズを下げる場合は「大きい文字」の緩和基準（3:1）から外れないか確認する。**

> **補足（ドキュメントの欠落。Phase 1 で是正する）**: アクセシビリティは実装・過去ステアリングでは
> 一貫して守られているが、`requirements-definition.md` §5 の NFR 表（NFR-01〜03）には
> 項目が存在しない。本フェーズのドキュメント更新で NFR として追加する。
