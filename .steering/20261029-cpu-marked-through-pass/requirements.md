# 要求内容

## 概要
CPU が、相手が何もしなくてもマーカーがついて入ってくるスルーパス（ヒントの札「マーク注意」）を避けるようにする。

## 背景
- 2026-10-28 に、スルーパスの運ぶ先へ守備が入ってきたら奪われる規則と、「マーク注意」の札（`ChoiceHint.is_marked`）を入れた。
- CPU はスルーパスの評価値が 0 のままで `is_marked` を見ず、マークがついてくる先へも同じように出して奪われていた（CPU 同士でスルーパスのロスト 47%。ほとんどがマークの追従）。
- シャビの指示（2026-10-29）: CPU に「マーク注意」を見せる。

## 実装対象の機能
1. CPU の評価値: `is_marked` の手から減点（`CpuConfig.marked_penalty`。0 以上。初期値 3.0 = オフサイドの減点と同じ。どちらもボールを失う見込みの手で、守備の手次第で外れることがあるため、選ばないわけではない）を引く。
2. 設定値: `cpu_config.tres` に `marked_penalty` を足し、`ConfigRepository` で 0 以上の有限の値かを検査する（範囲外なら初期値へ戻す）。
3. 仕様書: functional-overview（アルゴリズム8・設定値の表・数字の目安）、component-design。

## 受け入れ条件
- テストを先に書き、落ちることを確かめてから実装する。`tools/run-tests.sh` で失敗0・終了コード0。
- 減点が 0 のときと比べて、マーク注意のスルーパスの選択確率が下がる。マーク注意でないスルーパスの評価値は変わらない。
- `marked_penalty` は 0 を含めて読める。負・NaN・無限大なら初期値へ戻し、エラーを出す。
- CPU 同士の数字（点数・入れ替わり・スルーパスの選択率とロスト率）を壊れていないかの目安として報告する（調整はしない）。

## 成功指標
- CPU 同士でスルーパスのロスト率が下がる（マークの追従でのロストが減る）。

## スコープ外
- 利用者側の札・判定の変更。
- 受け手とマーカーが最初から運ぶ先にいる場合の扱い。
