# 要求内容

## 概要

2つのフォーメーションを選んで疑似的な90分の試合をシミュレーションし、ポゼッション・シュート数・スコア・試合のハイライトを提示する機能（FR-14）を追加する。

## 背景

要件定義書§6.2「スコープ外（後続マイルストーン）」で「簡易シミュレーション」としてP1・スコープ外に置いていた機能を、正式にMVPへ組み込む。アプリ名「soccer-sim（フォーメーションラボ）」を名乗りながら、これまでは静的な優位ポイントの箇条書きとレーダーチャートによる比較に留まっており、「シミュレーション」と呼べる動的な要素が無かった。既存の`Formation.stats`（5軸）と`Matchup.overallEdge`（噛み合わせルールから導出済みの優劣判定）という素材が既にあるため、これらを入力に、実際に試合を「動かして」結果を見せる機能として実装する。

## 実装対象の機能

### 1. 90分・1分刻みのイベント駆動シミュレーション

- 毎分、ポゼッションを持つチームを、両フォーメーションのstats（spaceControl/pressIntensity/balance）と`matchup.overallEdge`から確率的に決定する
- ポゼッションを持つチームについて、その分にチャンスが発生するか（attack vs 相手defense）→チャンスが枠内シュートになるか→シュートがゴールになるか、を段階的に確率判定する
- 乱数はシード付きPRNG（mulberry32方式）を自作し、シードはペアID（例: `"4-4-2_vs_4-3-3"`）からFNV-1aハッシュ（`matchupGenerator.ts`の`hash()`と同方式）で導出する。`Math.random`は使用しない
- 同じフォーメームの組み合わせは、常に同じ90分の展開・同じ結果になる（決定性必須）

### 2. シミュレーション結果の集計・表示

- ポゼッション%（a+b=100。1分刻みの積み上げ実績から算出。固定式で決め打ちしない）
- シュート数・枠内シュート数（`shotsOnTarget <= shots`）
- スコア（ゴール数）
- 90分のイベントタイムライン（ゴールと主要チャンスを分単位で保持）
- 試合サマリー文（平易な日本語。NFR-02準拠）
- 比較画面（`ComparisonPage.vue`）に「試合をシミュレートする」ボタンを追加し、押すとその場で結果パネル（`MatchSimulationPanel.vue`）が展開される。専用ページは作らない

## 受け入れ条件

### 90分・1分刻みのイベント駆動シミュレーション

- [ ] 同じフォーメーションの組み合わせで`simulateMatch`を複数回呼び出しても、常に同じ結果（ポゼッション・シュート・スコア・タイムライン全て）になる
- [ ] `Math.random`を直接使用していない（PRNGは自作のシード付き実装のみ）
- [ ] 極端なstats差（全軸が同一値のケースを含む）でも例外を投げず、有効な結果を返す

### シミュレーション結果の集計・表示

- [ ] ポゼッションの合計は常に100
- [ ] シュート数はゴール数以上
- [ ] 枠内シュート数はシュート数以下
- [ ] タイムラインのイベントは分（0〜90）の範囲に収まり、昇順で並ぶ
- [ ] 比較画面で「試合をシミュレートする」ボタンを押すと、スコアボード・ポゼッションバー・シュート/枠内シュートの対比・ハイライトタイムラインが表示される
- [ ] `prefers-reduced-motion`が有効な環境でも、既存のアニメーション方針（FR-06）と矛盾しない表示になる

## 成功指標

- 開発者本人が、任意の組み合わせでシミュレーションを実行し、「なぜその結果になったか」をサマリー文とタイムラインから読み取れること（定性）

## スコープ外

以下はこのフェーズでは実装しない:

- 分足より細かい粒度のシミュレーション
- 選手個人の疲労・交代等の要素
- シミュレーション結果の保存・共有機能
- 複数回シミュレーションして異なる結果を見る「リロール」機能（決定性の要件と矛盾するため）
