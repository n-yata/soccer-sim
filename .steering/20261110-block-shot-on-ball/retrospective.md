## やったこと
- ペナルティエリアで「シュートコースを塞ぐ」が、ボールの隣だけでなく、ボールのエリアに守備側がいても選べるようにした。
- 隣に誰もいなければ、ボールのエリアの選手がその場で塞ぐ（固定し、動きは空）。
- CPU 同士の計測で、出る割合は 65% から 83% になった。残りは、近くに誰もいない場面だけ。

## うまくいったこと
- 「出るときと出ないときがある」を、まず CPU 同士の試合で数えた。原因（ボールのエリアにいる守備側を数えていない）と頻度（27%）を出してから案を選んでもらえたので、1回で決まった。
- バランスの計測が落ちたとき、すぐ目安を広げたり直したりせず、HEAD を書き出して同じ計測を流した。その結果、外れの大半（得点 1.44 点・保持者の不変条件）は変更の前からだと切り分けられた。

## 次に気をつけること
- バランスの計測（`--with-balance`）は既定の実行から外れているので、規則を変えた作業で流し忘れると、外れが黙って積もる。今回、いつからか得点が目安の 2.0 点を割っていた。規則・CPU を変えたコミットの前には必ず流す。
- Bash 経由の Python の置き換え文字列に `\` を書いて、また行継続が壊れた（このセッションで4回目）。GDScript の行継続を含む置き換えは、最初から Edit か Write で書く。
