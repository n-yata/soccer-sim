## 学んだこと

**技術的な学び**:
- gdUnit4 は、スイートの途中で失敗したテストがあると、そのスイートの残りのテストを数えずに終わることがある（`Executed test cases` が全件より少なくなる）。件数が減っていたら、まず失敗したテストを直してから数え直す。変異の確認では、件数が少なくても失敗が出ていれば検出できている
- Godot の `-s`（スクリプトだけで起動）ではオートロードの名前（`App`）がコンパイルの時点で見えず、`App` を参照するクラスを使うスクリプトが読めない。画面のスクリーンショットは、使い捨てのシーンを `game/` に一時的に置いて起動し、終わったら消した
- 保存の失敗は、保存先の場所にファイルを置く（その下にファイルを作れない）か、`.tmp` の名前にディレクトリを置く（本体を残したまま書き込みだけ失敗する）と作れる。退避の失敗は、退避先の名前（日時と連番）に中身のあるディレクトリを先に置いて作った
- 推移の区切りの順序を検証しようとしたら、データ定義の件数の上限（（最大ターン数）× 2 ＋ 2）と両立しないと分かった（順序を守ると最大でも × 2 件）

**プロセス上の改善点**:
- シェル経由の Python で GDScript の `"\n"` を書き、本物の改行が入った（15回目）。レビュー指摘の修正をまとめたくなったときに起きた。バックスラッシュを含む1行だけは Edit に分ける
- 変異は書いた直後ではなくまとめて回したが、30個すべて検出できた。指摘の修正で変異の目印（アンカー）が変わったものは、目印を直して回し直した

## 次回への改善提案
- **データ定義の推移の件数の上限**: （最大ターン数）× 2 ＋ 2 は、区切りの順序を守る限り届かない。上限を × 2 に直し、順序の検証（コミット前レビュー L-2）を足す
- **`MatchController` の行数**: 約 430 行。チュートリアルの作業で `is_tutorial` を足すときに、起動時・再開・中断の公開関数を別のクラス（の薄い委譲）に寄せられるか見る
- **試合 ID の衝突**: 同じ秒に始めた2試合が同じ乱数4桁を引くと、2試合目の戦績が重複として記録されない（コミット前レビューの未検証欄）。確率は 1/10000 だが、気になるなら試合 ID の生成で中断データ・戦績との重複を避ける
- **起動時のやり直しの通知**: 起動時の終了処理のやり直しに失敗したときの通知は、`MainShell` がタイトルを開いた後に出す（中断・再開の作業で作った保留の仕組み）。実機で一度確かめる
- **戦績の写し**: `records()` は配列を写すが中の `MatchRecord` は共有している（L-4）。戦績を書き換える画面を作るときに写しを返す
- **理解度チェック・設定の作業**: `UserDataService` に回答結果・設定を足す。タイトルの理解度チェックのカードの一言とチュートリアルの位置の切り替えもそこで
