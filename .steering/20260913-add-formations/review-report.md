### Medium

**2. [バグ／静かに誤る] 既存ルール R06 の文言が、新フォーメーション 3-4-3 に対して事実と反する**

`中盤フラット4枚` は A-1 時点では 4-4-2 のみが持つタグで、R06 の文言は
「相手＝コンパクトな守備ブロック」という前提で書かれていた。3-4-3 がこのタグを
獲得したため、実出力で次が出ていた（`4-3-3_vs_3-4-3` A側）:

```
両翼のウイングが幅を使い、相手のコンパクトな守備ブロックを横に広げられる
```

相手の 3-4-3 はウイングバックを `x10/x90` に置く**最も幅を使う形**
（`spaceControl: 85`）であり、「コンパクトな守備ブロック」ではない。

design.md は「既存4種のタグが不変か」を検証項目に置いていたが、
**新形が既存タグを獲得したときに、そのタグを前提に書かれた既存ルールの文言が
真であり続けるか**は検証項目に無く、意味の誤りなのでどのテストも落ちない。

→ 修正方針（レビュー提示）: `R06.opponentTags` に `4バック` を足す案は**採らないこと**
（R02 の上位集合になり「テーマまたぎ包含」検知が落ちる）。
用語「コンパクトな守備ブロック」は R06 が唯一の運び手なので、
運び手を R25（`ウイング有 × 5バック` ＝実際に中央へ密集する形）へ移し、
R06 は compactness の断定を外す組み替えが、包含検知・用語回収の両方を壊さない。

**3. [バグ／運用] R21 `opponentTags: []` は「噛み合わせ」ではなく絶対値の加点になっており、
しかも既に判定を支えている**

`matchupGenerator.ts` は「stats を総合優劣に使わない（使うと噛み合わせでなく数値比較に
なる）」と明記しているが、R21 は相手条件ゼロ＝5バックなら全7組で無条件に +1 で、
性質としては stats と同じ絶対値加点。実測すると `4-4-2 vs 5-3-2` は score 2/1（even）で、
R21 が無ければ 2/0 → **`A`（4-4-2 有利）に反転する**。even 判定1件が無条件加点で
支えられている。

構造的な副作用:
- 既存ガード「全ルールがタグ条件を1つ以上持つ」は `selfTags.length + opponentTags.length > 0`
  しか見ないため、**片側だけ無条件**のルールは検知対象外
- `selfTags ⊇ [5バック]` の将来ルールはすべて R21 の上位集合になり、包含検知を通すには
  テーマを `最終ラインの数的関係` に揃えるしかない → 同一テーマ間引きで
  **5バックの形は最終ライン系の優位を常に1件しか出せない**、かつ配列で R21 より後ろに
  置いたものは静かに到達不能になる（R23/R09 で既に1度踏んだ現象）

→ 推奨: R21 に実在の相手条件を与える（`["2トップ"]` / `["1トップ"]` 等）か、
無条件で残すなら「`opponentTags` が空のルールは全体で1本のみ」という不変条件を
テストで固定し、なぜ1本に限るかをコメントに残す。

**4. [バグ／運用] 判定分布 even 20/28（71%）の内訳が「情報量の薄い行」を作っている**

per-formation の成績（正準順序で集計）:

| | 勝 | 敗 | 分 |
|---|---|---|---|
| 4-1-4-1 | 0 | 0 | **7** |
| 4-3-3 | 0 | 1 | 6 |
| 4-2-3-1 | 1 | 0 | 6 |
| 5-3-2 | 0 | 2 | 5 |
| 4-1-2-1-2 | 0 | 2 | 5 |
| 4-4-2 | 0 | 3 | 4 |
| 3-4-3 | 3 | 0 | 4 |
| 3-5-2 | 4 | 0 | 3 |

- **4-1-4-1 は7組すべて even** ＝相性マトリクスのその行が情報ゼロ。原因は閾値ではなく
  ルール網羅で、4-1-4-1 が拾えるのは R03/R08/R09/R13/R23/R26 のみで最大2点しか積めない
- 派生して**クイズの優劣設問は「互角」が71%正解**になり、常に「互角」と答えれば
  高得点になる（FR-12 の学習効果が薄まる）

  ±2 閾値では even が構造的に多数になる

→ `EDGE_THRESHOLD` を触るのは悪手。4-1-4-1 視点の噛み合わせルール
（`アンカー1枚` を**強み**として使う側）を足すのが筋。
