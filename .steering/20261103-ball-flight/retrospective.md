## 学んだこと

**技術的な学び**
- **進み具合と高さを分ける**: 地面の位置（影）は道筋に沿って進み、ボールだけを持ち上げる。これで浮き球もドリブルの弾みも、駒の並び順（奥から手前）を変えずに描ける。
- **進み方は1か所で決める**: 駒とボールが別々に「いまの拍か後の拍か」を判定すると、片方だけ直したときに動きがずれる。駒の道筋は flight を持たないので、同じ関数でまっすぐ等速になる。
- **見た目の値を入れる1行は、静かに抜ける**: bind で高さの値を入れ忘れても、浮き球が高さ 0 で動くだけでエラーにならない。画面の部品のテストで、値が入ったときの見え方（高さが 0 より大きい）まで確かめる。

**プロセス上の改善点**
- **全体テストは3分で打ち切る**: 結果を待ち続けず、180 秒で止めて報告する（メモリに追記した）。
- **共有ファイルの hunk の選び方**: 前のコミット（74cfc8d）で、component-design.md の「2拍にする」の注記が §5.5 の共通部品の表の中に入っていた。並行セッションと共有のファイルから自分の hunk だけを `git diff -U0` ＋ `git apply --cached --unidiff-zero` で入れたとき、**前後の文脈が無い挿入だけの hunk が、並行セッションの行の分ずれた位置に入った**。今回のコミットで正しい位置へ移した。今回は `git apply` を使わず、HEAD の内容に hunk を旧行番号で当てた結果を `git update-index --cacheinfo` で入れ、インデックスの中身を確かめた。共有ファイルを部分的にステージしたら、**インデックスの内容（`git show :path`）で挿入位置を必ず見る**。
- **バックスラッシュ**: Edit ツールに GDScript の行継続を `\\` と書いて2文字入った。変異の定義を Bash 経由の Python で書き換えて化けた。どちらもメモリにある失敗の再発。
