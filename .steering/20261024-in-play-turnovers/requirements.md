# 要求内容

## 概要

プレー中の攻守の入れ替わり（ロスト・シュート阻止・奪回成功）を、1試合 約2.3回から 6〜10回に増やす。
読みに段階をつける判定の規則と、CPU の守備の先読みで実現する。

## 背景

- 前の作業（`.steering/20261023-game-balance`）で、点数は目標（1試合 2〜3点）に入った。
- 一方、攻守の入れ替わり（6〜10回）は、得点後のキックオフで渡った分を含めて数えていた。プレー中に入れ替わるのは約2.3回だった。
  - パス・ドリブルの約9割が通り、「ずっと守るだけ」「ずっと攻めるだけ」の時間が長い。
- 計測すると、CPU の守備が攻撃の運ぶ先を読めているのは、攻撃の手の約9%だった。守備の手は、人数の脅威だけで選んでいた。
- 規則の案を試して比べた（2026-10-24）。シャビと相談し、「CPU の守備の先読み＋隣の読み」に決めた。

## 実装対象の機能

### 1. 読みの段階（判定の規則。アルゴリズム5）
- 守備の手で制限したエリアと、攻撃の比較エリアの関係で、読みを3段階にする。
  - **ぴったり**: 同じエリア。
  - **隣**: 同じゾーンで、レーンが1つ隣。
  - **外れ**: それ以外。
- シュート以外の手の結果:

  | 読み | 前進に要る人数差 | 足りないとき |
  |---|---|---|
  | ぴったり | +2 以上 | ロスト（今と同じ） |
  | 隣 | +1 以上 | ロスト |
  | 外れ | +1 以上。同数なら、背後にカバーがいれば膠着、いなければ前進 | −1 以下はロスト（今と同じ） |

- シュートは、今と同じ（ぴったり読まれた同数だけ阻止）。隣の読みは、シュートには効かない。
- トランジション（カウンター）は、今と同じく読み無し。

### 2. CPU の守備の先読み（アルゴリズム8）
- CPU の守備の手（プレス・カバー）の評価値に、`anticipation_bonus × (制限するエリアのゾーン − ボールのゾーン)` を足す。
  - ボールより前（攻撃側から見て）のエリアほど加点が大きく、後ろは負になる。
  - CPU の攻撃は前へ運ぶ手を好む（forward_bonus）。守備はそれを見越して、前のエリアを守りに行く。
- 設定値 `anticipation_bonus`（0 以上）を `cpu_config.tres` に置く。
- 攻撃の加点（forward_bonus・shot_bonus）も合わせて見直す（入れ替わりが増えると点数が下がるため）。

### 3. 判定理由の表示
- 隣を読まれて止められたロストは「隣を読まれてロスト」（守備側から見て「隣を読んでロスト」）と出す。
- ぴったりの読みの表示（「読まれて」「読み切って」）は今と同じ。

### 4. 計測
- 計測のテスト（`match_balance_test`）が、プレー中の入れ替わりで判定するようにする。
- 計測は複数のシードの平均で行う（前の作業の実装レビュー M-1）。

## 受け入れ条件

### 読みの段階
- [ ] 隣を読まれた手は、+1 で前進、同数・−1 でロストになる（カバーの有無によらない）。
- [ ] ぴったり読まれた手は、今と同じ（+2 で前進、+1 以下でロスト）。
- [ ] 外れの手は、今と同じ（同数は、カバーがいれば膠着、いなければ前進）。
- [ ] 隣は「同じゾーンで、レーンが1つ隣」だけ。ゾーンが違う・レーンが2つ以上離れたエリアは外れ。
- [ ] シュートとトランジションの結果は変わらない。
- [ ] 判定の内訳が、読みの段階を持つ（判定理由の表示とターン記録に使う）。

### CPU の守備の先読み
- [ ] 守備の手の加点は `anticipation_bonus × (ゾーン差)`。攻撃側の手には入らない。0 なら何も足さない。
- [ ] `anticipation_bonus` は、NaN・無限大・負の値なら、ほかの値と一緒に初期値へ戻す。

### 表示
- [ ] 隣の読みのロストの判定理由が、攻撃側・守備側それぞれの言い方で出る。

### 計測（同梱の設定で、CPU 同士。複数シードの平均）
- [ ] プレー中の入れ替わりが 1試合 6〜10回。
- [ ] 点数が 1試合 2〜3点。
- [ ] 保持の平均が 2〜4ターン。
- [ ] 利用者を模した手（最善手を選びやすい手）の得点が、1試合 1.0〜2.5点。
- [ ] 読みを当てたとき（ぴったり・隣）に奪う割合が、外したときより高い。

### 共通
- [ ] テストは先に失敗する状態から書く。`tools/run-tests.sh` が成功する（実行件数・失敗0・終了コード0）。
- [ ] 仕様書（要件定義書 FR-05、機能概要のアルゴリズム5・8・設定値・表示仕様・判定例、用語集ほか）を、.drawio を含めて新しい規則に合わせる。

## 成功指標

- CPU 同士の試合で、プレー中の入れ替わりが 1試合 6回以上（スパイクでは約6.9回・2.2〜2.5点・保持の平均 2.4ターン）。
- 利用者が、どこを読むかで奪えるかどうかが変わる（ぴったりでなくても、近くを読めば同数なら奪える）と感じられる。

## スコープ外

以下はこのフェーズでは実装しません:

- ヒント（FR-19）の表示の変更。ヒントの人数の計算は変えない。
- 利用者の守備の手を、CPU のように自動で先読みさせる仕組み（利用者は自分で読む）。
- シュートとトランジションの規則の変更。
- 試合のターン数の変更。
