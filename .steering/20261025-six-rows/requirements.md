# 要求内容

## 概要

盤面を 5レーン × 3列（15マス）から 5レーン × 6列（30マス）にする。試合の規則・方式の動き・基本配置・キックオフ・画面を、6列に合わせて作り直す。

## 背景

シャビのテストプレイの指摘から、15マスでは粗すぎると分かった（2026-10-24〜25）。

- キックオフで、相手陣地に自分の駒がすでにいる。中盤の列の中をハーフウェーラインが通るので、自陣を分けられない。
- 陣形の段（DF・守備的MF・攻撃的MF・FW）が3列に潰れる。たとえば 4-2-3-1 の「2」と「3」が同じ列に入る。
- ゾーンのスライドなどで1レーンずれると、端で選手が重なり、陣形が偏って見える（例: 4-3-3 の中盤が左に寄る）。

シャビの判断で、縦を6列にする。レーンは、主題の「5レーン」のまま5本。

決めたこと（2026-10-25）:
- 基本配置は、陣形の座標をそのまま6列に当てる（ライン間に空き列ができる）。
- キックオフは、陣形を自陣に縮めて置く（座標の縦を半分にする）。
- ショートパスは2マス先まで届く（ドリブルは周り1マスのまま）。
- シュートは、敵陣の奥の2列（5・6列目）の中央・ハーフスペースから打てる。

## 実装対象の機能

### 1. 6列の盤面

列の名前（自陣のゴール側から）:

| 番号 | キー | 名前 | 備考 |
|---|---|---|---|
| 1 | `D1` | 自陣ゴール前 | |
| 2 | `D2` | 自陣 | |
| 3 | `M1` | 中盤（自陣） | ここまでが自陣 |
| 4 | `M2` | 中盤（敵陣） | ハーフウェーラインは M1 と M2 の境 |
| 5 | `A1` | 敵陣 | |
| 6 | `A2` | 敵陣ゴール前 | |

- エリアのキーは `M1-C` の形（列-レーン）。
- 配置は各チーム自身の視点で持つ。相手から見ると列が逆になる（D1 ↔ A2、D2 ↔ A1、M1 ↔ M2）。

### 2. 基本配置（アルゴリズム1）
- 座標の y を6等分した列に当てる。境界は 100/6 ごとで、ちょうど境界の値は前の列に入れる（今の規則と同じ向き）。
- 重なりを散らす規則（2026-10-24）は、列ごとにそのまま使う。
- 例: 4-4-2 は DF が2列目、MF が4列目、FW が6列目。3-5-2 の中央の CB（y=15）は1列目。

### 3. キックオフ（アルゴリズム7）
- 全員を、座標の y を半分にした位置に置く。こうすると、全員が自陣の1〜3列目に入る。列ごとに重なりを散らす。
- ボールは、キックオフする側の `M1-C`。
- 保持者を置く規則は今のまま（キックオフでは距離を問わない）。
- キックオフの後は、1ターン1マスで基本エリアへ上がっていく。

### 4. 攻撃の手（アルゴリズム3）
- **ショートパス**: 2マス以内（斜めを含む。レーン差・列差がどちらも2以内）で、味方がいるエリア。
- **ドリブル**: 周り8エリア（今のまま）。
- **背後へのロングボール**: 自陣（1〜3列目）から、敵陣の奥の2列（5・6列目）のエリアへ。レーン差は1以内で、味方がいるエリア。
- **サイドチェンジ**: 同じ列で、レーン差3以上（今のまま）。
- **シュート**: 5・6列目の中央・ハーフスペース（`C`・`L1`・`R1`）から。

### 5. 守備の手
- **プレス**: 今のまま（隣の4エリアに守備者がいるエリア）。
- **カバー**: 制限するエリアが守備側の1列目（ゴール前で、背後が無い）なら選べない。今の「自陣の列は選べない」を6列で読み替えたもの。

### 6. トランジション
- **カウンター**: 運ぶ先は、ボールから1〜4列前で、味方がいるエリア。今の「1〜2ゾーン前」を6列で読み替えたもの。
- **カウンター型の大外の飛び出し**: 1列前へ。

### 7. 方式の動き（アルゴリズム2）
- **保持型**: 大外の選手の目標が1列前。
- **ゾーン**: 今のまま（レーンのずれだけ）。
- **マンツーマン**:
  - マーク対象は、守備側の1〜4列目にいる攻撃側の選手。
  - マーカーは、基本エリアが1〜4列目の選手。
  - どちらも、今の「D・M ゾーン」を6列で読み替えたもの。
  - 余ったマーカーの目標は `D2-C`（今の `D-C`）。

### 8. 試合の進行
- シュート阻止のあとは、守備側の `D1-C` から始める（ゴールキーパーのキャッチ）。

### 9. CPU の局面の加点（アルゴリズム8）
- 前へ運ぶ加点と先読みの加点は、列の差に比例する。列が倍になる分、1列あたりの加点を今の半分にする。
- これは距離あたりの強さを保つための読み替えで、調整ではない。

### 10. 画面
- 作戦ボード・ミニピッチ・陣形カードを6列で描く。
- エリア名は「中盤（敵陣）・左HS」のような形にする。
- 1エリアの押せる範囲が NFR-19（96×56dp）を満たすことを確かめる。

### 11. 判定例（JE-01〜08）
- 6列の場面で組み直し、期待値を手で書き直す。
- 陣形の名前に頼らず、配置で示す形にする。

## 受け入れ条件

### 盤面・基本配置・キックオフ
- [ ] テストを先に書き、落ちることを確かめてから実装する。
- [ ] 4陣形の基本配置が、手で計算した6列の表と一致する（どのエリアも1人以下）。
- [ ] キックオフでは、両チームとも全員が自陣（1〜3列目）にいる。キックオフの後、選手は1ターン1マスで基本エリアへ上がる。

### 規則
- [ ] 手の条件（実装対象の 4〜6）を、境界も含めてテストで確かめる。境界の例: ちょうど2マスと3マス、5列目と4列目、1列目のカバー。
- [ ] 1ターン1マスの性質のテスト（CPU の手・一様な手）が通る。
- [ ] 両チームを入れ替えた対称性のテストが通る。
- [ ] 判定例 JE-01〜08 を6列で書き直し、仕様書とテストが一致する。

### 画面
- [ ] 作戦ボードが 1280×720 で6列を描き、1エリアが NFR-19 を満たす。画面を描いて確かめる。

### 全体
- [ ] `tools/run-tests.sh` で失敗0・終了コード0。
- [ ] 点数などの数字は、壊れていないかの目安としてだけ確かめる（面白さはシャビが遊んで決める。調整はしない）。
- [ ] PC で1試合を最後まで遊べる（シャビが確かめる）。

## 成功指標

- シャビが遊んで、キックオフが自陣から始まり、陣形の段（ライン間の空き）が盤面で見分けられる。

## スコープ外

以下はこのフェーズでは実装しません:

- ターン数の見直し（遊んでから決める）。
- 点数・入れ替わりの調整。
- 陣形の噛み合わせの解説（まだ作っていない）。
- ワイヤーフレームの描き直し（積み残しのまま）。
