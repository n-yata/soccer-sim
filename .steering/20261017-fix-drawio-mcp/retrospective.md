# 振り返り: drawio MCP の接続失敗の解消

## 何をしたか
- `.mcp.json` の drawio を、空きポートで起動するラッパー（`tools/mcp/drawio-mcp.mjs`）経由に変えた
- サーバーの版を 2.3.0 に固定し、待ち受けを 127.0.0.1 に限定した
- エディタの URL を一時ディレクトリに書き出す運用を `repository-structure.md`「drawio MCP の運用」に書いた

## コミット前レビュー（review-pre-commit）の結果
- 第1回: Critical 0 / High 0 / Medium 2 / Low 6。セキュリティの指摘（M-2: 共有一時ディレクトリへの書き込み方）は規則どおり High と同じ扱いで修正し、再レビューした
- 第2回: Critical 0 / High 0 / Medium 0 / Low 3。L-a・L-b を修正した
- 全文と積み残し: [review-report.md](./review-report.md)

## 学び
- 「Connection closed」を Windows の npx の問題と決めつけず、実際に起動して標準エラー出力を見たことで、本当の原因（固定ポートを別セッションが使用中）にすぐたどり着けた
- 原因は前のセッションの時点で調べられた。接続失敗を回避策（XML を直接書く）で流し続けたことが、シャビの強い苛立ちにつながった。繰り返すツール障害は、気づいた時点で根本原因を直す
- コミットのフック（no-verify の検出）は、ヒアドキュメントの本文と git コマンドを同じコマンドに入れると誤検知する。ファイルの書き込みと git は別のコマンドに分ける

## 改善提案
- soccer-sim など、同じ drawio の設定を持つ他のリポジトリにも同じ問題がある。kit の配布物で MCP の設定例を持つなら、固定ポートのサーバーを直接起動しない形を推奨するとよい
