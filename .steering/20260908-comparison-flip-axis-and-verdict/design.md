# 設計

## 1. PitchDiagramへの左右オフセットの追加

### 経緯: 左右反転（flip）では解決しなかった

当初、上下反転の代わりに左右反転（`cx = 100 - x`）を実装した。しかし
`formations.ts`の全4フォーメーションは実は左右対称なデータ（LB⇔RB、CB⇔CB等が
ミラー関係）であり、`review-pre-commit`で「左右反転は数学的に恒等変換に等しく、
何も変わらない」と指摘された。さらに上下反転をやめたことで、両チームが同じ向きで
重なるようになった結果、GK・CB等の中央〜対称位置の選手が**完全に同一座標**へ
描画されるケースが以前より増加していた。

シャビへ報告したところ「重ね合わせはしろよ。それで左右に並べろ」という指示があり、
反転軸の変更ではなく「2枚目の選手全体を左右にオフセットして重ねる」ことを
求めていたと判明した。

### 採用した実装

```typescript
function playerCx(x: number): number {
  return x + props.offsetX;
}
```

- `PitchDiagram`に`offsetX?: number`（既定値0）propsを追加する。`flip`propsは廃止する。
- `ComparisonPage.vue`の2枚目（フォーメーションB）に`offsetX=6`を指定し、選手全体を
  右に6ずらして重ねる。
- オフセット量6は、`formations.ts`の最大x座標90に対し `90 + 6 + 4(半径) = 100` と
  viewBoxの境界にちょうど収まる値として選んだ。左端の選手（最小x=10）はオフセットで
  さらに右へ寄るため、はみ出しの心配はない。
- GK同士（x=50）はオフセット後の中心間距離が6で、円の半径4+4=8には届かないため
  依然として部分的に重なるが、完全一致（距離0）は解消される。半透明+白ストロークの
  配色と組み合わせることで、部分的な重なりでも両チームを視認できる。

## 2. Matchupへの総合優劣判定の追加

（この節は前回設計時点から変更なし）

### データ構造

```typescript
export interface Matchup {
  // ...
  overallEdge: "A" | "B" | "even";
  overallReason: string;
}
```

`getMatchup`の入れ替え正規化で`overallEdge`もA↔Bを反転する（`even`はそのまま）。

### 6組み合わせの判定根拠（一般的な戦術理論に基づく開発者判断）

| 組み合わせ | overallEdge | 理由の要旨 |
|---|---|---|
| 4-4-2 vs 4-3-3 | even | サイド1対1と中央連携が拮抗 |
| 4-4-2 vs 4-2-3-1 | B（4-2-3-1) | 中盤の実質枚数（5 vs 4）で上回る |
| 4-4-2 vs 3-5-2 | B（3-5-2） | 最終ライン+ウイングバックの数的優位 |
| 4-3-3 vs 4-2-3-1 | even | 高い位置取りと中盤の安定性が拮抗 |
| 4-3-3 vs 3-5-2 | B（3-5-2） | 5レーン構成+中盤の実質的数的優位 |
| 4-2-3-1 vs 3-5-2 | even | サイドバックとウイングバックの上下動が噛み合う |

### 画面表示

`ComparisonPage.vue`の凡例の直下に、総合判定を一言見出しとして表示する。
`overallEdge`が`"even"`なら「互角」、`"A"`/`"B"`ならその側のフォーメーション名+
「がやや優位」を太字見出しとして表示し、`overallReason`を理由として一段小さい文字で添える。
