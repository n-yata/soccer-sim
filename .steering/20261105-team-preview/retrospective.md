# 振り返り（チーム全員のプレビュー）

## できたこと

- 決定前のプレビューを、1人分の矢印から、自分の選手全員が半透明の駒で動いて戻るくり返しに変えた
  （ターン開始時 → 判定時 → 次のターン開始時の詰め直し）
- 次のターン開始時の配置は、resolve_turn から切り出した `_apply_judged` を共有して作り、試合の進め方を二重に持たない
- 遊んでの指摘で、2つ直した。動く選手のもとの駒を描かない。開示で、同じ id の相手の駒が自分の駒と一緒に動くバグ
  （選手の id は陣形の枠の id で、両チームで重なる）
- 別セッションの報告で、自分で運ぶカウンターの膠着で運んだ選手を戻した

## うまくいかなかったこと

- フェーズ3で、テストを書いたのに失敗するのを確かめず実装に進んだ。変異で代わりに確かめたら、穴が5件あった
  （止める時間・くり返し・動く時間の検証・オフサイド・パネルからの時間）。くり返しのテストは `is_previewing()` を見るだけで、
  くり返さなくても通っていた
- 変異で、くり返しを確かめるスイート（tactics_board_test）を回さず、loop のスイートだけを回していた。変異ごとに、
  その性質を確かめるテストがどのスイートにあるかを先に見る
- 開示の id の重なりは、前の開示のコミット（630fe05）より前からあった。テストの選手 id が両チームで重ならない
  （p1 と o1）ため見つからなかった。id で引く所は、同じ id が相手にもいる場面をテストに入れる
- 「後半の動き」を、試合の後半・プレビューの後半・開示の2拍目のどれか読み切れず、シャビに確かめた。確かめてから直したので、
  見当違いの直しはしなかった
- 型付き配列への三項演算子（`[]` が型なしになる）で一度落とした
