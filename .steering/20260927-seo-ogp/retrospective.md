## 学んだこと

**技術的な学び**:
- GitHub Pagesのようなプレーンな静的ホスティングでHTML5 history modeのSPAルーティングを
  使う場合、`dist/index.html`を`dist/404.html`としてコピーする（内容を完全に同一にする）のが
  標準的な回避策。GitHub Pagesは404レスポンス時にこのファイルを返すため、ブラウザのURLは
  元のまま維持され、Vue Routerがクライアント側で正しいルートを解決できる
- ローカルの検証サーバー（`vite preview`、多くの開発用staticサーバー）は親切心から
  SPAフォールバックを自動で持っていることが多く、**本番環境（GitHub Pages等の素の静的配信）の
  挙動を正確に再現しない**。「ローカルで200が返った」は「本番で動く」の証明にならないケースが
  あることを学んだ。検証には、対象の本番環境の制約（フォールバック無し等）を再現できる
  ツール（`serve`をSPAモード無しで使う等）を選ぶ必要がある
- SVGを日本語テキスト込みでPNGにラスタライズする際、`@resvg/resvg-js`の
  `loadSystemFonts: true`でOS標準の日本語フォント（Yu Gothic等）を利用でき、
  Webフォントの同梱無しでOGP画像を生成できた
- `robots.txt`はオリジン直下（`https://host/robots.txt`）でしか有効にならないという仕様は、
  GitHub Pagesのプロジェクトページ（サブパス配信）では罠になりやすい

**プロセス上の改善点**:
- コミット前レビューを「動いたから完了」で終わらせず、専門的な観点（今回はGitHub Pagesの
  静的配信の仕様）から独立して検証してもらったことで、リリース後に気づいていたら
  影響が大きかった問題を事前に潰せた。大きな構成変更（デプロイ設定等）では、
  自分の目視確認だけで完了と判断しない習慣が引き続き有効だと再確認した
