# 要求内容

## 概要

配色・装飾のデザイン言語を「スポーティ&エネルギッシュ」路線から、
**情報（ピッチ図・レーダーチャート・解説）を主役にする落ち着いた路線**へ転換する。
UI/UXモダナイゼーション全3フェーズの第2弾。

> 🚨 **前提: Phase 1（`20260929-ui-foundation`）がマージ済みであること。**
> 本フェーズは Phase 1 で整備したトークン層・基盤層の上に構築する。
> Phase 1 未完了の状態で着手すると、フォントが既定セリフ体のままの画面で
> 配色を判断することになり、判断を誤る。

> 🚨 **前提: 本 requirements.md の「デザイン方針」についてシャビの承認を得ていること。**
> 本フェーズは 2026-09-11 にシャビが承認した「スポーティ&エネルギッシュ」路線
> （`.steering/20260911-ui-redesign-sporty/`）を**意図的に転換する**作業である。
> 承認なしに着手してはならない。

## 背景

### 現在の装飾は、過去に承認された設計判断の産物である

2026-09-11 の `20260911-ui-redesign-sporty` で、以下がシャビ承認のうえ意図的に導入された。

- グリーングラデーションのページヘッダー
- カードの選択状態をオレンジ（`#FF6B35`）の枠線・背景で強調
- 総合判定エリアのチームカラーグラデーションカード＋絵文字装飾
- 芝生グラデーション＋ストライプのリアル寄りピッチ表現

**これらは失敗した実装ではなく、当時の狙いどおりに実装されたものである。**
しかし現在は「全体的に古く見える」という評価になっている。理由は、
これらの表現（全幅グラデーションバナー・太い色枠・面で塗る強調）が
**2010年代前半のWeb UIの語彙**であり、現在の標準的な感覚と乖離しているためである。

したがって本フェーズは不具合修正ではなく、**デザイン方針の意思決定のやり直し**である。
そのためシャビの承認を必須とし、関連する設計ドキュメント（画面設計・ワイヤーフレーム）も
併せて更新する。

### 現状の機械的な棚卸し（2026-09-29 実施）

| 観点 | 現状 | 問題 |
|---|---|---|
| ページヘッダー | `linear-gradient(90deg, #15803d, #115e59)` の全幅バナー | 面積の大きい彩度の高い塗り。最も古く見える要素 |
| カード枠線 | `border: 3px` | 現在の標準は 1px + 影。太枠は素朴な印象を与える |
| 影 | 実質1種類（`--shadow-card` が17箇所） | 階層の表現ができず、すべての要素が同じ高さに見える |
| ホバー | 全カードが `translateY(-2px)` の同一挙動 | 画一的 |
| 面の分離 | ページ背景もカードも白（`#ffffff`） | カードが背景から浮かず、区切りが枠線頼みになっている |
| 一覧画面のフッター注記 | `font-style: italic` のピル | イタリック体の注記は古い表現の典型 |
| 角丸 | 8 / 10 / 14px の3種が混在 | 統一感がない |

## デザイン方針（★シャビの承認が必要）

**「データを主役にする、落ち着いたスポーツUI」**

| 原則 | 内容 |
|---|---|
| 1. 色は情報にだけ使う | 装飾のための着色をやめる。色が付いている＝意味がある、という状態にする |
| 2. 構造は余白と境界で作る | 面を塗って区切るのではなく、余白・1px境界・わずかな段差で構造を示す |
| 3. 彩度を落とす | ブランドグリーンは残すが、大面積での使用をやめ、アクセントに限定する |
| 4. 階層を段差で表す | 影を3段階に整理し、「地」「カード」「浮遊物（モーダル・ポップオーバー）」を区別する |

### 変更しないもの（制約）

- **フォーメーションA＝青 / B＝赤 の配色は変更しない。**
  `docs/specs/1_requirements/functional-overview.md`「表示仕様 > カラーコーディング」に
  「ピッチ図の重ね合わせ表示・凡例・優位ポイントの見出し・レーダーチャートいずれも
  同じ色分けで統一する」と定義された**正本の情報設計**である。これは装飾ではなく意味を持つ色。
- **ピッチの緑**も同様に情報（ピッチであること）を表すため維持する。ただし
  グラデーション・ストライプの装飾強度は見直してよい。
- Phase 1 で確立したタイポグラフィ体系（サイズ・ウェイト・行間）を崩さない。

## 実装対象の機能

### 1. カラートークンの再設計

- ニュートラル（グレー）スケールを整備し、これを構造の主役にする。
- ブランドグリーンをアクセント用途に限定した値へ整理する。
- アクセントオレンジの彩度を落とし、選択状態の表現に用いる。
- ページ背景とカード背景に差を付け、カードが面として認識できるようにする。

### 2. ページヘッダーのグラデーション廃止

- `PageHeader.vue` の全幅グリーングラデーションを廃止し、
  通常背景＋下境界＋大きめのタイトルという構成へ変更する。
- 文字色が白から通常のテキスト色へ変わるため、`BackButton` など
  ヘッダー内に置かれる要素の配色も併せて見直す。

### 3. 段差・境界・角丸の体系化

- 影トークンを3段階（`--shadow-sm` / `--shadow-md` / `--shadow-lg`）へ整理する。
- カードの枠線を 3px から 1px へ変更し、選択状態はリング（`box-shadow`）とトーンで表現する。
- 角丸を3段階へ統一する。

### 4. 各画面の装飾の見直し

- 一覧画面: カード・フッター注記（イタリック廃止）
- 比較画面: 総合判定エリアのグラデーションカード・凡例・優位ポイントカード
- 相性表画面: セルの配色
- 用語集・クイズ画面: カード・設問カード

## 受け入れ条件

### 1. カラートークン

- [ ] ニュートラルスケールが `tokens.css` に定義されている
- [ ] ページ背景とカード背景が異なる値で、カードが面として視認できる
- [ ] フォーメーションA＝青 / B＝赤 の対応関係が全画面で維持されている
- [ ] コントラスト比が WCAG AA（通常文字 4.5:1 / 大きい文字 3:1）を満たしている
      （**全変更箇所で実測すること**。目視判断は不可）

### 2. ページヘッダー

- [ ] `linear-gradient` を用いたページヘッダーが存在しない
      （`grep -rn "linear-gradient" src/components/PageHeader.vue` が 0 件）
- [ ] 全5画面でページタイトル・サブタイトル・戻るボタンが判読でき、AA を満たしている

### 3. 段差・境界・角丸

- [ ] `--shadow-sm` / `--shadow-md` / `--shadow-lg` が定義され、用途別に使い分けられている
- [ ] `border: 3px` の指定が存在しない（`grep -rn "border: *3px" src/` が 0 件）
- [ ] 角丸の指定がすべてトークン参照である（`grep -rn "border-radius: *[0-9]" src/ --include=*.vue` が 0 件）

### 4. 装飾の見直し

- [ ] `font-style: italic` の指定が存在しない（`grep -rn "font-style: *italic" src/` が 0 件）
- [ ] 一覧・比較・相性表・用語集・クイズの全5画面をシャビが見て、
      「ひと昔前のサイト」という印象が解消されたと判断できる

### 5. 回帰がないこと

- [ ] `npm test` が全passing（Phase 1 完了時点の件数を基準とする）
- [ ] `npm run lint` / `npm run typecheck` / `npm run build` がすべて成功する
- [ ] 375px / 768px / デスクトップ幅で全5画面に崩れがない
- [ ] `prefers-reduced-motion` 対応が退行していない

### 6. ドキュメントが実装と一致していること

- [ ] `functional-overview.md`「表示仕様」が実装と一致している
- [ ] `screen-design.md` の全5画面のレイアウト記述が実装と一致している
      （現在「グリーングラデーションのヘッダー」「スポーティなスタイル」「オレンジの枠線」等の
      記述が5画面に散在しており、**すべて実装と食い違う状態になる**）
- [ ] `wireframes.drawio` が実装と一致している

## 成功指標

- **定量**: `linear-gradient` を用いた装飾的な背景塗りを廃止する。影トークンを1種類から3種類へ。
  角丸・枠線の直書きを 0 件にする。コントラスト比 AA 違反 0 件。
- **定性**: シャビが「モダンで使いやすい」と判断できること。これが本フェーズの主目的であり、
  **実装前にデザイン方針の承認を、実装後に画面の確認を得る**。

## スコープ外

- **ダークモード対応** → Phase 3
- **ハードコードされたカラーコード86箇所のトークン化** → Phase 3
  （本フェーズでは、触った箇所のみトークン化する。全件の掃除は Phase 3）
- タイポグラフィ体系の変更（Phase 1 で確定済み）
- 機能・ロジック・データ・画面遷移の変更
- フォーメーションA/B の色（青/赤）の変更 — 情報設計の正本のため不可
