# 要求内容

## 概要

トークン体系からの逸脱（ハードコードされた色 86 箇所・`rgba()` 直書き 11 箇所）を一掃し、
レイアウトコンテナ幅とブレークポイントを統一したうえで、**ダークモードに対応する**。
UI/UXモダナイゼーション全3フェーズの最終弾。

> 🚨 **前提: Phase 2（`20260929-ui-visual-language`）がマージ済みであること。**
> ダークモードは Phase 2 で分離したセマンティックトークン層の上に成立する。
> Phase 2 未完了の状態では、再定義すべき対象そのものが存在しない。

## 背景

### 1. トークンが正本として機能していない

Phase 1・Phase 2 でトークン体系を整えても、**コンポーネント側が値を直書きしている限り
トークンは正本にならない**。2026-09-29 時点の実測は以下のとおり。

| 種別 | 件数 | 備考 |
|---|---|---|
| カラーコードの直書き（`#rrggbb` 等） | **86** | 18ファイルに分散 |
| `rgba()` の直書き | **11** | 7ファイルに分散 |

ファイル別の上位:

| ファイル | 直書き色 |
|---|---|
| `src/components/QuizQuestionCard.vue` | 12 |
| `src/components/MatchupPitchDiagram.vue` | 12 |
| `src/components/FreeLayoutPitchDiagram.vue` | 11 |
| `src/pages/ComparisonPage.vue` | 7 |
| `src/pages/MatrixPage.vue` | 6 |
| （以下 13 ファイルに 1〜4 件ずつ） | 38 |

> **SVG 描画コンポーネント（ピッチ図・レーダーチャート）に直書きが集中している。**
> これらは SVG 属性（`fill` / `stroke`）として色を渡している箇所が多く、
> CSS カスタムプロパティを SVG 属性から参照する方法の検討が必要になる。
> 単純な置換では済まないため、本フェーズの中で最も設計判断を要する部分である。

### 2. レイアウトの基準が画面ごとにバラバラ

コンテンツの最大幅が画面ごとに異なり、さらに**グローバルヘッダーには最大幅の指定がない**。

| 画面 | コンテンツ最大幅 |
|---|---|
| `AppHeader`（全画面共通） | **指定なし**（左右パディングのみ） |
| `PageHeader`（全画面共通） | **指定なし**（左右パディングのみ） |
| 比較画面 | `1400px` |
| 一覧画面 | `1200px` |
| 用語集画面 | `1000px` |
| クイズ画面 | `640px` |

結果として、**画面を横に広げるとヘッダーの左端と本文の左端が揃わない**。
これは「作りが雑に見える」典型的な原因であり、個々の装飾品質とは別の問題である。

### 3. ブレークポイントが統一されていない

`640px` / `480px` / `769px`（`min-width`）が混在している。
`tokens.css` には以下のコメントが残っており、**問題は認識されているが未解決**の状態にある。

```css
/* breakpoints (参照用。@mediaには直接使えないため値をコメントとして残す) */
/* --breakpoint-mobile: 640px; --breakpoint-tablet: 768px; */
```

### 4. ダークモード非対応

`prefers-color-scheme` への対応が存在しない。現在は「対応していないこと」自体が
古さの印象を与える要因になっている。Phase 2 でセマンティックトークン層を分離してあるため、
**本フェーズでは主にトークンの再定義で対応できる**——ただしそれは、
上記1のハードコードを一掃した後に限る。**直書きされた色はダークモードで反転しない。**

## 実装対象の機能

### 1. ハードコード値の一掃

- CSS 内のカラーコード直書き 86 箇所をセマンティックトークン参照へ置き換える。
- `rgba()` 直書き 11 箇所を、トークン化するか `color-mix()` 等で表現する。
- SVG 属性として色を渡している箇所の扱いを設計し、統一する。

### 2. レイアウトコンテナの統一

- コンテンツ最大幅トークンを定義し、グローバルヘッダー・ページヘッダー・各画面本文で
  同一の左右基準を共有する。
- 画面ごとに最適な幅が異なる場合は、**トークンの中から選ぶ**形にする（直書きしない）。

### 3. ブレークポイントの統一

- 使用するブレークポイントを定義し、`640px` / `480px` / `769px` の混在を解消する。
- `tokens.css` の未解決コメントを、実際に機能する運用ルールへ置き換える。

### 4. ダークモード対応

- `prefers-color-scheme: dark` に応じてセマンティックトークンを再定義する。
- 全5画面がダークモードで判読でき、コントラスト比 WCAG AA を満たす状態にする。

## 受け入れ条件

### 1. ハードコード値の一掃

- [ ] `grep -rn "#[0-9a-fA-F]\{3,8\}" src/ --include=*.vue` が **0 件**
      （SVG のグラデーション定義 ID 等、色ではない `#` は除く。除外した場合は理由を design.md に記録する）
- [ ] `grep -rn "rgba(" src/ --include=*.vue` が **0 件**
- [ ] `src/styles/tokens.css` 以外に生のカラー値が存在しない

### 2. レイアウトコンテナの統一

- [ ] コンテンツ最大幅がトークンとして定義されている
- [ ] `grep -rn "max-width: *[0-9]\+px" src/ --include=*.vue` が、
      コンテナ以外の用途（ミニピッチ図の `120px`、モーダルの `560px` 等）のみに限定されている
- [ ] デスクトップ幅（1280px以上・1920px）で、**グローバルヘッダー・ページヘッダー・
      本文の左端が全5画面で揃っている**

### 3. ブレークポイントの統一

- [ ] 使用するブレークポイントが定義され、その一覧が `screen-design.md` に記載されている
- [ ] `@media` クエリの境界値が、定義された値のみを使っている
- [ ] `tokens.css` の「@mediaには直接使えないため」コメントが、実際の運用ルールに置き換わっている

### 4. ダークモード対応

- [ ] OS をダークモードにすると全5画面がダークテーマで表示される
- [ ] ダークモードで全5画面が判読でき、コントラスト比が WCAG AA を満たす（**実測すること**）
- [ ] ライトモードの表示が Phase 2 完了時点から退行していない
- [ ] ピッチ図・レーダーチャート・相性表がダークモードで正しく描画される
      （SVG の色がダークモードに追随している）
- [ ] フォーメーションA＝青 / B＝赤 の識別がダークモードでも成立している

### 5. 回帰がないこと

- [ ] `npm test` が全passing（Phase 2 完了時点の件数を基準とする）
- [ ] `npm run lint` / `npm run typecheck` / `npm run build` がすべて成功する
- [ ] 375px / 768px / デスクトップ幅で、ライト／ダーク両モードの全5画面に崩れがない

## 成功指標

- **定量**: カラー値の直書きを 86 + 11 件から 0 件へ。トークンが色の唯一の正本になる。
  ダークモードでの AA 違反 0 件。
- **定性**: 画面を広げてもヘッダーと本文の左端が揃い、「作りが揃っている」印象になること。
  OS のテーマ設定に追随すること。

## スコープ外

- 新しい配色・装飾の追加（Phase 2 で確定済み。本フェーズは**それをダークへ写像するだけ**）
- タイポグラフィ体系の変更（Phase 1 で確定済み）
- 手動のテーマ切り替えUI（トグルボタン）
  — OS 設定への追随のみを対象とする。UI の追加は機能追加であり、本フェーズの範囲を超える
- 機能・ロジック・データ・画面遷移の変更
