# 要求内容

## 概要

フォーメーションラボの全5画面で、初めて使う人にも操作の順序と情報の意味が伝わるよう、見た目と操作体験を一体で改善する。ピッチ図と比較結果を主役に据え、既存の落ち着いたデザイン方針をサッカー戦術の学習体験に合わせて発展させる。

## 背景

本アプリの主な利用者は、サッカー観戦には興味があるが戦術用語には詳しくない人である。現在の主要な流れは「一覧で2つ選ぶ → 比較で配置と理由を理解する」だが、比較画面では切り替え操作・表示オプション・結論・ピッチ図・チャート・解説・シミュレーションが連続して並ぶ。画面をまたぐ見た目の統一だけでは、何を先に見て、次に何をすればよいかは解決しない。

過去のUI作業で文字・色・余白・コンテナ幅などの基盤は整備された。今回はそれを再度整理する作業ではなく、全5画面の情報の優先順位、操作の発見しやすさ、説明文の分かりやすさを改善する。企画時点ではアプリ内Browserに接続できず、実画面の目視評価は未実施である。実装前に全画面を実際に確認し、現状の問題点を設計に反映する。

## 実装対象の機能

### 1. 共通の視覚・操作体系

- 既存の「情報を主役にする落ち着いたスポーツUI」を継承し、戦術ボードであるピッチ図を視覚的な核にする。
- 5画面で見出し、本文、補助説明、主要操作、二次操作、選択状態の優先順位を一貫して表現する。色は意味のある情報と状態の区別に使い、装飾だけの強調を増やさない。
- ページ移動後に現在地と画面の目的が分かり、キーボードでも主要操作に到達できるようにする。

### 2. 一覧から比較までの導線

- 一覧画面で「異なる2つのフォーメーションを選ぶ」という最初の行動と、選択済みの状態が明確に分かるようにする。
- 2件目の選択で比較画面へ進む既存の操作は維持し、遷移前後で何が選ばれたか見失わないようにする。
- 比較画面では、組み合わせ、総合判定、ピッチ図とその読み方、理由を学ぶための解説を自然な順序で追えるようにする。組み合わせ変更、自由配置、選手個体差、試合シミュレーションは役割が分かる形に整理する。

### 3. 補助画面の学習体験

- 相性マトリクスでは、行と列の意味、各セルの判定、確認済みの状態、比較画面へ進む操作が分かるようにする。
- 用語集では、カテゴリと用語・説明の対応が読みやすく、解説中に知らない用語が出たときに目的の項目を見つけやすくする。
- クイズでは、現在の問題数、回答後の結果、次の操作、最終結果が一連の流れとして分かるようにする。

### 4. 画面幅・アクセシビリティ・実画面確認

- デスクトップ、768px、375pxで全5画面の表示と主要操作を確認し、狭い画面でも情報の順序と操作性を保つ。
- 既存のNFR-04に従い、キーボード操作、視認できるフォーカス、色だけに頼らない状態表現、文字のコントラスト、44px以上の操作領域、動きの抑制設定に対応する。
- 実画面の確認で見つかった問題と対応結果を作業記録に残す。目視できなかった画面を確認済みとして扱わない。

## 受け入れ条件

### 共通の視覚・操作体系

- [x] 全5画面で、ページタイトル、主要操作、補助操作の役割が見た目と文言で区別できる。
- [x] フォーメーションA＝青、B＝赤という既存の情報色と、ピッチの緑を維持する。
- [x] 一覧・比較・相性マトリクス・用語集・クイズを行き来しても、ヘッダー、本文の外枠、見出し階層、操作の状態表現が一貫している。

### 一覧・比較

- [x] 初回利用者が一覧で2件選択して比較結果を表示するまで、既存のNFR-01どおり3クリック以内で操作できる。
- [x] 一覧で1件選択した状態が色以外でも判別でき、2件目の選択で遷移することが操作前に分かる。
- [x] 比較画面でA/Bの組み合わせ、総合判定、ピッチ上の配置、判定理由が、二次操作を開かずに確認できる。
- [x] 比較対象の入れ替え・切り替え、表示オプション、試合シミュレーションの各操作が目的別に見分けられ、既存の結果と操作の挙動が維持される。

### 相性マトリクス・用語集・クイズ

- [x] 相性マトリクスの任意の有効なセルで、行と列のフォーメーション名、判定、確認済みかどうかを色以外の手段でも識別でき、対応する比較画面へ進める。
- [x] 用語集でカテゴリ見出し、用語、説明の対応が画面幅にかかわらず判別できる。
- [x] クイズで回答前、回答後、最終結果の各状態において、進捗・結果・次の操作が分かり、既存の採点結果が変わらない。

### 表示・操作の検証

- [x] 全5画面を375px、768px、デスクトップ幅で実画面確認し、横スクロール、要素の重なり、読めない文字、操作不能な要素がない。
- [x] 全5画面の主要操作をキーボードで実行でき、フォーカス位置が視認できる。状態や結果を色だけで伝えない。
- [x] 変更した文字色と背景色の組み合わせがWCAG AA（通常文字4.5:1、大きい文字3:1）を満たし、主要なタップ領域が44px以上であることを実測する。
- [x] 動きを追加・変更した場合、`prefers-reduced-motion: reduce`で必要な最終状態を失わず動きを抑制できる。
- [x] 既存の自動テスト、型チェック、lint、ビルドが成功し、比較・採点・画面遷移の回帰がない。

## 成功指標

- 定量: 5画面 × 3画面幅の表示確認を完了し、上記の表示・操作上の不具合を0件にする。NFR-01の3クリック以内とNFR-04の基準を維持する。
- 定性: 初めて使う人が「どの2つを選ぶか」「比較結果のどこから読むか」「次に何を試せるか」を説明なしで理解でき、シャビが全5画面の見た目と操作の改善を実画面で確認できる。

## スコープ外

以下はこのフェーズでは実装しない:

- 新規画面、認証、バックエンド、外部サービス連携。
- フォーメーション・相性判定・試合シミュレーション・クイズ採点のデータや計算規則の変更。
- ダークモード対応。過去のステアリングで持ち越された別課題として扱う。
