## 計画と実績の差分

**計画と異なった点**:
- 計画時点では`lucide-vue-next`の採用を想定していたが、`npm install`時に
  `npm warn deprecated lucide-vue-next@1.0.0: Package deprecated. Please use @lucide/vue instead.`
  という警告を受け、後継パッケージ`@lucide/vue`へ変更した。公開品質を上げる目的の作業で
  非推奨パッケージを使うのは本末転倒と判断。アイコン名・`LucideIcon`型のexportに互換が
  あることを`node -e`で実導入確認してから切り替えた
- 絵文字の箇所数は計画時の調査で「全26箇所」としていたが、実装時に`ComparisonPage.vue`の
  「後半を開始する」ボタン（`▶`）など見落としがあり、最終的な対応表は31行になった

**新たに必要になったタスク**:
- `HalftimeTacticsModal.vue`の閉じるボタン（記号のみ、`aria-label="閉じる"`）が
  アイコン化後も維持されていることを固定する回帰テストを1件追加
- コミット前レビューの指摘を受け、`docs/specs/`配下で当初のタスクリストに挙げていなかった
  画面（用語集・相性マトリクス・クイズの詳細設計書、対応する単体テスト仕様書）にも
  絵文字表記が残っていることが判明し、追加で修正した

**技術的理由でスキップしたタスク**:

  - スキップ理由: 同ファイルは`matchups.ts`の戦術解説文（テキスト内容）レビュー専用の

## 学んだこと

**技術的な学び**:
- npm install時のdeprecated警告は、パッケージ選定の最終確認として機能する。計画段階の
  Web検索やAgentの調査だけでは検知できない情報（非推奨化のタイミング）が実際に
  `npm install`するまで分からないことがあるため、依存追加は「計画→即座に実インストールして
  警告を確認」の順で進めるのが安全
- lucideアイコンはSVGの`stroke="currentColor"`がデフォルトのため、共通ラッパー側で色を
  一切指定せず、呼び出し元のCSS `color`をそのまま継承させる設計にできた。絵文字と違い
  「テーマ色に自動追従するアイコン」を実現でき、これは絵文字では原理的にできなかった改善点
- CSSの`::before { content: "🏆 " }`のような絵文字埋め込みは、SVGアイコンへの移行時に
  テンプレート側への構造変更（実要素化）が必須になる。絵文字を多用する設計は、後からの
  アイコン差し替えコストを増大させるアンチパターンだと実感した

**プロセス上の改善点**:
- Plan modeで実装計画をユーザーに承認してもらってから`.steering/`のrequirements.md/design.md/
  tasklist.mdを作る二段構えは、大規模な横断的変更（31箇所×複数ファイル）でも迷わず
  機械的に進められて効果的だった
- 自己点検（ユーザーからの「他に詰めの甘い箇所は？」という問いかけ）が、実装の質を
  引き上げる有効なきっかけになった。次回も一度提案したら自分で批判的に見直す習慣を持つ
