# 設計書

## アーキテクチャ概要

既存Vue・SVG構成を維持する。ページが陣形と教材の静的データを取得し、表示部品にはpropsとして渡す。再生部品は教材データを直接importしない。

## コンポーネント設計

### FormationLearningPage

`/formations/:formationId/learn` で全体配置・教材のねらい・条件と注意点を表示する。一覧へ戻る導線と全8陣形の切替リンクを設ける。陣形IDをkeyにして再生部品を再生成する。

### TacticalReplay / TacticalReplayPlayer / TacticalReplayPitch

既存の補間・段階再生・停止処理を再利用する。共通教材に固定された説明・番号凡例・右サイド表示を教材データから表示するようにする。

### 教材データ

各陣形に固有のタイトル・ねらい・注意点・5段階の座標と説明を定義する。青の選手に元の陣形ポジションIDを付け、ページに役割対応を表示する。局面を切り出した図であることを明記し、全11人の配置図と区別する。4-3-3では既存サイド2対1教材をその陣形のウイングとSBに対応付けて使用する。

## データフロー

1. 一覧の学習リンクからルートへ遷移する。
2. ページがルートIDに対応する陣形・教材を取得する。
3. 再生部品に教材を渡し、各区間で自動停止して解説を表示する。

## エラーハンドリング戦略

不明な陣形ID・教材不足は学習画面内のエラー案内にする。静的データのID・座標・段階数・選手の一致はデータテストで検証する。

## テスト戦略

- Red: 新データと学習ページの未実装状態でテスト失敗を確認する。
- 全陣形の網羅、役割ID、座標、選手の一貫性、異なる軌跡、パスの到着位置を検証する。
- 画面の正常系・不明ID・陣形切替・一覧リンクと比較撤去を検証する。
- 既存再生の停止・タイマー破棄・reduced-motionテストを維持する。
- npm test / npm run lint / npm run typecheck / npm run build、ブラウザでデスクトップと375px幅を確認する。

## 依存ライブラリ

追加なし。

## ディレクトリ構造

- `src/data/formationLessons*.ts`: 陣形別教材。
- `src/types/tacticalReplay.ts`: 教材型と役割対応。
- `src/pages/FormationLearningPage.vue`: 学習ページ。
- `src/router/index.ts`: 学習ルート。

## 実装の順序

1. 失敗するデータ・画面テスト。
2. 各陣形の教材。
3. 学習画面と導線、比較画面からの移動。
4. テストとブラウザ確認、独立した実装・コミット前レビュー。
5. 正本ドキュメント更新、振り返り、コミット、PR。

## セキュリティ考慮事項

ルートIDは静的データとの照合だけに使う。説明はVueの通常補間で表示し、HTML挿入しない。サービスURL・認証情報を追加しない。

## パフォーマンス考慮事項

開いている教材だけを再生する。陣形変更・画面離脱時は既存unmount処理でタイマーとイベントリスナーを破棄する。

## 将来の拡張性

陣形ごとの教材レコードを追加できる。今回の画面は1教材を扱い、教材選択機能は追加しない。


## 再生状態の引き継ぎ

学習ページがsceneを渡し、陣形IDをkeyとして切替時に再生成する。再生部品は到着状態のindex、次状態への補間率progress、isPlaying、shouldReduceMotionを持つ。教材のdurationMsを基準に経過時間で進み、32ms間隔の時計は再生中だけ有効。途中停止時のprogressを保持して再開する。解説への移動は時計を解除し、indexを有効範囲に制限してprogressを0へ戻す。動きを減らす設定の変更とvisibilitychangeを監視し、unmountで時計・監視を解除する。
