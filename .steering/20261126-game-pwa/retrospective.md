## 計画と実績の差分

- ラボの画面からゲームへのリンクは、ワイヤーフレームと画面設計を同じ PR で更新する規則に掛かるため、別の PR に分けた

**新たに必要になったタスク**:

## 学んだこと

**技術的な学び**:
- Godot の Web 書き出しは、GitHub Pages ではスレッドなし版にする（COOP/COEP ヘッダーを付けられない）。単体の 3D・音・`user://` は
  そのまま動いた
- ブラウザ版の Godot には端末のフォントへのフォールバックが無い。「端末のフォントで代わりに表示される」前提の画面は、
  Web にすると黙って豆腐になる
- Godot の PWA の Service Worker は `index.html` の名前でキャッシュする。`/game/`（ファイル名なし）で開くとオフラインでは起動しない。
  オフライン起動に要る wasm・pck がそろうのは2回目に開いたとき
- 文言の文字を集めるとき、コメントまで拾うとフォントに無い字（`≒`）で誤検出する。逆にコメントの除去を行単位にすると、
  複数行の文字列の中を取りこぼしうる
- doctest も変異を入れて確かめないと空振りする（最初の例では三重引用符と単一引用符の扱いの違いを検出できなかった）

**プロセス上の改善点**:
- 公開リポジトリへ履歴ごと取り込む前に、全履歴の秘匿情報・鍵・個人のパスを走査したので、安心して取り込めた
- ゲームのテスト（3分の制限付き）は、ラボのテストと並行で流すと時間切れで失敗扱いになる。単独で流す
