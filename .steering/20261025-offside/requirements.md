# 要求内容

## 概要

前へのパスにオフサイドを入れる。受け手がパスの時点で守備の最終ラインより前の列にいれば、オフサイドで守備側のボールになる。

## 背景

- スルーパス（2026-10-25）で、裏へ走り込む手が人数に関係なく通るようになった。守備が裏を取らせない手段（ラインを上げる）が無い。
- 実際のサッカーのオフサイドとオフサイドトラップを、盤面の列の単位で取り入れ、読み合いを増やす（シャビの指示「スルーパスを出した分、それも必要」）。
- 決めたこと（2026-10-25。シャビの回答）:
  - 前へのパス全部（スルーパス・前へのショートパス・背後へのロングボール）に適用する。
  - 判定は守備の手を出した後のライン。守備が最終ラインの選手を前へ出すとラインが上がる（オフサイドトラップの読み合い）。
  - オフサイドなら守備側のボールで再開し、トランジションには入らない。
  - 盤面にオフサイドラインを描き、今のままだとオフサイドになる運ぶ先の札で注意を出す。

## 実装対象の機能

### 1. オフサイドライン
- 守備側のフィールド選手のうち、いちばん自陣ゴールに近い選手の列（攻撃側から見た列）。GK は盤面にいないので、フィールドの最後の選手が「後ろから2人目」に当たる。
- 判定に使うラインは、守備の手（プレス・カバーと、マンツーマンの付け直し）を適用した後の配置で出す。守備が最終ラインの選手を前へ寄せればラインが上がり、カバーで下げればラインが下がる。

### 2. オフサイドの判定
- 対象の手: スルーパス、運ぶ先がボールより前の列のショートパス、背後へのロングボール。ドリブル・横や後ろへのパス・サイドチェンジ・シュート・トランジションのカウンターは対象外。
- 受け手の列が、オフサイドラインより前（攻撃側から見て相手ゴールに近い）ならオフサイド。同じ列ならオンサイド。
- 受け手: スルーパスは走り込む前の受け手の位置（走り込みの起点）。ショートパス・ロングボールは運ぶ先にいる味方（運ぶ先の列）。
- 受け手が自陣（1〜3列目）にいればオフサイドにならない。
- オフサイドの判定は、読み・人数の判定より先に行う（オフサイドなら人数・読みに関係なくオフサイド）。

### 3. オフサイドの結果（ターン結果 `OFFSIDE` を足す）
- 守備側のボールで再開する（フリーキック）。ボールの位置は受け手のいたエリア（守備側の視点）。トランジションには入らず、守備側の攻守ターンから始める。
- 試合が止まるので、配置区間の始まりとして固定を解く。保持者を置く規則は今のまま（1ターン1マス）。
- アディショナルタイムでは、ボールを失った扱いでハーフを終える。
- 振り返りの集計では、守備側の勝ちとして数える。

### 4. 画面
- 作戦ボードに、今のオフサイドライン（守備の最終ラインの列の手前の境界）を線で描く（利用者が攻撃中のとき、相手の守備のライン）。
- 今の配置のままだとオフサイドになる運ぶ先の札に注意（例: `オフサイド`）を出す（ヒントの札。守備の手でラインが動くので、確定ではない）。
- 結果の札・判定理由: 「オフサイド」。理由は「受け手がラインより前でオフサイド」の形。

### 5. CPU
- 今のラインのままオフサイドになる運ぶ先は、ボールを失う手として評価を低くする。
- 守備側の CPU は、今の先読みの加点のまま（ラインを上げる読みは、既存のプレスの選び方に任せる）。

### 6. 仕様書
- `functional-overview.md`（アルゴリズム5・7・8・10、判定例 JE-10、表示仕様、区分値 `TurnOutcome`）、`glossary.md`（オフサイド・オフサイドライン）、`requirements-definition.md`（FR-03・FR-05）、`component-design.md`、`screen-design.md`・`screen-03-match.md` を更新する。

## 受け入れ条件

### ラインと判定
- [ ] テストを先に書き、落ちることを確かめてから実装する
- [ ] ライン: 守備の手の前後でラインが変わる（最終ラインの選手を前へ寄せると上がる、カバーで下げると下がる）
- [ ] 境界: ラインより1列前はオフサイド、同じ列はオンサイド。自陣の受け手はオンサイド
- [ ] 横・後ろへのショートパス、サイドチェンジ、ドリブル、シュートは対象外。スルーパスは走り込む前の位置で判定する
- [ ] オフサイドは人数・読みより先: 攻撃側が多くても、読まれていなくてもオフサイド

### 結果と試合進行
- [ ] 守備側のボールで攻守ターンから再開、トランジションなし、固定が解ける
- [ ] アディショナルタイムならハーフを終える
- [ ] 1ターン1マス・対称性・通しの試合のテストが通る

### 画面・全体
- [ ] ライン・札・結果の表示を、画面を描いて確かめる
- [ ] `tools/run-tests.sh` で失敗0・終了コード0
- [ ] 数字（点数・入れ替わり・オフサイドの回数）は壊れていないかの目安だけ確かめて報告する（調整はしない）

## 成功指標

- シャビが遊んで、ラインを上げる／裏を取るの読み合いが生まれていると感じられる。

## スコープ外

以下はこのフェーズでは実装しません:

- トランジションのカウンターのオフサイド
- 守備の新しい手（オフサイドトラップ専用の手）。今の手（プレス）でラインを上げる
- 点数・入れ替わりの調整
- ワイヤーフレームの図の描き直し
