# 要求内容

## 概要

試合後の振り返り画面（S-07。FR-18）を作る。試合結果（S-06）から開き、エリア別・局面別の判定の勝ち負け、
得失点に至った直前のターン、時間帯ごとの両者の陣形・方式を見せる。

## 背景

要件の P0 のうち、試合の外側の画面は S-01〜S-06 までしか作っていない。振り返りは、どのエリア・局面で判断が通ったか・
崩されたかを確かめる学習の核（UC-04）で、既存のターン記録だけで作れる（保存の土台を要さない）。
シャビの判断で、未着手の要件のうちここから進める（2026-10-29）。

## 実装対象の機能

### 1. 振り返り集計（アルゴリズム10。ドメイン）
- `ReviewAggregator.aggregate(records, viewer, lookback_turns)` が `ReviewSummary` を返す
- エリア別・局面別の勝ち／負け／膠着、得失点の流れ（得点のターンと直前の最大 N ターン）、時間帯ごとの陣形・方式

### 2. 振り返りの値（アプリケーション）
- `MatchController.review()` が `ReviewView`（利用者の視点。得失点の流れの各ターンは `RevealView`）を返す
- 遡るターン数は `PresentationConfig` の設定値（初期値 3。functional-overview.md「設定値として外部化する値」）

### 3. 振り返り画面 S-07（UI）
- 4つのタブ（エリア別・局面別・得失点・時間帯）
- エリア別は作戦ボードに集計の札（「勝3 負1 膠1」）を描く
- 得失点は、得点のカードを押すと直前のターン（両者の手・動きの矢印つきミニピッチ・判定理由）を出す
- 戻る（ヘッダー・Android の戻る操作）で S-06 へ

### 4. 試合結果画面 S-06 の「振り返り」ボタン
- 押すと S-07 へ。`LEAVING` 中は押せない

## 受け入れ条件

### 振り返り集計
- [ ] 勝ち負けの数え方がアルゴリズム10の表どおり（全9種のターン結果 × 攻撃側・守備側）。`NO_CONTEST` は数えない
- [ ] 局面は、攻守ターンで攻撃側＝攻撃・守備側＝守備、トランジションで奪取側＝ポジティブ・喪失側＝ネガティブ
- [ ] エリアは比較エリアを viewer の視点に変換して数える（相手が攻撃側なら鏡像）
- [ ] 得失点の流れは、同じハーフ内・直前の得点より後のターンに限り、最大 N ターン遡る。ハーフの1ターン目の得点は0件
- [ ] 時間帯は、両チームの陣形・方式が同じ連続したターンをまとめ、ハーフの境で必ず区切る
- [ ] `NO_CONTEST` だけ・記録0件でもエラーにならず0件として返る

### 振り返りの値
- [ ] `review()` の集計値が、同じターン記録を HOME から集計した値と一致し、各ターンの `RevealView` が `ViewConverter.reveal` と一致する
- [ ] 試合前は null（push_error）
- [ ] 遡るターン数の設定値が範囲外（負）なら初期値に戻る

### 振り返り画面
- [ ] 開くとエリア別のタブ。判定の無かったエリアは札を出さない
- [ ] 局面別は4局面の行に勝・負・膠着。判定の無い局面は「この試合では起きなかった」
- [ ] 得点があれば最初の得点のカードを選んだ状態で、直前のターンが並ぶ。得点の見出しは「▲ 得点」「▼ 失点」
- [ ] 得点が0件なら「この試合は 0 − 0 でした。…」を出す
- [ ] ターン記録が無ければ「振り返りのデータがありません」
- [ ] 戻る操作で S-06 を頼み、`handle_back` は true

### 試合結果の「振り返り」
- [ ] 押すと S-07 を頼む。タイトルへ戻る処理中は押せない

## 成功指標

- シャビが試合後に振り返りを開き、どこで判断が通ったかを読み取れる（遊んで判定）

## スコープ外

以下はこのフェーズでは実装しません:

- 「実戦では」の補足（FR-23）。単純化カタログ（`LibraryService.simplifications()`）と `simplification_ids` は単純化を扱う作業で足す。画面は `simplification_ids` が空なので何も出さない
- 試合結果画面の陣形・方式の推移（HistoryCard。`final_record()`）。戦績の作業で足す
- 戦績の保存・中断データ（FR-13・FR-14）
