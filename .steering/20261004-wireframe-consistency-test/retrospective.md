## 計画と実績の差分

**計画と異なった点**:
- **drawio の読み込み方**: `node:fs` で読む計画から、Vite の `?raw` インポートに変えた。jsdom 環境では `import.meta.url` が file: スキームにならないうえ、プロジェクトに Node の型定義が無く typecheck が通らなかったため。`?raw` なら依存を増やさずに済み、`vite/client` の型だけで通る。
- **0件ガード**: 0件ガードを `it` からモジュール読み込み時の例外に移した。`it.each` が0件だと各ページの検査が1件も実行されないまま緑になるため。

**新たに必要になったタスク**:
- 名前の無いルートを失敗させる検査（review-implementation の [必須]）。
- 一対一対応の失敗メッセージで、過不足のあるページ・ルートを名指しする改善。変異1を入れたとき、件数の比較だけでは原因が読めなかったため。

## 学んだこと

**技術的な学び**:
- Vitest（jsdom 環境）でリポジトリ内のテキストファイルを読むなら、`?raw` インポートが最も素直。Node の型定義もパス解決も要らない。本番のエントリから到達しなければ、バンドルにも入らない。
- `vi.mock("vue-router", async (importOriginal) => ({ ...await importOriginal(), useRoute }))` で、本物の `createRouter` を保ったまま `useRoute` だけを差し替えられる。実ルート定義（`router.getRoutes()`）と画面描画の両方を正として突き合わせる検査に使える。
- `it.each` は対象が0件だと黙って何もしない。対象の収集時点で0件を止めないと、検査機構が空振りする。

**プロセス上の改善点**:
- 変異注入を「落ちるか」だけでなく「何が原因か読めるか」まで確認したことで、失敗メッセージの改善点が見つかった（testing 規約「出力経路も検証する」）。

## 次回への改善提案
- **申し送り（review-pre-commit Low 1）**: drawio にだけ、規約外の id（コピー&ペーストで自動採番された id 等）を持つ主ナビ項目が増えた場合、その項目は検査から外れる。塞ぐなら、ヘッダー領域（y < 50）にあるテキスト付きセルで、規約外の id を持つものを失敗させる。
- 主ナビ以外（ページタイトル・サブタイトル）も、PageHeader の文言と照合できる余地がある。ただしページ側の文言は動的なもの（`${formation.name}を学ぶ` 等）を含むため、照合規則の設計が要る。
- kit への提案は前回の retrospective（`20261004-screen-docs-alignment`）に記載済み。今回の学びとして補足すると、「ドキュメントと実装の書き写し関係を、テストで機械的に照合する」パターンは、ワイヤーフレームに限らず汎用的に使える（`testing.md`「ビルドで検出できない制約は、ソースを走査するテストで守る」の具体例として追加できる）。
