# 要求内容

## 概要

画面6〜8の単体テスト仕様書で未実装（`[ ]`）のまま残した16件を、Vitest のテストとして実装し、完了欄を `[x]` にする。

## 背景

- `.steering/20261004-screen-6-8-specs/` で画面6〜8の単体テスト仕様書を作成した際、詳細設計書に記載した振る舞いのうち
  対応するテストが無い16件を `[ ]` のまま申し送った（画面6: 5件、画面7: 9件、画面8: 2件）。
- 中身はアクセシビリティ属性（`aria-current` / `aria-expanded` / `aria-label` / `aria-describedby`）・文言・例外経路で、
  壊れても既存テストでは気づけない。

## 実装対象の機能

### 1. 画面6（`test-screen-06-learning-list.md` No.10〜14）
- 場面タイトルの `h3`、カードの `aria-label` 書式、カードごとのミニピッチ図、教材の無い陣形の除外、戻るボタンが無いこと

### 2. 画面7（`test-screen-07-formation-learning.md` No.17〜19・27・28・30〜33）
- 陣形切替の `aria-current`、役割一覧の文言、用語0件の教材、開閉ボタンの文言と `aria-expanded`、移動途中の「前の解説」、
  「再生完了」の文言、ピッチ図の `aria-label`、一時停止中の動き抑制への切替、非表示タブでは再生を開始しないこと

### 3. 画面8（`test-screen-08-free-layout-board.md` No.40・41）
- 戻るボタンが無いことと `aria-describedby`、陣形の選び替えで配置が切り替わり相手チームとボールに影響しないこと

## 受け入れ条件

- [ ] 16件それぞれに、仕様書の前提・操作・期待結果どおりのテストがある（具体的な入力と期待値。恒真テストにしない）
- [ ] 各テストについて、対応する実装を壊すと落ちることを変異注入で確認する（実装は元に戻す）
- [ ] 3つの仕様書の完了欄を `[x]` にし、備考の対応テストファイルの記述を更新する
- [ ] 本番コード（`src/` のテスト以外）を変更しない
- [ ] `npm test` / lint / typecheck / build がパスする

## スコープ外

- 本番コードの変更、仕様書に無いテストの追加
