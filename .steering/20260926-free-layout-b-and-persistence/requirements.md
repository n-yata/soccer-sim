# 要求内容

## 概要

自由配置モード（FR-15）のスコープ外として積み残していた2項目、「Bチームの自由配置」と「自由配置の座標の永続化」を実装する。

## 背景

FR-15（自由配置モード）は2026-09-18の実装時点で、Aチームの選手のみドラッグ対象とし、変更した配置は永続化しないという2つの制約を意図的にスコープ外としていた（`requirements-definition.md` §6.2）。当時は初回実装のスコープを絞る判断だったが、機能自体は安定稼働しており、両方とも既存の設計（`freeLayoutCoordinates.ts`が既にチーム非依存の座標変換を提供している、`learningProgress.ts`がlocalStorage永続化の実装パターンを既に持っている）を素直に転用できるため、積み残しの回収として着手する。

## 実装対象の機能

### 1. Bチームの自由配置

- 比較画面の自由配置モードで、Aチームに加えてBチームの選手もドラッグで配置を変更できるようにする。
- Bチームの配置変更に応じて、優位ポイント・総合判定・レーダーチャート（Bチーム側）がリアルタイムに再計算・再表示される（Aチームで既に実現している挙動をBチームにも適用する）。
- リセット操作は、A・B両チームの配置を元に戻す。

### 2. 自由配置の座標の永続化

- 自由配置モードでドラッグした配置を`localStorage`へ保存し、再訪時（自由配置モードへ再度切り替えたとき。ページ再読み込み後を含む）に復元する。
- 永続化はフォーメーション単位（フォーメーションIDをキーとする）とし、どの相手と比較していたか（組み合わせ）には依存しない。同じフォーメーションを別の相手との比較で選んだ場合も、保存済みの配置があればそれを復元する。
- リセット操作を行うと、保存済みの配置も破棄され、以降はそのフォーメーションの元の定義が使われる。
- 自由配置モードをOFFにする操作・画面離脱・組み合わせの切替では、保存済みの配置は破棄しない（そのままlocalStorageに残る。「その場に表示する一時状態」だけがリセットされる。この点はFR-15の既存の「トグルOFF・切替・離脱で変更内容は破棄され元の配置に戻る」という記述から変更になる）。

## 受け入れ条件

### Bチームの自由配置

- [ ] 自由配置モードON時、Bチームの選手もドラッグで移動できる
- [ ] Bチームの選手はAチーム同様、ピッチの座標範囲外へは移動できない（境界にクランプされる）
- [ ] Bチームの配置変更後、優位ポイント・総合判定・レーダーチャート（Bチームのみ）が変更後の配置に基づいて再計算・再表示される
- [ ] Aチームの配置変更は、Bチームの表示・状態に影響しない（逆も同様）
- [ ] リセット操作で、A・B両チームの配置が元のフォーメーション定義に戻る

### 自由配置の座標の永続化

- [ ] 自由配置モードでドラッグした配置は、操作のたびに`localStorage`へ保存される
- [ ] 自由配置モードをOFF→ONと切り替えると、直前に保存した配置が復元される
- [ ] ページを再読み込みしたあと、同じフォーメーションで自由配置モードをONにすると、保存済みの配置が復元される
- [ ] 保存はフォーメームID単位である。あるフォーメーションで保存した配置は、そのフォーメーションを別の相手との組み合わせで表示したときも復元される
- [ ] リセット操作を行うと、保存済みの配置が削除され、以降はそのフォーメーションの元の定義に戻る（再度自由配置モードをONにしても、リセット後は元の配置から始まる）
- [ ] `localStorage`が使えない環境（プライベートモード等）でも、保存・復元に失敗するだけで画面は正常に動作する（既存の`learningProgress.ts`と同じ防御方針）
- [ ] 保存されたデータが不正な形式（手動での書き換え等）でも、画面が壊れず元のフォーメーション定義にフォールバックする

## 成功指標

- 定量: 上記受け入れ条件を自動テストで検証できる状態にする。
- 定性: 開発者本人（シャビ）が両チームの配置を自由に動かして噛み合わせの変化を確認でき、気に入った配置が再訪時にも残っていることを確認できる。

## スコープ外

以下はこのフェーズでは実装しません:

- 複数の保存済み配置を並べて管理する機能（プリセット・名前付き保存等）
- 保存済み配置の端末間同期（バックエンドを持たないため）
- Bチーム側の座標に現れない手動タグ（`extraTags`）の配置変更への追従（Aチームと同じ既知の制約を踏襲する）
